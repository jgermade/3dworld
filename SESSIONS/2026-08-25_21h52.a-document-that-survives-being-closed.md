# 2026-08-25 21h52 · A document that survives being closed

Took **item 1** from `2026-08-25_19h22.what-is-not-built-yet.md`: a file format. It had reached
the top of the register the moment there was something to lose.

Ctrl-S writes a `.w3d`, `--open` reads one back, and `unzip -l` lists what is inside. The
specification is `FORMAT.md`, and that file — not the container — is what makes the format open.

## Where this repo actually was

Seven crates and a modeller you could use until you closed it. `Body` is an opaque `u32` handle
into a backend, so a document could not be saved by writing its handles down, and nothing in the
kernel contract could turn a body into bytes.

## What was decided before anything was written

Three questions, and the third is the one the design turns on.

### Which format — and the answer is two formats, not one

**Interchange is STEP.** ISO 10303 AP242 is the only thing that carries exact B-rep — NURBS,
topology, tolerances — and is read by Fusion, FreeCAD, SolidWorks and Onshape. `TKDataExchange` is
one toolkit away in `build.rs`. Its specification is a paid ISO document, which is worth saying
plainly: what is free is every implementation, OCCT's included, and the format has no owner who
can withdraw it.

**The native document is ours, because no existing format holds one.** Nothing else stores a graph
of nodes with names, visibility and a document tolerance:

| | |
| --- | --- |
| **Fusion `.f3d`** | Undocumented, and its geometry is **ASM**, Autodesk's proprietary ACIS fork. There is no specification and no free implementation. Not "hard" — impracticable. The way into Fusion is STEP. |
| **FreeCAD `.FCStd`** | A zip of `Document.xml` and OpenCASCADE `.brp` files. Genuinely open, and we could write it since we already produce BREP — but its document is a **parametric feature tree** and ours is direct modelling with state-based undo. The half we could fill is exactly the geometry STEP already carries; the half that makes it FreeCAD's, we have nothing to put in. |
| **glTF, 3MF, STL** | Meshes. Exporting is fine and losing the NURBS is irreversible. Not a document. |

So: one native format, and **one** export path that reaches everything. Writing somebody else's
native format would be a second implementation to reach where STEP already goes — and making your
native format be someone else's is inheriting their data model, which is the same mistake the
kernel seam exists to avoid.

### Whether to save the history — no

Tempting: the file would be tiny and backend-independent. It also requires kernels to be
deterministic forever, turns opening an imported 200 MB solid into recomputing it, and means
saving every intermediate body the history holds alive — which is most of what `collect_garbage`
exists to discard. **A loaded document has nothing to undo back to**, and that is written into
`Document::from_parts` as a property rather than an omission.

### What the geometry blobs are — the load-bearing decision

**They are the writing kernel's own bytes, and the manifest records which kernel wrote them.**
OpenCASCADE writes BREP and the file says `occt-brep-1`. A build whose kernel does not match
**refuses the file by name**.

> A native file that silently half-converts is the worst outcome a format can have. A file that
> will not open is a problem you can see.

That rule is the seam wearing a different hat, and it is checked in both directions: an OCCT build
refuses a fake-kernel document and a fake-kernel build refuses an OCCT one. A one-way check would
have passed with half the failure mode live.

## Walkthrough · as built

### The trait grew by three, declared first

`geometry_format`, `save_body`, `load_body` — thirteen methods to sixteen, and the C header grew
by three entry points because `AGENTS.md` says the header is the specification. `load_body`
distinguishes its two failures on purpose: `Unsupported` for bytes that are not this kernel's,
`Failed` for this kernel's bytes that are damaged. A caller can tell "wrong build" from "broken
file", and a user deserves to know which.

Three checks went into the **conformance suite** rather than into a backend's tests, because each
is true of any correct kernel:

- a saved body loads back with the same topology and bounds, and **saving does not consume it**;
- nonsense is refused, and refused as one of those two errors;
- `geometry_format` is non-empty and carries a digit, so it can be changed safely.

Fourteen checks became seventeen. Both backends pass.

### `w3d-format`, and why it is not `w3d-core`

A separate crate so the document keeps its no-dependency property: `w3d-core` does not know what a
file is, and `w3d-format` does not know what a GPU is. The dependencies — `serde`, `serde_json` —
live only here. JSON because a document format wants escaping rules somebody else already got
right.

### The zip is hand-written, and that is the point

Two hundred and seventy lines, stored entries only, no Zip64. It could have been the `zip` crate.
It is not, because **the reason for choosing zip at all is that `unzip -l` works**, and a
container whose reader is a dependency is one you cannot check that claim about cheaply.

```
$ unzip -l demo.w3d
     3464  1980-00-00 00:00   geometry/0.bin
      893  1980-00-00 00:00   geometry/1.bin
      414  1980-00-00 00:00   manifest.json
$ unzip -p demo.w3d manifest.json
{ "format": "w3d-document", "version": 1, "geometry": "occt-brep-1", ... }
```

Timestamps are zero, entries are sorted, so **two saves of the same document are byte-identical**
— which is what makes `diff` and content-addressed storage worth anything. There is a test for it.

The CRC-32 is checked against `0xCBF43926` for `"123456789"`, the value the whole world agrees on.
A checksum that is merely self-consistent passes every test in the file and fails every other zip
tool.

## Bugs found by building, not by reading

### A magic number recalled instead of looked at

The C++ side refused every BREP file it had just written. `BRepTools::Write` was assumed to begin
`DBRep_DrawableShape`; it actually begins `\nCASCADE Topology V3, (c) Open Cascade`. The first is
what the Draw harness writes, not what a plain stream write produces.

Found by dumping eighty bytes rather than by reading more OCCT documentation. The check now
searches a 64-byte window for `CASCADE Topology`, because the leading newline and the version
digit are both things OCCT has changed before.

### The manifest said `quality.linear`, and every test passed

The first version shared one `Pair` struct between tolerance and quality, so a file said:

```json
"quality": { "linear": 0.01, "angular": 0.35 }
```

The numbers were right and their names were meaningless — `linear` was a chord sag. **Caught by
reading the output of `unzip -p`**, which is the only reason it was caught at all: no test asserts
what a field is called, and none would have.

That is the argument for the container in one line. A format you can look at is a format whose
mistakes you find before version 1 ships rather than after.

### A test that asserted a name the boolean had already consumed

`the_file_is_a_zip_with_a_readable_manifest` looked for `"Plate"` in the manifest. The fixture
performs a difference, so the node is called `Plate − Drill` and no node named `Plate` survives.
The assertion was checking that a substring existed, which it did, for the wrong reason.

### `redundant_closure_call`, and what it was telling me

Clippy rejected the new conformance check because its body had no `?` in it, making the macro's
wrapping closure removable. The fix was not to appease the lint: the check was doing two things in
one `match` — asserting that nonsense fails *and* asserting which error it fails with. Splitting
them added the `?` and made the failure messages tell you which half broke.

## Verified, and not

**Verified.** `make test` is **62 tests** (47 before) — five on the zip, eight on the round-trip,
two on saving and opening from the editor. `make test-occt` is **11** (8 before), including a
drilled plate saved to BREP and reopened with its seven faces, fifteen edges and ten vertices
intact, still tessellating with every face reaching the mesh. The conformance suite is seventeen
checks and both backends pass. `make wasm`, `make web-test`, `make app-test`, clippy and fmt are
unchanged and green.

The screenshot in this session is a document written by the modeller, closed, and opened again
from disk.

**Not verified, and the risk taken with each.**

- **No STEP.** Nothing leaves this program for another tool. The format's whole escape hatch for
  "wrong kernel" is a feature that does not exist yet, and until it does, a `.w3d` written by an
  OCCT build is readable only by an OCCT build.
- **One writer, one reader.** The format has never been read by an implementation written from
  `FORMAT.md`, which is the only test of whether that document is sufficient. That is the claim
  most likely to be wrong.
- **Nothing has opened a file it did not write in the same version.** There are no old files.
  Forward compatibility is asserted by a test that edits a version number, not by history.
- **No file has been large.** The largest is a few kilobytes. Stored entries mean a real assembly
  will be bigger than it needs to be, and nothing has measured how much.
- **Zip64 is absent rather than handled.** A document over 4 GiB fails to save. Nothing tests
  that path, because constructing the case costs more than the case is worth today.
- **`fake-csg-1`'s decoder is recursive over untrusted input.** A crafted file could recurse
  deeply. It is the test kernel and `FORMAT.md` says not to implement it, but the bytes are still
  parsed by a real program.
- **Names are the only identity in a file.** Nodes have no stable id across a save, so anything
  that wants to refer to a body between sessions — an assembly, a reference, a comment — has
  nothing to hold on to.

## Loose ends, deliberately left

- **No units.** `tolerance` implies a scale and nothing states one. Named in `FORMAT.md` as a
  version-2 conversation.
- **No thumbnail**, which every file browser wants and which costs a renderer at save time.
- **No camera, no selection** in the file. A document is what was modelled, not how it was being
  looked at — but "reopen where I left off" is a reasonable thing to want.
- **Saving is synchronous and on the frame.** A large document will stall the window.
- **`Save` with no path writes `untitled.w3d` in the working directory** rather than opening a
  dialogue, because there is no file dialogue and adding one is a dependency.
- **No `.FCStd` exporter.** Defensible later precisely because we already produce BREP; it would
  be a converter outside the seam, never the native format.
