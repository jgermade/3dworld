## Walkthrough · as built

`w3d-render`: five files, 1,332 lines, and the first third-party dependency this workspace has
taken. Plus 456 lines of tests, of which the interesting ones are not in this crate.

### The dependency, and why it is declared twice

`wgpu` 30, MIT OR Apache-2.0, which is compatible with GPL-3.0-or-later in the direction that
matters. It is declared **per target rather than once**, with `default-features = false` and an
explicit backend list in each: `vulkan`/`metal`/`dx12` natively, `webgpu`/`webgl` on wasm. The
backend list *is* the platform decision from `STACK.md`, and a default-features build would pull
in backends neither column uses and hide the decision in a lockfile.

That turned out to matter more than it reads — see `gles is not WebGL2` below.

### `gpu.rs` — the answers are read, not assumed

`Capabilities` is constructed only by `Gpu::open` and every field comes off the adapter:
`backend`, `adapter` name, `compute`, `vertex_storage_buffers`, `max_buffer_size`,
`max_texture_dimension_2d`. Nothing is inferred from `cfg!`, and the reason is specific to the
web: a build compiled with both backends can land on WebGPU *or* on WebGL2, and which one it got
is not knowable until it has happened.

`compute` is the flag the register asked for. It is
`DownlevelFlags::COMPUTE_SHADERS`, and `Capabilities::degradation()` turns its absence into the
sentence a loader shows a user — because `STACK.md`'s rule is that the fallback must degrade
*visibly*, and a fallback nobody announces is indistinguishable from a performance bug report six
months later.

Two smaller decisions worth keeping:

- **The device is asked for `downlevel_webgl2_defaults`.** The weakest target in the matrix is the
  one every other target must also satisfy, so a pipeline that works in a test works on WebGL2.
  Anything wanting more has to ask, and then has to handle not getting it.
- **`Gpu::instance()` is async**, because it goes through
  `wgpu::util::new_instance_with_webgpu_detection`. That helper exists for a reason worth knowing:
  `navigator.gpu` existing is *not* the same as WebGPU working, and a build that trusts the object
  drops to no adapter at all rather than to WebGL2. It is the graphics half of the two-variant
  dispatch that `web/` still owes for threads.

### `camera.rs` — the narrowing point, and the limit it cannot fix

Everything is `f64` and stays `f64` until `view_projection` hands a matrix to the queue, where it
is transposed into column-major and cast. `perspective` produces depth in `0..1` — wgpu's
convention, not OpenGL's `-1..1`; getting that wrong halves the depth buffer and presents as
z-fighting rather than as a bad matrix, so there is a test that evaluates the near and far planes
and asserts 0 and 1.

`fit` derives `near` and `far` **from the framed radius** rather than from constants. Fixed at
0.1 and 1000, a 2 mm fillet and a 40 m assembly cannot both be depth-tested, and that is not a
tuning problem, it is the same code having to serve both.

And the honest limit, written into the module docs because it is exactly the kind of thing that
gets claimed and then quietly isn't true: **`f64` here does not buy precision far from the
origin.** `w3d_kernel::Mesh` positions are already `f32` in absolute model coordinates, so a
document sitting kilometres from origin has lost precision before this module sees it. The camera
cannot fix that; only a per-body origin in the tessellation contract could, and that is a
widening of the trait with no caller.

### `scene.rs` — the face-id contract, and what it costs at the boundary

This is the part that was not obvious from the design. `Mesh::face_of_triangle` is per *triangle*,
and WGSL has no per-primitive input — there is no `gl_PrimitiveID` to read in a fragment shader.
So a face id has to become a **vertex** attribute, which is only sound if no vertex is shared
between two faces.

In practice it never is: both backends tessellate face by face and give each face its own nodes.
But "in practice" is not the contract, so `per_vertex_faces` **checks**, and returns `None` when a
vertex is claimed by two faces, at which point the mesh is de-indexed to one vertex per triangle
corner — three times the memory in the worst case. `GpuMesh::deindexed` is public so the cost is
observable rather than mysterious, and both the fake and OCCT are asserted to take the indexed
path.

`validate` rejects a malformed mesh here rather than letting it become a device loss three frames
later. The conformance suite already checks well-formedness; this is the second line of defence,
and it costs one pass over the indices.

Vertices are packed with `to_le_bytes` rather than a casting crate. This runs once per body, the
workspace forbids `unsafe`, and a second dependency to avoid a copy nobody has measured is a bad
trade.

### `lib.rs` — one shader, two entry points, and a scissor

`Renderer` owns two pipelines over one WGSL module: `fs_shade` writes colour, `fs_pick` writes
`Rg32Uint` — object id in `.r`, face id in `.g`. **They share the vertex stage**, and that is the
decision rather than a saving: a pick that rasterises differently from the picture is a pick that
lies at silhouettes, which is where users click.

`face` is `@interpolate(flat)`. It is the one attribute where smooth interpolation is not a
quality trade-off but a wrong answer — an interpolated face id names a face that is not there.

`pick` sets up the whole framebuffer and **scissors to one pixel**. Rasterisation is bit-for-bit
what the picture did — same projection, same depth test — and only the wanted texel is written.
It is a full render for one pixel, which is the cost of exactness; a pick matrix that shrinks the
frustum to the pixel is the obvious optimisation and is deliberately not written, because a click
is not a hot path and a wrong pick is much worse than a slow one.

Three smaller ones:

- **`NOTHING` is `u32::MAX`, not 0.** The id target is cleared to it, so a caller's object id of 0
  is a legal object. Reserving zero pushes an off-by-one into every call site instead.
- **Nothing is back-face culled.** A solid whose normals are inverted is a defect worth *seeing*;
  culling shows a hole and blames the boolean.
- **Per-object data is one uniform buffer addressed by dynamic offset**, and the alignment is read
  from the device rather than assumed to be 256. Instancing through a storage buffer is the
  natural next step and is exactly what `Capabilities::vertex_storage_buffers` says WebGL2 will
  not do.

### The end-to-end test lives on the other side of the seam

`render/` cannot depend on `kernel-occt` — it must not know a backend exists, and it takes a
caller-chosen `u32` id precisely so that it does not know a *document* exists either. So the test
that closes the loop is `kernel-occt/tests/viewport.rs`, where OCCT is already a prerequisite.

It drills the same 40×40×10 plate the topology test asserts, uploads it, and clicks it. Two
things come out of that which no earlier test could give:

- **All seven faces of the drilled plate are reachable by a click.** `kernel-occt` already
  asserted every face produces triangles; this asserts the stronger thing — that they survive to a
  pixel. A face nothing can click is a face the modeller does not have.
- **`Mesh::face_of_triangle`'s justification stopped being an argument.** It is in the kernel
  contract *because* ID-buffer picking is impossible without it. That sentence has been in the
  crate docs since the seam was built; it is now a passing test.

### Pending item 5, closed: the OCCT install repairs itself in one command

Ubuntu Noble's `libocct-foundation-dev` 7.6.3+dfsg1-7.1build1 ships `Poly_ArrayOfNodes.hxx` and
not the `NCollection_AliasedArray.hxx` it includes. The previous session patched a container by
hand and recorded that a fresh checkout would not build. It reproduced here exactly.

Three things now, none of which vendors OCCT source into this repository:

1. **`build.rs` detects the specific case** — `Poly_ArrayOfNodes.hxx` present, its include absent —
   and fails with one sentence naming the package, the bug and the remedy. Left to the compiler it
   is forty lines of include trace ending at a file nobody has heard of.
2. **`make occt-headers`** fetches the missing header from upstream at the tag in
   `kernel-occt/native/UPSTREAM`, into a gitignored `native/vendor-include/` that `build.rs` puts
   on the include path *after* the system one — a vendored header stands in for one a distribution
   failed to ship and must never shadow one it did.
3. **`native/UPSTREAM`** records 7.6.3 / `V7_6_3`, what is fetched and why, and says plainly that
   it is not a pin in the sense a lockfile is one: the build still takes whatever OCCT the system
   has. A real pin arrives with the Emscripten build, which compiles OCCT rather than linking a
   distribution's.

The fetch is deliberately **not** run from `build.rs`. A build that reaches the network on its own
is not a build anybody can reproduce or audit.

## Bugs found by building, not by reading

### `gles` is not WebGL2, and `make wasm` passed anyway

The wasm target was first given wgpu's `gles` feature, on the reading that GLES on the web is
WebGL2. `cargo check --target wasm32-unknown-unknown` passed. `make wasm` passed. The crate
compiled, and the build had **no fallback in it at all**.

`gles` is the *native* OpenGL backend — Windows, Linux, Android, Emscripten. The WebGL2 backend is
a separate feature called `webgl`, and on `wasm32-unknown-unknown` the `gles` flag reduces to
`wgpu-core?/gles`, where the `?` means "only if something else already enabled `wgpu-core`".
Nothing had. `wgpu-core`, `wgpu-hal` and `glow` were absent from the dependency tree and the
result was a WebGPU-only build that type-checked perfectly.

This is the exact failure `Capabilities` exists to prevent, arriving one layer lower than
`Capabilities` can see: not "the adapter turned out to be weaker than assumed" but "the fallback
was never compiled in". A capability probe cannot report a backend that is not in the binary.

**The fix is a check, not a comment.** `make wasm` now greps the wasm dependency tree for `glow`
and fails with the reason if it is missing. It was verified by putting `gles` back and watching it
fail. The feature name is also a comment in `render/Cargo.toml`, but the comment is not what will
catch it next time.

### The clear colour is linear and the target is sRGB

The first framebuffer test asserted the background bytes were `(14, 15, 17)` — the clear colour
`(0.055, 0.059, 0.067)` times 255. Every pixel differed from it, so the test read as "the clear
did not happen". It had: the target is `Rgba8UnormSrgb`, so what lands in memory is the sRGB
*encoding* of a linear clear value, and 0.055 comes back as 65.

The test now **samples** the corner pixel as its background reference and separately asserts that
sample is in a plausible band. Hard-coding an expected framebuffer value means encoding a colour
pipeline into a test that is not about colour.

### A through-hole viewed down its own axis is background

`every_face_of_a_drilled_plate_is_reachable_by_a_click` first sampled six axis-aligned viewpoints
and found 6 of 7 faces. The missing one was the hole's cylindrical wall — the only face the
boolean actually created.

Looking exactly down the axis of a **through** hole, there is nothing behind the hole. The centre
pixel is background, and the wall is edge-on. The companion test had asserted "the hole's wall is
under the centre" and was wrong about the geometry, not about the renderer.

Both tests now use oblique elevations. Recorded because the instinct — line the camera up with the
feature — is exactly backwards for a hole, and because a renderer test that fails for a geometric
reason is very easy to "fix" by loosening it.

### `too_many_arguments`, and the bug class it was hiding

`draw` took eight arguments and `pick` nine; clippy refused both, and `AGENTS.md` allows no
allow-list. The obvious move is to bundle device and queue. What that surfaced is that
**`aspect` was a separate argument sitting next to the target textures** — so a caller could pass
an aspect ratio that disagreed with the size it was rendering into, which looks like a broken
camera and is a broken call site.

`Viewport { device, queue, width, height }` computes `aspect()` itself. The lint was right about
the signature and, indirectly, about the design; that is worth noting, because the reflex on a
`too_many_arguments` is to reach for `#[allow]`.

## Verified, and not

**Verified.** `make test` is **32 tests** and still needs nothing installed (19 before). `make
test-occt` is **8** against OpenCASCADE 7.6.3 (6 before), including the two new end-to-end ones.
`cargo clippy --all-targets -- -D warnings` is clean with no allow-list, `cargo fmt --check` is
clean, `make wasm` type-checks the default members — now including `w3d-render` — for
`wasm32-unknown-unknown` and asserts the WebGL2 backend is really in the tree.

The rendering tests ran against **lavapipe**, Mesa's software Vulkan rasteriser, in this
container. Colour was read back from an offscreen texture and picks were read back from an
`Rg32Uint` texture.

**Not verified, and the risk taken with each.**

- **No real GPU has run any of this.** Software rasterisation proves the pipeline, the bind group
  layouts, the shader and the readback. It proves nothing about timing, nothing about driver
  quirks, and nothing about what a discrete GPU does with a 1×1 scissor.
- **WebGL2 has never been run**, only compiled and asserted present in the tree. Every claim about
  the fallback — that `Rg32Uint` is renderable, that the scissored pick works, that the
  `downlevel_webgl2_defaults` limits are actually enough — is an argument. This is now the largest
  single unknown in the crate, and it is unknown in the *opposite* direction from before: the code
  is there, untested, rather than absent.
- **Nothing has been presented to a surface.** `Renderer::draw` takes texture views, so a window
  or a canvas is somebody else's problem — which is right, and means the swapchain, resize and
  present path do not exist and have never been thought about hard.
- **`pick` blocks.** It maps a buffer and waits on the device. On the web that is not acceptable on
  a frame, and there is no async variant.
- **A test that skips looks like a test that passed.** The GPU tests print `SKIPPED:` and return
  when there is no adapter. `cargo test` still says `ok`. That is a real hole in CI and the only
  defence right now is `--nocapture`.
- **The fake's mesh is a bounding box**, so `render/`'s own tests prove upload, draw and readback
  and say nothing about geometry. The geometry statements are all in `kernel-occt/tests/viewport.rs`
  and therefore only run where OCCT does.
- **The seven-faces-clickable assertion is a sampling argument.** It sweeps nine viewpoints on a
  12×12 grid. A face too small to land on a sample point would read as unreachable, and a
  degenerate sliver face — which is what a real B-rep kernel produces on bad input — probably
  would.
- **The dependency count went from 0 to 1 and the transitive count went to about 40.** No licence
  audit beyond `wgpu` itself has been done, and `AGENTS.md` forbids a dependency incompatible with
  GPL-3.0-or-later. That check is owed.

## Loose ends, deliberately left

- **The pick matrix.** `pick` renders the whole frustum and scissors. Shrinking the projection to
  the pixel would rasterise a fraction as much. Not written on purpose; a click is not hot.
- **Instancing.** Every object is a draw call with a dynamic uniform offset. A storage buffer of
  transforms is the natural next step, and `Capabilities::vertex_storage_buffers` already says
  WebGL2 will not do it — so it is a two-path feature, not a free one.
- **Edges and silhouettes are not drawn.** A B-rep modeller is largely judged on its edge display,
  and `Mesh` carries no edge data at all. That is a widening of the kernel trait, and the rule is
  that it happens when there is a caller.
- **Selection is a colour tint.** No outline, no depth-independent highlight.
- **No MSAA and no depth prepass.** `multisample` is the default everywhere.
- **The mesh cache is the document's, and GPU buffers are the caller's.** Nothing connects them, so
  an application will re-upload unless it keeps its own map. That map is `app/`'s job and `app/`
  does not exist.

## Walkthrough · as built

### `Renderer::pick_begin` and `PickPending::collect`

The blocking `pick` is now a convenience over a two-step request. This had to happen before
anything else: a GPU readback completes on the JS event loop, so a blocking wait in a browser is a
wait that can never finish, and the honest symptom would have been a modeller where nothing is ever
selected.

`PickPending` carries no lifetime, so it sits in an application's state between frames.
`collect` is one atomic load until the answer is there. `pick` keeps its signature — native
callers and the existing tests are unchanged — and its doc comment now says plainly that it
answers `MISS` for every click on the web.

### `Renderer::new` takes the colour format

It used to build its pipelines for `COLOR_FORMAT`. A canvas hands back whatever its compositor
wants — `bgra8unorm` here — and a pipeline built for a different one is a validation error at the
first frame. The format is not ours to choose, so it is an argument.

### `web/` — three files, and only one of them is Rust

- **`loader.js`** is the part that has to be JavaScript, and the reason is in `STACK.md`: there is
  no CPUID inside wasm, so detection happens before instantiation. It validates two probe modules
  and asks one question of the page:

  | | |
  | --- | --- |
  | **Threads** | a property of the *engine* — does it accept a shared memory and `i32.atomic.load` |
  | **SIMD128** | the baseline; probed anyway, because "universal since Safari 16.4" is a claim |
  | **Cross-origin isolation** | a property of the *page* — did the server send COOP and COEP |

  The threaded variant is an `and` of the first and third, and the common failure is a host that
  forgot the headers. That case now produces a working single-threaded modeller and a sentence
  naming the two headers, which is what `STACK.md` means by degrading visibly.

- **`w3d-web`** is the wasm entry: a canvas becomes a surface, the format is negotiated, and the
  capabilities go back to JS. It is **not** the modeller — the scene is a fixed document on
  `FakeKernel`, so nothing about it is a statement about geometry. `app/` replaces the scene; the
  surface, the format negotiation and the pick loop stay. The crate is `#![cfg(target_arch =
  "wasm32")]` in its entirety, with its dependencies declared per target, so a native `cargo check`
  builds an empty crate and `make test` does not grow a toolchain requirement.

- **`serve.py`** sends COOP and COEP, and takes `--no-isolation` to stop. The flag is the point:
  the interesting failure is a *missing* header, and a server that cannot omit them cannot test it.

### `web/test/browser.mjs` — the first check that runs a browser

Three runs, three different questions: WebGPU offered; WebGL2 with `navigator.gpu` absent
entirely; and no COOP/COEP. Playwright drives the pre-installed Chromium, and every assertion is
made against something the page itself displays — a test that inspects state the page does not show
is a test that can pass while the page is blank.

```
— WebGPU offered, cross-origin isolated —
ok    an adapter answered — gl · ANGLE (SwiftShader)
ok    the canvas is not blank — 77 distinct colours
ok    a click in the middle names a body and a face — {"object":2,"face":5}
ok    a fallback, if it happened, is stated
— WebGL2, the fallback —
ok    the backend really is WebGL2 — gl
ok    and it reports no compute, rather than pretending
ok    ID-buffer picking works on WebGL2 — {"object":2,"face":5}
— no COOP/COEP: the degradation must be visible —
ok    the single-threaded variant was chosen
ok    the reason names the headers
```

**`Rg32Uint` as a render target, a scissored one-pixel pass and a texture-to-buffer readback all
work on WebGL2.** Those were the three things the previous `Verified, and not` called arguments,
and they are the three most likely to have been missing.

## Bugs found by building, not by reading

### A browser that reports WebGPU and rasterises nothing

Headless Chromium here exposes `navigator.gpu`, passes wgpu's own
`new_instance_with_webgpu_detection`, returns an adapter reporting compute shaders, vertex storage
buffers and a gigabyte of buffer — and draws nothing at all. No error, no validation message, a
black canvas. Calling `requestDevice()` directly, with no wgpu involved, fails with `A valid
external Instance reference no longer exists`, which is Dawn saying its instance is gone.

wgpu's helper documents exactly this hazard — "`navigator.gpu` existing is not the same as WebGPU
working" — and its check was **necessary and not sufficient** here. That is the finding: a
capability probe cannot certify a driver.

**So the loader stops probing and starts looking.** `boot` renders three frames and counts the
distinct colours on the canvas; one flat colour means nothing was drawn, and it re-opens on
`Backends::GL` and says so in a sentence the page displays. `Gpu::instance_for` exists for that
second attempt.

Two consequences worth stating rather than burying:

- **The fallback is from evidence, not from a feature flag**, which is the only kind that survives
  a driver bug.
- **A canvas keeps the first context it is given**, so falling back means replacing the element,
  not reconfiguring it. `boot` therefore owns the canvas and `index.html` hands it a container.

### The SIMD probe validated nothing, and would have reported the opposite

`v128.const` carries **sixteen** bytes of immediate. The first probe supplied four, so the module
was malformed and `WebAssembly.validate` returned false — on every browser. Nobody would have seen
a crash; they would have seen a permanent, wrong "no SIMD128" in the status line, which is the
worst kind of monitoring.

Caught by a negative control: the same probe with the feature removed must fail, and the positive
must pass. The threads probe was checked the same way and was right.

### A WebGL2 drawing buffer is empty by the time anything looks at it

The browser test first measured "did anything draw" by the byte count of a PNG screenshot, which
reported a *black* canvas as drawn — a blank 960×660 frame still encodes to a few kilobytes.
Replacing that with a real colour count then reported **both** backends as blank, including the one
that was visibly working.

The cause is not ours: a WebGL2 drawing buffer is not preserved, so `drawImage` outside the
rendering task reads back a cleared buffer. Sampling has to happen in the same task as the render
that produced the frame. `distinctColours` is exported from `loader.js` with that requirement in
its doc comment, and the page exposes a `sample()` that renders and measures together — which is
also what the fallback check needs, so the two uses agree by construction.

Recorded because the first two attempts at this measurement both produced confident wrong answers
in opposite directions.

### `serve.py --port 0` printed the port it was asked for

Zero. The bound port is `server.server_address[1]`, and a test that gets a free port from the OS
has no other way to learn it.

## Verified, and not

**Verified.** `make test` is 32 tests, `make test-occt` is 8, `make wasm` type-checks and asserts
the WebGL2 backend is in the tree, clippy and fmt are clean — all unchanged by this work.
`make web` produces **3.34 MiB of wasm, 1.12 MiB gzipped**, release with LTO. `make web-test` runs
the page in Chromium and all seventeen of its checks pass.

**Not verified, and the risk taken with each.**

- **WebGPU has never rendered a pixel in this project, anywhere.** The native tests run on Vulkan
  through lavapipe, which is not WebGPU; the browser's WebGPU is broken here. Everything the
  viewport claims about the fast path is still an argument, and the *only* thing this session
  proved about WebGPU is that a browser can claim it falsely.
- **The threaded variant does not exist.** The loader dispatches to it, finds it missing, and says
  so — which is honest and is not the same as the two-variant build matrix `STACK.md` describes.
  Nothing has ever run with `SharedArrayBuffer` and rayon.
- **The browser scene is `FakeKernel`**, so the browser has drawn a bounding box, not geometry.
  OCCT for wasm does not exist, so nothing else was available.
- **One browser, one version, software rendering.** No Firefox, no Safari, no real GPU. Safari is
  the one that matters most and is the one least likely to behave like this.
- **1.12 MiB gzipped is not the shipping number.** No brotli here, no `wasm-opt`, and the payload
  contains a modeller that does nothing yet — OCCT will dwarf it.
- **`pick` still renders a full frame per click**, now once per click in a browser too.
- **Playwright is an npm dependency outside the crate graph**, so `make web-test` needs
  `npm install` in `web/test/` and is not part of `make test`. Its licence has not been audited
  either — see the register.
- **`distinctColours > 1` is a heuristic.** A document that is legitimately one flat colour would
  trigger a fallback. It runs against the fixed startup scene for that reason, and if `app/` ever
  starts with an empty document the check has to move.

## Loose ends, deliberately left

- **No `wasm-opt`.** `wasm-bindgen` runs, nothing else does. The size number above is therefore an
  upper bound and a lazy one.
- **The loader's variant probe is a `HEAD` request** for the threaded bundle, which logs a 404 in
  the console on every load. Harmless, ugly, and it goes away when the variant exists.
- **`index.html` is the whole application shell**, and it is 100 lines of inline module script.
  That is deliberate for now — it is a harness, not a UI — and it is what `app/` replaces.
- **No resize test.** `resize` exists and is called on `resize` events; nothing checks it.
