# 2026-08-25 13h55 · Choosing the language, and the memory model

The first file. Nothing was built; what was decided is the architecture, and this records it
along with the two reversals it took to get there.

## Where this repo actually was

Empty. `git log` on `claude/plasticity-mydeje` reported no commits at all. There was a
directory name, `3dworld`, and an intent: an alternative to Plasticity, in WebAssembly.

The name is not settled either. `3dworld` is the repository, not a decision.

## What was asked

Four questions in sequence, each of which turned out to constrain the next:

1. Rust or Go?
2. Is wasm64 not mature yet?
3. Could one thread run in wasm32 and another in wasm64?
4. Can hardware acceleration be used where it exists?

The order matters. The language question looks like the big one and is the easy one; the memory
model is where the architecture actually got decided.

## Walkthrough · as built

Nothing was built. What follows is what was settled, and it is written down here because the
reasoning is worth more than the conclusion — a later reader who disagrees needs to be able to
disagree with the argument, not just overturn a verdict.

### 1 — Rust, and the reason is not the one usually given

The reasons that get cited (speed, safety) are not the deciding ones. The deciding ones are:

- **No GC.** Go's pauses land in the interaction loop of a real-time modeller.
- **Threads exist.** `GOOS=js/GOARCH=wasm` is single-threaded. There is no rayon equivalent, and
  a kernel that cannot use cores is not competitive.
- **C++ interop.** Any path that wraps OpenCASCADE needs it, and from Go under wasm it is
  impractical.
- **One source, two columns.** Rust compiles the same core to `wasm32-unknown-unknown` and to a
  native desktop binary. Plasticity is a desktop application; a web-only answer is a different,
  smaller product. Go would have meant Wails or Electron over the top.

Binary size and SIMD also favour Rust but were not needed to decide it.

### 2 — the kernel is the project, and it is not the language

Recorded because it is the thing most likely to be forgotten under enthusiasm: Plasticity is good
because it sits on **Parasolid**. Robust booleans, and fillets that do not fall over on
degenerate input, are decades of work. Parasolid is a commercial Siemens licence with no
WebAssembly distribution, so it is not available at any price that matters here.

That leaves OpenCASCADE (mature, LGPL-with-exception, 5–40 MB of wasm, unpleasant API, fillets
short of Parasolid), `truck` (Rust, permissive, booleans not production-ready), or writing one.

**The decision was to not decide**, and to make not-deciding structural: `kernel::GeometryKernel`
exists from the first commit, OCCT goes behind it to get something usable quickly, and a kernel
of our own replaces it from underneath without the modeller noticing. This is the single most
load-bearing decision in the file, and the rule that protects it — nothing below the seam leaks
above it — is in AGENTS.md as a rule rather than a preference for that reason.

### 3 — wasm32, and the sharding that makes it enough

wasm64 was rejected. Not for availability — see the correction below — but because 64-bit memory
gives up the 4 GB guard-page trick, so every access is bounds-checked, at a cost SpiderMonkey
measured between 10% and over 100%. A B-rep kernel is memory-bound and pointer-chasing, which is
the wrong end of that range. Rust's `wasm64-unknown-unknown` is Tier 3 besides, and the JS API
caps a memory at 16 GB anyway.

The question that followed — one thread in wasm32, another in wasm64 — does not typecheck, and
the reason is worth keeping: **the address width belongs to the memory, not to the thread.**
Threads are N workers instantiating the same module against the same shared `WebAssembly.Memory`,
whose index type is fixed in the module type. Two separate modules can of course differ, but they
cannot share linear memory at all — a wasm32 module importing an `i64` memory is a `LinkError`.
And in Rust, one binary is one target is one `usize`.

There is a real loophole: multi-memory (also Wasm 3.0) makes index types per-memory, so a wasm64
module could declare an `i32` shared memory alongside its 64-bit one and exchange with a wasm32
module without copying. LLVM and Rust cannot emit usable multi-memory modules, so it stays
theoretical. **Recorded so nobody re-derives it and thinks they have found something.**

What survived from that question is the good half of the instinct, and it became the memory
model: **shard across wasm32 heaps.** One shared memory for the interactive document with a rayon
pool over it; separate workers with their own memory for bulk work, each with its own 4 GB;
transferable `ArrayBuffer` between them, which is a move rather than a copy. Total addressable
exceeds the ceiling and nothing pays for 64-bit pointers.

This is what forces arenas and `u32` indices. A pointer is meaningless in another worker's heap;
an index is valid in any of them.

### 4 — acceleration, and the two traps specific to this domain

The general answer is that wasm exposes acceleration in three layers — WebGPU, SIMD128, threads —
and that **there is no CPUID**: a module cannot ask what the machine can do, so detection happens
in JS before instantiation via `WebAssembly.validate()` on probe modules. That means a build
matrix. It was kept to two entries: SIMD128 is universal enough since Safari 16.4 to be the
baseline, and threads are the axis actually worth branching on — they depend on the *host's*
COOP/COEP headers, not on the user's hardware.

The two traps are CAD-specific and both became rules:

- **WGSL has no `f64`.** So the kernel never moves to the GPU, whatever a benchmark says. The GPU
  gets display tessellation, BVH, culling, ID-buffer picking, silhouettes, instance transforms.
- **Relaxed SIMD is non-deterministic across platforms.** Fine for rendering, poison in a
  predicate: the same document would produce different topology on different machines and the
  fixture suite would stop meaning anything. The rule is per-crate — `kernel/` builds without it.

Also noted, and easy to miss: the WebGL2 fallback has **no compute shaders**. Anything built on
compute degrades to the CPU, not to a slower GPU.

### Correction · 2026-08-25 · wasm64 is mature, and the conclusion is unchanged

The first answer given was that wasm64 "is not viable yet". That was wrong on the facts. Memory64
was standardised in **Wasm 3.0** (September 2025) and ships in **Chrome 133+** and **Firefox
143+**; `wasm-bindgen` has since added `wasm64-unknown-unknown` support, lowering `usize` and raw
pointers through an `f64` JS number ABI and inspecting the module's memory type to pick codegen.

The original text is left standing above because the correction is the interesting part: the
maturity objection had *moved*, and the reasons to still say no are entirely different from the
reasons first given. It is now bounds-check cost, Rust Tier 3, and Safari — not absence.

Kept as the worked example for AGENTS.md § Always append, never rewrite.

## Walkthrough · as built

Three crates, 2,188 lines, **no dependencies at all** — not even `glam`. The linear algebra the
contract needs is about 200 lines and writing it avoided having any dependency-licence
conversation before the kernel licence is settled.

### `w3d-kernel` — the seam

The trait is thirteen methods and that is on purpose: every one is something a backend has to
implement *well*, so a short list is a short list of things that can be wrong. Two properties of
it turned out to be load-bearing enough to be written into the crate docs rather than assumed:

- **Bodies are immutable.** Every operation returns a new `Body` and leaves its operands intact.
  This is not a stylistic preference about value semantics — it is what makes undo implementable.
  Nothing can invert a boolean, so state-based undo is the only honest kind, and state-based undo
  needs the previous state to still be addressable.
- **Tolerance is an argument.** `Tolerance` is passed into every operation that compares. There
  is one constant, `Tolerance::document_default()`, and it is described in its own doc comment as
  what a *document* starts with rather than something a predicate may reach for.

`Body` is an opaque `u32` newtype with `from_raw` documented as backends-only. That is what makes
"nothing below the seam leaks above it" mechanical instead of aspirational: there is no OCCT type
a caller *could* name, so the rule cannot be broken by accident, only by editing this crate.

### The conformance suite is the interesting part

`w3d_kernel::conformance` is a non-dev feature on purpose, so a backend crate can run it from its
own tests without depending on this crate's dev-dependencies. Thirteen checks, and the discipline
that shaped them is that **every assertion has to be true of any correct kernel** — which throws
out most of the interesting ones. Nothing checks that a boolean is geometrically right; that
needs golden fixtures and a real kernel.

What survived is the contract itself: bounds relate to their operands the way set operations
require (a union contains both, a difference stays inside the minuend, an intersection inside
both); a boolean leaves its operands valid; a copy outlives its original's deletion; a deleted
handle is an error at every entry point and deleting twice fails; tessellation is well-formed,
lies inside its body's bounds, is deterministic, and finer quality never yields fewer triangles.

Two of those are there because of decisions in the first half of this file. **"A boolean leaves
its operands valid"** is history's foundation, and a backend that failed it would break undo in a
way that looks like a document bug for weeks. **"Tessellation is deterministic"** is the property
relaxed SIMD below the seam would quietly destroy, so the rule now has a test that fails when
somebody adds `+relaxed-simd` to the wrong crate.

`Report::assert_passed` prints every failure rather than the first. A backend under development
fails five checks for one reason, and seeing them together is what tells you it is one reason.

### `w3d-kernel-fake` — honest about shape, silent about geometry

A CSG tree that is never evaluated. Bounds are exact for primitives and combined by the rules set
operations obey; tessellation returns the bounding box, subdivided by quality. So its answers are
true statements about the real answer, just weak ones — which is exactly the split the conformance
suite tests, and the reason the fake can pass a suite a real kernel must also pass.

Its subdivision count is clamped to 16 and monotone in `sag`, which is the whole of what
"finer quality never yields fewer triangles" needs from it.

### `w3d-core` — the document

`Document<K: GeometryKernel>` and nothing in the file names a backend. History is a stack of
transactions of `Insert` / `Remove` / `Replace` edits over a generational arena, and a boolean is
one transaction of three edits: remove both operand nodes, insert the result.

Two things fell out of building it that were not obvious from the design:

- **There is no `History::abort`.** It was written, and then it was never called, because the
  document does every kernel call — everything that can fail — *before* opening a transaction. A
  transaction that has begun cannot fail partway. Deleting the method was better than keeping a
  path for a state that cannot occur; the invariant is now a doc comment on `begin`.
- **The mesh cache is keyed by body, not by node**, which makes it permanently valid: bodies are
  immutable, so a body's mesh at a given quality never changes. Only a quality change or garbage
  collection evicts. A node-keyed cache would have needed invalidation on every edit.

### The cost of state-based undo, made visible

Because history holds previous states, the kernel holds every intermediate body for as long as
something can undo back to it. `Document::collect_garbage` walks live nodes plus every retained
edit and deletes the rest, and `clear_history` is the other half. Nothing calls either
automatically — when to pay is a policy the application owns.

The trait deliberately cannot enumerate its own bodies, so the document remembers what it asked
for in a `created: Vec<Body>`. That is the price of a narrow trait, and it is the right price.
`history_holds_bodies_alive_and_clearing_it_lets_them_go` asserts the whole cycle: three bodies
after a union, nothing collectable while undo or redo can reach them, two collectable once history
is cleared.

## Bugs found by building, not by reading

**The free list ate undo.** The arena was written with a free list, because that is what a
generational arena is for. `a_boolean_consumes_its_nodes_and_undo_puts_them_back` failed:
`d.len()` was 1 after the undo, not 2.

The mechanism: `A` is slot 0, `B` is slot 1. The union removes both — freeing slots 0 and 1 — and
inserts the result, which pops slot 1 off the free list. Undo removes the result and then tries to
restore `B` into slot 1, whose generation has now moved twice. `restore` refuses, and refuses
*silently*, so one node simply never came back.

**The fix is that slots are never reused.** Undo restores a node into the slot it came from, so
any free list means a later insert can take a slot an undo still needs. The price is an arena that
grows with the nodes a session ever created rather than the number alive, and `Arena::slot_count`
exists so that cost is observable rather than theoretical.

This is recorded at this length because it is the kind of bug someone reintroduces in good faith
while optimising memory. Compaction — renumbering with history cleared — is the honest fix and is
not written. The rule is now in AGENTS.md, and the test that caught it asserts the *opposite* of
what it originally asserted.

## Loose ends, deliberately left

- **Arena compaction.** Named above. Safe only with history cleared, renumbers every id.
- **Transactions are not user-grouped.** One edit is one undo step, so a drag that transforms
  twenty nodes would be twenty steps. `History::begin`/`commit` already take a label and would
  support grouping; nothing exposes it.
- **`set_tolerance` does not re-evaluate existing geometry**, and says so in its doc comment.
  Retrofitting a tolerance is a rebuild, and a rebuild is a feature that does not exist.
- **No serialisation.** The arena's ids are stable and `u32`, which is most of what a format needs,
  but there is no format.
- **`Topology` is counts only.** Anything richer — face ids, edge loops, the things selection and
  filleting will want — is a widening of the trait, and it should happen when there is a caller,
  not before.

### Correction · 2026-08-25 · what the OCCT exception actually says

The first half of this file, and `AGENTS.md` as first written, said OpenCASCADE was "LGPL-2.1
with an exception. Usable commercially, but read the exception before, not after". The hedge was
right and the summary was wrong, in a way worth leaving standing because it is the version that
circulates on forums.

`OCCT_LGPL_EXCEPTION.txt` — SPDX `OCCT-exception-1.0` — grants exactly one thing:

> The object code (i.e. not a source) form of a "work that uses the Library" can incorporate
> material from a header file that is part of the Library. As a special exception to the GNU
> Lesser General Public License version 2.1, you may distribute such object code incorporating
> material from header files provided with the Open CASCADE Technology libraries under terms of
> your choice.

That is the C++ header problem and nothing else: LGPL-2.1 leaks into callers through `inline`s
and templates, OCCT is enormously header-heavy, and the exception stops the leak. **It does not
waive §6** — the right to relink against a modified library.

Which is our problem specifically, because **a wasm build is static linking**. There is no `.so`
to substitute. A closed distribution would therefore have owed §6 a real answer, and the answers
are Emscripten `SIDE_MODULE` dynamic linking (painful with C++ exceptions and a library this
size, and indirect calls cost), or shipping relinkable objects alongside the binary (legal,
viable, awkward).

Recorded at this length because "OCCT is fine for commercial use" is the single most repeated
claim about this library and it is a summary of a narrower permission than people think.

### The decision, and what it costs

**GPL-3.0-or-later.** The compatibility route is not obvious and is worth writing down: OCCT is
LGPL-2.1-**only**, which reads like it forecloses GPL-3. It does not, because LGPL-2.1 §3 carries
the permission to apply "the ordinary GNU General Public License" to a copy, and its parenthetical
anticipates versions later than 2 explicitly. So the LGPL-2.1-only kernel is taken to GPL-3 and
the combined work is coherent.

Two consequences fall straight out:

- **The whole §6 analysis above becomes irrelevant.** The source ships; there is nothing to
  relink around. The `SIDE_MODULE` question is closed before it was opened.
- **The exception is not relied on either**, and is not needed: there is no proprietary caller
  for LGPL to leak into.

What it forecloses, deliberately and with the decision made knowing it: **a closed binary sold
under a perpetual licence — Plasticity's own model.** Relicensing later would mean removing OCCT
from the project. This is the trade, and it was taken.

Operationally: serving the `.wasm` to a browser **is distribution**. GPL-3, not AGPL, so the SaaS
distinction neither saves us nor is needed. A link to the corresponding source ships with the
build. And modifications to OCCT are OCCT's whatever this repository is: Emscripten port patches
live in their own series, published LGPL-2.1.

### The backend was not a close call

OpenCASCADE is the only mature, free B-rep kernel with NURBS and STEP that exists. The field:

| | |
| --- | --- |
| **truck** | Rust, permissive, `truck-shapeops` has booleans and `truck-js` has wasm bindings. Not production-grade on degenerate input. |
| **Manifold** | MIT, robust, fast — and **mesh**, not B-rep. No NURBS, no STEP. A different product. |
| **CGAL** | GPL or commercial. Exact and slow, and a worse licence than OCCT's for anyone who might not have chosen GPL. |
| **C3D · ACIS · CGM** | Commercial, native-only. The same wall as Parasolid. |

For calibration on "decades of work": **OCCT V8.0.1, July 2026** ships an infinite-loop guard in
the boolean section algorithm and crash guards in chamfer construction. They are still fixing
hangs in booleans in 2026. That is what Parasolid costs and what it buys.

### Two things that shorten the port considerably

**`occt-wasm` already exists** (andymai) — OCCT built for wasm at ~4.5 MB brotli, roughly half of
`opencascade.js`, with arena-based memory, structured errors and Web Worker support, and a Rust
crate. Its licence structure is exactly the one described above, already done by someone else:
the wasm artifact is LGPL-2.1 inheriting from OCCT, the build tooling is MIT/Apache-2.0. That
turns `native/` from a forty-minute C++ build into "evaluate an artifact that exists". Its
surface is TypeScript/embind and we want a C ABI, so it is a starting point rather than a drop-in.

**The export list is already written, and it is the trait.** Thirteen methods means a shim of
thirteen `extern "C"` functions with `EMSCRIPTEN_KEEPALIVE`, not bindings for thousands of OCCT
classes. This is the role `src/module.ts` plays in `wasm-gaming/ppsspp-wasm`: the narrow
declaration *is* the specification of what the Emscripten build must keep exported, and a narrow
declaration is a short list of things that can break. Widen it there first, then implement, then
use.

### truck is the second backend, not the first

Recorded as a decision rather than a leftover. The conformance suite has only ever run against
the fake, so it is not yet known whether it encodes *the contract* or encodes *the fake*. A second
implementation that shares no code with the first is the only thing that can answer that, and
truck — Rust, permissive, genuinely independent — is the cheapest such answer available. When it
fails checks, read them as questions about the suite before treating them as bugs in truck.

### The UI question, closed by the same constraint

`STACK.md` left `egui` versus a TypeScript shell open. **Dioxus** was raised as a third way and is
the strongest candidate against egui: Rust, one codebase, web and desktop, real DOM and CSS.

It fails on the thing that is specific to a modeller: **the UI is not the viewport**. On the web
a DOM shell composes fine around a `<canvas>` that wgpu owns. On the desktop, any DOM framework
is a webview — the Rust core still runs natively, so nothing is lost there — and compositing a
native wgpu surface with a webview has only two answers, both bad: a transparent webview overlaid
on a GL window, whose mouse events fight the viewport's, which is fatal when *everything* in a
modeller is the mouse over the viewport; or rendering to a texture and pushing frames into the
webview, at latency nobody will accept while dragging a vertex.

egui does not have the problem rather than solving it: the chrome is GPU geometry in the same
pass as the scene. One surface, one loop, nothing composited. Blender, Fusion and Plasticity all
land in the same place. Accessibility and IME, the standing objection, are covered by AccessKit,
which egui integrates; limited styling and redrawing every frame remain real costs and are
accepted.

Dioxus stays noted for auxiliary surfaces that composite with nothing — a documentation panel,
the project's site.

## Walkthrough · as built

### 0 — the LICENSE, found locally

Ubuntu ships the canonical text at `/usr/share/common-licenses/GPL-3`. 674 lines, verbatim, and
no network involved. Item 0 was a one-line `cp` once someone thought to look on the disk instead

### 1 — `kernel-occt`, and the header that is the specification

**`native/w3d_occt.h` is thirteen entry points**, one per trait method, plus `mesh_free`,
`last_error` and the context pair. Nothing in it exposes a `TopoDS_Shape`, a `Handle` or a
`Standard_Real`. It plays the part `src/module.ts` plays in `wasm-gaming/ppsspp-wasm`: it is not a
convenience, it is the list of symbols an Emscripten build will have to keep alive through
`EMSCRIPTEN_KEEPALIVE`, and a narrow list is a short list of things that can break.

The claim from the licence session — *"the export list is already written, and it is the trait"* —
held exactly. The header wrote itself from `GeometryKernel`.

**`native/w3d_occt.cpp`, 400 lines**, is where OCCT's shape stops leaking. Three conventions had
to be absorbed there rather than allowed upward:

- **OCCT's cylinder sits on its base**; the contract's is origin-centred. One `gp_Ax2` half a
  height below the origin.
- **OCCT throws** for input it dislikes. Every entry point is wrapped: a `Standard_Failure`
  crossing into Rust is undefined behaviour, and OCCT raises rather than returning.
- **An explorer visits an edge once per face that shares it.** `TopExp::MapShapes` counts unique
  edges. Reporting a box's twelve edges as twenty-four is the sort of wrong nothing downstream
  notices for months.

**`build.rs` shells out to a compiler** instead of using the `cc` crate, so the workspace keeps
its zero-dependency property all the way down. One translation unit, one `ar`, thirteen toolkits
named explicitly — and that list is also the list a wasm build has to compile.

**The crate is excluded from `default-members`**, so `make test` stays a command that needs no
setup. `make test-occt` runs it. The alternative — a feature flag — would have meant every
contributor's `cargo test` either silently skipping the real backend or failing on a missing
system library.

### 2 — the suite's first real verdict

This is what the extension is for. The suite had only ever run against the fake, so it was not
known whether it encoded *the contract* or encoded *the fake*. First run against OpenCASCADE:

```
FAILED  box bounds are exact and origin-centred
ok      sphere bounds are symmetric about the origin
ok      degenerate primitives are refused, not built
ok      union bounds contain both operands
ok      difference bounds stay within the minuend
ok      intersection bounds stay within both operands
ok      a boolean leaves its operands valid
ok      a translation moves the bounds by exactly that
ok      a copy is independent of its original
ok      a deleted body is gone, and says so
ok      topology is reported and is non-degenerate
ok      tessellation is well-formed and inside its body
ok      tessellation is deterministic
ok      quality changes the mesh, not the model
```

Thirteen of fourteen, and the failure was a real defect:

```
expected min -1.0,      -2.0,      -3.0
got      min -1.0000001, -2.0000001, -3.0000001
```

`BRepBndLib::AddOptimal` takes a `useShapeTolerance` argument, and the shim passed
`Standard_True`, which inflates the box by each vertex's and edge's own tolerance — 1e-7 by
default. So a 2×4×6 box reported bounds 2.0000002 across.

**The judgement, written down because the discipline only works if it is:** the check was asked
whether it over-specified, and the answer was no. "Bounds" in the contract means the geometry's
bounds. An inflated box is a defensible answer for *culling*, where conservative is safe, and the
wrong answer to "what are this solid's bounds" — a caller that wants slack can add its own, and
one that cannot tell the difference cannot implement snapping. So **the backend was fixed and the
suite was left alone**, and it then passed. That is the clean outcome: the suite encoded the
contract.

The temptation in the other direction was real and is worth naming. The comparison uses `<=
tol.linear` and the error was 1.0000000116e-7 against a tolerance of 1e-7 — it failed by one ULP.
Loosening the comparison would have made the test green while leaving a backend that answers a
different question than the one asked.

### 3 — the document, against real metal

`kernel-occt/tests/document.rs` drives the *unchanged* `Document` with OCCT underneath. A 40×40×10
plate, a 12mm drill, a difference:

| | solids | faces | edges | vertices |
| --- | --- | --- | --- | --- |
| plate | 1 | 6 | 12 | 8 |
| drill | 1 | 3 | 3 | 2 |
| **drilled** | **1** | **7** | **15** | **10** |

Six planar faces plus one cylindrical; the hole adds its seam edge and two circles, and the seam's
two vertices. That is what a drilled plate *is*, and it is the first thing in this repository that
is true about geometry rather than about machinery. The mesh is 334 vertices and 324 triangles,
every one of the seven faces produces triangles under its own id — which is what ID-buffer picking
will read, so a face that tessellates into nothing is a face a user cannot click — and every normal
is unit.

Undo across a real boolean restores both operands, because OCCT keeps them: the contract's
immutability rule, end to end.

## Bugs found by building, not by reading

**The shim's registry was global, and `cargo test` is multi-threaded.** The first
`the_document_releases_opencascade_shapes_it_no_longer_needs` run failed on a body count, and the
count was wrong because *another test in another thread* had bodies in the same static
`unordered_map`. A wrong number was the polite symptom; the real one is that several threads were
mutating one map with no lock, which is a data race whatever the map does about it.

**The fix was not a mutex.** It was a `W3dOcctContext` per kernel, threaded through every entry
point, freed by `OcctKernel::drop`. That is better than a lock on three counts: each instance's
storage is its own; Rust's borrow rules then serialise access for free, because the mutating
entry points take `&mut self` and the reading ones take `&self`; and a dropped document no longer
leaks OCCT shapes even if nothing called `collect_garbage`.

And it forced an honest admission into the type system. `OcctKernel` holds a raw pointer, so it is
neither `Send` nor `Sync` — which is *correct*, not merely conservative: `tessellate` takes
`&self` and mutates anyway, because `BRepMesh_IncrementalMesh` attaches the triangulation to the
face it meshes. Even the read-shaped calls write. Parallel meshing therefore means one
`OcctKernel` per worker, not a lock, and the compiler now says so.

**Ubuntu Noble's `libocct-foundation-dev` is broken.** `Poly_ArrayOfNodes.hxx` ships and
`#include`s `NCollection_AliasedArray.hxx`, which does not — so *every* translation unit that
reaches `Poly_Triangulation` fails, which is all of modelling. Version 7.6.3+dfsg1-7.1build1, and
there is no other version in the archive. The header was taken from upstream at tag `V7_6_3` and
dropped into `/usr/include/opencascade/`. Recorded because the next person on Noble hits the same
wall and the error message points nowhere useful.

## Verified, and not

**Verified.** `make test` is 19 tests and needs nothing installed. `make test-occt` is 6 more —
the conformance suite plus five document tests — against OpenCASCADE 7.6.3. `cargo clippy
--all-targets -- -D warnings` clean, `cargo fmt --check` clean, and the default members still
build for `wasm32-unknown-unknown`.

**Not verified, and the risk taken with each.**

- **No Emscripten build exists.** Everything about OCCT-in-wasm remains an argument: the size, the
  toolkit list, and `-fwasm-exceptions` against `-fexceptions`, which is a real decision with real
  size and speed consequences that has not been looked at. `kernel-occt` is excluded from
  `make wasm` for exactly this reason, so the wasm check does **not** cover it.
- **The conformance suite still encodes what two backends agree on.** OCCT passing is much
  stronger evidence than the fake passing, and it is not proof. truck is still the interesting
  third opinion.
- **Five document tests are not a fixture suite**, and not one of them is degenerate. No
  coincident faces, no tangent surfaces, no near-zero-thickness result — which is exactly where a
  B-rep kernel actually fails, and where OCCT is known to.
- **The topology numbers for the drilled plate are asserted from observation**, not derived. They
  are right, and a different kernel producing different ones would not necessarily be wrong — it
  would have to say so out loud, which is the point of asserting them.
- **`live_bodies` is now per-context and the tests rely on it**, so they no longer prove anything
  about the *process* not leaking — only about one kernel.
- **The `NCollection_AliasedArray.hxx` workaround is in this container, not in the repository.**
  A fresh checkout on Ubuntu Noble will not build `kernel-occt` until someone repeats it.

## Loose ends, deliberately left

- **No OCCT version is pinned.** The build takes whatever the system has. A `native/UPSTREAM`
  equivalent is owed before the Emscripten build, not after.
- **`BRepBuilderAPI_GTransform` is written and never exercised.** The fallback path for
  non-uniform transforms has no test, because nothing in the suite scales non-uniformly. It is the
  most likely thing in the shim to be wrong.
- **STEP and IGES are not wired**, though `TKDataExchange` is one toolkit away and is most of why
  OCCT was chosen.
- **Fillets are not wired either**, and `TKFillet` is present. That is the feature Plasticity is
  actually good at, and the first honest measurement of the gap.
- **Nothing frees a mesh early.** `tessellate` copies and frees inside one call, which is simple
  and costs a full copy of every vertex buffer.

### Blocking a viewport existing at all

1. **`render/`** — wgpu initialising against WebGPU with a WebGL2 fallback, and detecting whether
   compute is available rather than assuming. Nothing is drawn yet, and everything after this is
   cheaper to judge with something on screen.
2. **`app/`** — egui over the wgpu surface, in the same pass as the scene. The decision is made
   (see `The UI question, closed by the same constraint`); the integration has never been run.
3. **`web/`** — the loader: `wasm-feature-detect` probing threads, a COOP/COEP check that degrades
   visibly instead of failing obscurely, and the two-variant dispatch. Where `make wasm` stops
   being a type-check.

### Blocking the wasm target

4. **An OCCT build for Emscripten.** `kernel-occt` is excluded from `make wasm`, so the wasm check
   does not cover it today. The toolkit list in `build.rs` is the input. Two things must be
   decided rather than discovered: `-fwasm-exceptions` against `-fexceptions`, which has real size
   and speed consequences; and a pinned upstream revision, which does not exist — the build takes
   whatever the system has.
5. **The Ubuntu Noble workaround is in a container, not in the repository.** `README.md` documents
   it, which is enough for a human and not enough for CI. A fresh checkout does not build
   `kernel-occt` unattended.
6. **The tessellation format across the worker boundary** was hand-waved as "transferable
   `ArrayBuffer`" in the first session and never designed. It constrains the GPU upload path, and
   `tessellate` currently copies every vertex buffer once inside a single call.

### Owed, but not blocking

7. **Fixture regression with degenerate input** — coincident faces, tangent surfaces, thin walls.
   The five tests in `kernel-occt/tests/document.rs` are seeds, not a suite, and not one of them
   is degenerate. This is where B-rep kernels actually fail and where OCCT is known to.
8. **truck as the second backend.** The conformance suite currently encodes what two backends
   agree on, one of which does no geometry. An independent implementation is the only thing that
   can tell us whether the suite is right, and every failure it produces is a question about the
   suite first.
9. **`BRepBuilderAPI_GTransform` has never been exercised.** The non-uniform-transform fallback
   has no test because nothing in the suite scales non-uniformly. It is the most likely thing in
   the shim to be wrong.
10. **STEP and IGES.** `TKDataExchange` is one toolkit away and is most of why OCCT was chosen.
11. **Fillets.** `TKFillet` is present. This is the feature Plasticity is actually good at, so it
    is also the first honest measurement of the gap — worth doing once there is a viewport to see
    them fail in.
12. **Transactions are not user-grouped.** One edit is one undo step, so a drag that transforms
    twenty nodes would be twenty steps. `History::begin`/`commit` already take a label and would
    support grouping; nothing exposes it.
13. **No serialisation.** The arena's ids are stable `u32`, which is most of what a format needs.
    There is no format.
14. **Arena compaction.** Slots are never reused, so an arena grows with the nodes a session ever
    created. Safe only with history cleared, and it renumbers every id. `Arena::slot_count` is how
    the cost is visible meanwhile — and a free list is not the fix, see the rule in `AGENTS.md`.
15. **Measure something.** The 4 GB sharding argument is still an argument. A tessellated body of
    known size through the worker boundary turns it into a number.
16. **The project's name.** `3dworld` is a directory. Crates are `w3d-` because `3dworld` is not a
    valid Rust identifier. Costs nothing now, costs a rename later.

### Known and deliberately not pending

- **`set_tolerance` does not re-evaluate existing geometry.** Retrofitting a tolerance is a
  rebuild, and a rebuild is a feature that does not exist. Documented at the call site.
- **`Topology` is counts only.** Face ids, edge loops and the rest are a widening of the trait,
  and that should happen when there is a caller, not before.
- **`OcctKernel` is neither `Send` nor `Sync`.** Correct, not pending: `tessellate` mutates
  through `&self` because OCCT attaches triangulations to faces. Parallel meshing means one kernel
  per worker.
- **`collect_garbage` rebuilds a `HashSet` per call.** Fine at this size, unmeasured at any other,
  and not worth touching before there is a document large enough to notice.
- **Safari's Memory64 status is unresolved.** It blocks nothing, because wasm64 was rejected on
  other grounds. Do not quote a Safari version from this file.
