# 2026-09-26 20h35 · What a save and a build carry

Takes register **item 6** — *"Nothing ships the NOTICE beside the thing it is a notice for"* — and
the small item *"`TruckKernel::save_body` is not byte-stable across runs"*. Both were chosen for
the same reason: each was a thing already wrong in what this repository hands out, rather than a
thing not yet built, and each could be verified from inside this container.

## Where this repo actually was

- `make web` built `web/dist/` with the wasm and its glue and nothing else. The Pages job uploads
  `web/`, so what was served was a GPL-3 program with its licence, and the notices of 248 crates
  and two fonts, left on the build machine. `make notice-check` kept `NOTICE` honest in the tree;
  nothing put it anywhere a visitor could reach.
- The register said `save_body`'s instability came from *"a pointer-keyed, randomly-seeded
  `HashMap` in `truck-topology`"*. That was measured as a symptom — ten runs, same length, same
  numbers, different order — and the cause was attributed by reading, not by measuring.
- The container's stable `rustc` was 1.94.1 again, below egui 0.36's 1.95, so `make test` did not
  start until `rustup update stable` (to 1.98.1). The environment, as on the morning's file.

## Walkthrough · as built

**The save.** The attribution was wrong, and finding that was most of the work.
`truck_topology::compress` is deterministic: it numbers vertices and edges by `map.len()` at first
sight and sorts by that number on the way out, so its output is a pure function of the order it is
handed the faces in. What varies is that order. `truck-shapeops` builds a boolean's result by
iterating maps keyed by `VertexID`/`EdgeID` — addresses — so the cut's **faces** arrive in an order
that changes with the allocator, and `compress` faithfully numbers each order differently. A
dump of two runs showed the same nine faces in a different sequence and nothing else different.
The operands were always stable — `make xarch` has asserted `plate.blob.hash` and
`drill.blob.hash` exactly for days — because a primitive's faces come from a `Vec`.

So the fix is where the register said, on the way out, but not what it described: `save_body` now
writes `canonical(solid)`, the same `truck-json-1` with every order the topology leaves free
decided from the geometry. Three orders are free in a compressed shell — the faces, which edge
each loop starts at, and which of a face's loops comes first — and the vertex and edge tables
follow from the walk. Each loop is rotated to start at its least edge use, compared as a whole
sequence so a loop that visits a point twice still has one answer; a face's loops are sorted; the
faces are sorted by surface, orientation and loops; shells by their text; and the tables are
renumbered by the same first-sight walk `compress` makes. The keys are the geometry's own
`serde_json` text, which is what the file holds anyway: two faces whose keys tie are identical in
everything written, so their order cannot show. The file format is unchanged — `load_body` reads
old files and new ones alike, because both are a `CompressedSolid`.

**It found a second bug on its first test, and an older one.** Save, load and save gave a
different file, before canonical order had anything to do with it: **28 numbers in the demo cut
came back one ulp off** — `3.2475952641916446` read as `3.247595264191645`. `serde_json` without
its `float_roundtrip` feature parses a decimal to within an ulp rather than to the double that
printed it. So every `truck` document reopened since `.w3d` existed held a solid a bit different
from the one that was saved, in the control points of the cylinder and the polylines that lead the
intersection curves. `kernel-truck` now asks for `float_roundtrip`; the feature is additive and
unifies across the build, so `w3d-format`'s manifest parsing gets it too.

**What holds it.** `kernel-truck/tests/save_order.rs`, three tests on the drilled plate. The one
that matters cannot wait for the allocator to shuffle something, because a test that does passes
whenever the allocator is kind — so it does the shuffle itself: the saved JSON is taken apart, the
faces reversed, each face's loops reversed, each loop started one edge later, and the vertex and
edge tables reversed with every index rewritten; that loads, and must save to the original bytes.
A control asserts the scramble changed the bytes at all. The second holds save-load-save to
identity, and the third holds the scrambled solid to the same topology and triangle count, since
a canonical order is only worth having for the same solid. And `make xarch` gains
`cut.blob.hash`, the saved cut's **bytes**, exact — a row the morning's file had to leave out.

**The notice.** A `web-notice` target: `tools/notice.py --check` first, then `NOTICE` and `LICENSE`
copied into `web/dist/` as `NOTICE.txt` and `LICENSE.txt`. Refusing a stale notice at the build,
rather than only in `make test`, is the point — a notice that omits a crate is the same absence as
no notice for that crate, and `make web` is run in places `make test` is not. `.txt` because a host
serves an extensionless file as a download or not at all. Both `make web` and `make web-threaded`
end by running it, so either build alone leaves a servable directory.

The page gets a line under the status bar: the licence's name and three links — the licence, the
notices, and the source. The first two carry `data-notice`, and `make web-test`'s service-worker
run, the one shaped like GitHub Pages, **fetches every such link** and requires two, each an
HTTP 200 with a body, and the notice to begin with this project's header. A link in the markup to a
file that was not copied reads as compliance and serves a 404, which is the failure this checks.

## Bugs found by building, not by reading

- **`load_body` was lossy on `truck`.** `serde_json`'s default float parser is not correctly
  rounded; 28 of the demo cut's numbers came back one ulp off. Cause: the `float_roundtrip`
  feature was never asked for, and nothing compared a reopened solid with the saved one below the
  level of a triangle count. Nothing in the suite would have found it: every check of a reopen
  weighed a mesh, and an ulp in a control point moves no vertex a triangle count can see.
- **The register's diagnosis of `save_body` named the wrong crate.** Not a code bug, and recorded
  because the item had been rewritten twice with the wrong cause in it: `truck-topology`'s maps
  are only looked up; the order comes from `truck-shapeops`' result. The morning's audit item —
  the other `FxHash` containers in `truck-shapeops` — is where this belongs, and this is the first
  measured case of one reaching an output.
- **`make web` prints `wasm.br: 0.00 MiB` when `brotli` is not installed.** The `|| true` guards the
  pipe, not the `wc`, so an absent tool reports a size of zero. Seen here, not fixed — item 7 is
  where brotli gets a real number.

## Verified, and not

**Verified**

- The cut's saved bytes are **identical across ten processes** on x86-64 (they differed in every
  one of six before), and identical between x86-64 and wasm32: `make xarch` passes all 32 rows,
  `cut.blob.hash` among them.
- `save_order.rs` passes, and **fails without the change**: with `save_body` put back to a plain
  `serde_json::to_string`, the scramble test fails; with `float_roundtrip` off, the save-load-save
  test fails on the 28 numbers above.
- `make web-test` passes every check, including the three new ones, with the single-threaded
  build (no nightly here, so the threaded variant is absent and the suite's own branch for that
  asserted). With `web/dist/NOTICE.txt` deleted, exactly the two notice checks fail, HTTP 404.
- `make test` — see the end of this file for the run.

**Not verified**

- **Canonical order is shown on one solid.** The drilled plate: one shell, nine faces, loops with
  no repeated vertex, no two faces with the same surface. A shell with two faces on one plane, or
  a solid of several shells, goes through code paths the scramble test does not reach — the tie
  argument says they are safe, and nothing has run it.
- **Sorting a face's loops assumes truck gives the first loop no meaning.** Nothing read in
  `truck-topology` or `truck-meshalgo` treats `boundaries[0]` as the outer loop, and the scrambled
  solid meshes to the same triangle count. The evidence is the plate's top and bottom — the only
  faces with two loops, the outline and the hole — surviving having their loops reversed. Two
  faces, and a triangle count rather than a comparison of the triangles.
- **OpenCASCADE's blob is untouched.** `.w3d` from `OcctKernel` is still not byte-stable across a
  reopen (the `Checked` flag), which is a different item and still stands.
- **The source link points at the repository, not at the commit that was built.** GPL-3 §6(d)
  wants the Corresponding Source of *this* object code; a link to `main` is right only while the
  deployment is `main`'s head, which the Pages job makes true in practice and nothing enforces.
- **Nothing ships the notice beside a desktop binary**, because nothing ships a desktop binary.
  There is no packaging step to put it in; the day there is one, this is owed again.
- **`float_roundtrip`'s cost is** measured below in `make web`'s size, and not in time: it is a
  slower parser, and no load of a large `truck` document has been timed with it.

## Loose ends, deliberately left

- **The source link's commit.** The Pages job could write the SHA into the page at build time. Not
  done: it is a build step that edits a committed file, for a gap that is closed while deployment
  follows `main`.
- **`NOTICE` still carries dev-dependencies** (`egui_kittest` and two more). Unchanged here; it is a
  policy decision about the tool, as the register says.
- **The brotli zero.** Item 7's.
