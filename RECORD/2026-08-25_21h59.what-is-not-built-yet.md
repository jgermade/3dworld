# 2026-08-25 21h59 · What is not built yet

**This file is the plan.** It is the register, it supersedes the one in
`2026-08-25_19h22.what-is-not-built-yet.completed.md`, which took over from four `Next` blocks
before it, and it stays open for as long as there is a plan. The *other* `*.md` in `RECORD/`, when
there is one, is the body of work currently in progress; that there should normally be exactly one
of those is the convention in `AGENTS.md`, and this file has never been one of them.

It records no work. It exists so the plan is something a reader can read rather than reconstruct,
and it has no `Walkthrough · as built` and will never grow one — work that acts on it opens its
own file and says which items it took.

**It is also the one file in `RECORD/` that is maintained rather than appended.** The
never-rewrite rule protects a *record*, where the wrong turns are most of the value; this is a
*plan*, and a plan that only grows stops being one. Items leave it as they are done and `## Taken`
at the end says which file took each, so the reasoning stays one link away. Every other file in
the folder is append-only.

## Where this repo actually was

Eight crates. 65 native tests, 17 more against OpenCASCADE, 17 checks in a real browser, and a
window that opens.

```
kernel/        w3d-kernel       the seam: 16 methods + the conformance suite    ✅
kernel-fake/   w3d-kernel-fake  the contract without geometry                   ✅
core/          w3d-core         document · history · selection · mesh cache     ✅
format/        w3d-format       the .w3d file, specified in FORMAT.md           ✅
kernel-occt/   w3d-kernel-occt  OpenCASCADE through a 16-entry C ABI            ✅ native
                                                                                ⬜ wasm
render/        w3d-render       wgpu · camera · ID-buffer picking               ✅
web/           w3d-web          loader · probe · COOP/COEP · a canvas           ✅ WebGL2
                                                                                ✅ threaded
app/           w3d-app          editor · scene · winit and egui in one pass     ✅ desktop
kernel-truck/  w3d-kernel-truck pure Rust: exact surfaces, real edges, and a
                                boolean that is narrow rather than absent      ◐
kernel-native/                  ours, or truck                                  ⬜
```

A person can open a window, add primitives, select them, run a boolean on real OpenCASCADE
geometry, orbit, pan, undo, save and reopen — and export what they made as STEP, or import one,
including files written by Pro/ENGINEER and Siemens NX. **No CAD program has yet opened a file this
one writes**: a parser with no OCCT in it has read one and found the solids in it, which is
evidence about the file and not about the geometry.

The browser runs the same viewport on `TruckKernel`, in either a single-threaded or a threaded
build, and the threaded one meshes a solid's faces across a rayon pool. **Since 2026-09-05 it
models**: the plate on the page has a hole in it because a boolean cut one, and the page says so.
What that boolean will do is narrow — see the small items — and there is still no OCCT in wasm.

**Not verified, and the risk taken with each.**

- **WebGPU has never rendered a pixel, anywhere.** Native runs are Vulkan through lavapipe, which
  is not WebGPU; the browser's WebGPU reports an adapter and draws nothing. The largest single
  unknown, and the only thing established about it is that a browser can claim it falsely.
- **Nothing about how it *feels*.** Thirty frames under a software rasteriser prove the pipeline
  runs. Latency while dragging is the only thing that matters in a modeller and cannot be measured
  here.
- **One browser, one windowing system.** Chromium and X11 under Xvfb. No Firefox, no Safari, no
  Wayland, no macOS, no HiDPI.
- **A skipped test looks like a passed test.** `w3d-render`'s tests print `SKIPPED:` without an
  adapter and `cargo test` still says `ok`; `make web-test` and `make app-test` are not part of
  `make test` at all.
- **Little geometry is verified beyond the contract.** Since 2026-09-05 the conformance suite has a
  geometry half — the volume a mesh encloses, and what a boolean does to it. Later the same day it
  also gained a **golden census** that compares a *boundary*: the material in each plane, where its
  centre of area is, the total area lying in no named plane, and the rule that a face id names one
  connected region. That closed the "weighs rather than compares" half of this item, and the
  centroid is what makes it worth having — a hole drilled in the wrong place weighs exactly what a
  hole drilled in the right place weighs.
  Later again the same day it gained four degenerate fixtures and an off-axis one, and the first of
  those found a real defect: a difference by a tool that missed the part returned an empty body.
  The suite is **42 checks**.
  What is left is still fixtures. Nothing in it has a fillet, a sweep or a loft held to a boundary;
  nothing is degenerate on the *overlapping* side of the line, which is where B-rep kernels
  actually fail; and there is one rotation and no translation away from the origin.
  **`OcctKernel` has now run all of it, and passed.** OCCT is not installable in the environment
  the work was written in, so this was carried by CI: run 64 on commit `207aeda`, OpenCASCADE
  7.6.3, `test opencascade_conforms ... ok` — and since `assert_passed` panics on any failure, an
  `ok` there is all 42 checks. That is the two sessions' single largest open risk closed, and it
  closed the right way: the suite encodes the contract rather than encoding one backend, which is
  the whole reason a second one exists.
- **The suite encodes what three backends agree on**, one of which does no geometry and says so.
- **No CAD program has read a STEP file this one writes.** A parser that shares no code with OCCT
  now reads one and is held to resolving every reference, finding the solids in the model and
  counting the faces by surface type — but it reads the *file*, not the *model*: nothing in it
  builds a solid or would notice one that is not closed. Fusion, FreeCAD, SolidWorks and Onshape —
  the whole reason STEP was chosen — have still never seen one, and nothing that could is
  installable in the environment these sessions run in.
- **Three foreign files is three.** AP203 and AP214 import; no AP242, nothing in inches, nothing
  from CATIA or SolidWorks, nothing pathological. **The unit conversion has still never run**,
  because all three samples are in millimetres.
- **An import is not compared to anything.** Bodies, faces and triangles are printed, not asserted
  against a golden number: a wrong-but-well-formed import passes.
- **No implementation has been written from `FORMAT.md`**, which is the only test of whether that
  document is sufficient. One writer and one reader from the same head agreeing proves less than
  it looks like. There are also no old files, so forward compatibility is asserted by a test that
  edits a version number rather than by history.
- **The numbers that exist are native, single-threaded, and one run each.** *Rewritten 2026-09-14,
  when `make measure` replaced "every performance number here is somebody else's".* Two assemblies
  are now measured phase by phase — see the `Verified` table — and what that does **not** cover is
  most of the argument: nothing is repeated or averaged, so no variance is known; nothing has been
  measured on `TruckKernel`, which is the only kernel the browser has; and **nothing here is still
  evidence that threads made anything faster**. The threaded page reports 0–2 ms on a scene of
  twelve triangles, which is a place to put a number rather than a number.
- **The suite's floor under "a backend may decline" is three box fixtures.** Since 2026-09-05 a
  backend may refuse an operation and still conform, so that a narrow real boolean is not treated
  as worse than a fake one; the union, difference and intersection of two boxes are mandatory so
  that refusing everything cannot pass. That is a floor, not a ceiling: a backend that does those
  three and declines the rest is conforming, and is not a modeller.
- **`f32` mesh positions are absolute.** A document kilometres from the origin has lost precision
  before the camera sees it, and the camera's `f64` cannot recover it. **Measured on 2026-09-14**, on
  a 2 mm cube whose geometry OpenCASCADE has exactly right in `f64` at every distance: drawn 0.016 mm
  out of place at 1.2e6, 0.2 mm at 8.4e6, 0.6 mm at 1.7e7, and at **3.4e7 — 34 km in a millimetre
  document — its mesh encloses no volume at all**, because an `f32` there is spaced 4 mm apart and
  both faces of the cube land on one grid line. The conformance suite holds a backend to a kilometre
  and stops there, because past that the limit is this crate's `Mesh` and not the backend.
- **The licence texts are collected but nothing assembles a distribution.** `make notice` writes
  `NOTICE` — 328 crates, and the fonts egui embeds, whose licences oblige their notices to be
  preserved — and `make notice-check` fails `make test` when it is stale. What does not exist is
  anything that *ships* it beside a binary or a `.wasm`.

### Blocking a modeller somebody can actually use

1. **A CAD program opening a file this one writes.** The half of the old item 1 that no check
   here can close, and it is now the *only* claim about interchange resting on nothing outside
   this repository. `make step-check` has an independent parser reading the file and finding the
   solids in it; what nobody has is a second *geometry* kernel building them. It needs an
   environment with FreeCAD in it — this one's apt sources have none — or a person, once, with
   Fusion or Onshape open and this file in front of them.
   The other half is done: files from Pro/ENGINEER, Siemens NX and ST-Developer import, and a
   surface model from the wild is refused by name. What is still missing there is **a sample in
   inches from the wild** — `kernel-occt/tests/step.rs` runs the conversion by rewriting the unit
   entity of a file this program wrote, which exercises the reader and not another writer's idea of
   an inch — **and one in AP242**, and a golden number to compare an import against rather than
   counting that solids came out. Since 2026-09-13 there is one such number, for one file:
   `make step-check` weighs AS1's whole assembly tree against what the file holds.
2. **WebGPU on hardware that works.** See `Verified, and not`. Until then the fast path is an
   argument, and so is every performance claim resting on compute shaders.

### Blocking the wasm target

3. **An OCCT build for Emscripten.** `kernel-occt` is excluded from `make wasm`, so the browser
   has no exact kernel in it. It is no longer a `FakeKernel` bounding box — `TruckKernel` has
   tessellated the browser's scene since 2026-08-27 — but the boolean's narrowness is what that is worth: real
   surfaces, and no boolean under them. The toolkit list in `build.rs`
   is the input. Two things must be *decided* rather than discovered: `-fwasm-exceptions` against
   `-fexceptions`, which has real size and speed consequences; and a real upstream pin —
   `native/UPSTREAM` names a version, it does not enforce one. **STEP made this bigger**: five more
   toolkits are in the link now — `TKXSBase`, `TKSTEPBase`, `TKSTEPAttr`, `TKSTEP209`, `TKSTEP` —
   and the last is wanted by nothing here and will not link without the one before it.
4. **One boolean, two architectures, two different solids.** *New on 2026-09-15, and the finding
   the document work produced. The old item 4 — no document across the worker boundary — is in
   `## Taken`.*
   The browser's demo scene is a plate with a hole. Cut **natively** and carried into the browser
   as a `.w3d`, it meshes to **6294** triangles; cut **in wasm32** by the same kernel at the same
   tolerance, it meshes to **6290**. The four triangles are not the tessellator, and that is what
   makes this worth a number: the same document meshes to 6294 natively *and* to 6294 in the
   browser, so tessellation of identical input agrees across the two architectures. It is the
   **boolean's output** that differs.
   `truck-shapeops` divides an intersection curve into a polyline at a sag tolerance, so a float
   difference of an ulp plausibly moves a segment count — but nothing has looked, and *plausibly* is
   the whole of what is known.
   This is the hazard `AGENTS.md` legislates against for relaxed SIMD — "results are *permitted* to
   differ between machines, so one document would produce different topology on different hardware
   and the regression fixtures would stop meaning anything" — arriving through a door that rule does
   not cover, since nothing here enabled relaxed SIMD. What it costs is not yet known and is worth
   stating as a question rather than a severity: a document modelled on the desktop and the same
   document modelled in the browser are not the same solid, which matters for a golden fixture, for
   a content-addressed store, and for any claim that the two builds are the same modeller.

### Owed, but not blocking

5. **A GPU in CI.** The browser half is done and so is CI itself — `make test`, OCCT, step-check,
   the window under Xvfb and FreeCAD on every push, the browser nightly — so a green run is now
   evidence of something. It is still not evidence about a **driver**: the window job draws on
   lavapipe and the browser job on headless Chromium's software path, and WebGPU has never
   rendered a pixel anywhere. A GitHub runner has no GPU, so this needs a self-hosted runner with
   one, or a person, a machine and a screenshot.
   Both jobs now *say* so rather than leaving it to be inferred: since
   `2026-09-03_01h25.what-the-adapter-will-admit.completed.md` the report names what is behind the
   adapter, and every run of it anywhere has said `software (CPU rasteriser)`. The `Hardware`
   branch has never been taken.
6. **Nothing ships the NOTICE beside the thing it is a notice for.** *Was item 8, "A NOTICE file
   for a distribution"; rewritten 2026-09-05 after the code was read.* The file exists and is kept
   honest: `tools/notice.py` collects the licence text of every crate and of the fonts egui embeds,
   `make notice` writes it, and `make notice-check` fails `make test` when it is stale.
   What has never existed is the last step, which is the one the licences actually require.
   `make web` builds `web/dist/` and **does not copy `NOTICE` into it**; nothing puts it beside a
   desktop binary either. The fonts are OFL-1.1 and Ubuntu-font-1.0 and both oblige their notices
   to be *preserved*; MIT and Apache-2.0 want the same, and GPL-3 §6 wants the corresponding
   source. Serving a `.wasm` is distribution, and today it is distribution with the notice left on
   the build machine.
7. **`wasm-opt`, brotli, and a real payload number.** `make web` reports **4.25 MiB** of wasm and
   **1.28 MiB** gzipped, up from 3.34 and 1.12 when `truck-shapeops`, `truck-meshalgo` and `spade`
   joined the tree on 2026-09-05. Both are upper bounds and lazy ones, and OCCT will dwarf them.
   **It got worse on 2026-09-15**, deliberately and with the trade written down: sending a document
   into the worker as a `.w3d` put `w3d-format` and `serde_json` into the browser build, which cost
   **+217 KiB raw and +74 KiB gzipped** (4 502 678 → 4 724 483 bytes, one toolchain, same tree).
   What it bought was not having a second document format: reusing `FORMAT.md` means one
   specification, one implementation, and the kernel-mismatch rules for free. A leaner format for
   this boundary alone is the alternative, and it is a specification nobody has written.

8. **Three modelling operations the browser does not have.** Since 2026-09-14 `TruckKernel`
   refuses `fillet`, `chamfer` and `shell` outright, along with a `sweep` along a bent path and a
   `loft` of more than two sections — where before it returned the body unchanged, or a smaller box,
   and said it had worked. The refusals are honest and they are still absences: the default desktop
   build and the browser are both `--features truck`, so a user there cannot round an edge, cut a
   corner, or hollow a solid at all. `fillet` needs a rolling-ball surface, `shell` needs an offset
   surface, and `truck` has neither; a `chamfer` built the cheap way — a plane and a boolean — needs
   the coincident-face boolean that same backend declines. The honest routes are OCCT in wasm
   (item 3), or writing the blends.
   **The half about the Ribbon was taken on 2026-09-18** by
   [`2026-09-18_06h36.what-a-build-can-actually-do.md`](./2026-09-18_06h36.what-a-build-can-actually-do.md),
   and what is left of this item is the operations themselves. `GeometryKernel::supports` takes a
   `Capability`, the conformance suite holds every backend to its answers in both directions, and
   the Ribbon's `Fillet`, `Chamfer`, `Shell`, `Sweep` and the two STEP buttons are now disabled
   with a reason on a build that cannot serve them — as are the edge-blend handles, which are no
   longer drawn where a blend cannot happen. A user on the browser build no longer finds out by
   pressing.
   **Two things it deliberately does not cover**, and they are the honest shape of what a query
   can do. The boolean has no capability: `truck` declines a body with a pole and two boxes
   sharing a coplanar face, which is a property of the *operands*, so the commonest thing a user
   meets there is still found out by pressing. And `w3d-web` asks nothing — it has no Ribbon and
   no buttons, so the browser, whose backend holds six of the `false`s, has no caller for the
   query at all.
9. **A mesh is in the geometry blob, and no document says so.** *New on 2026-09-14, and the
   finding `make measure` produced.* OpenCASCADE attaches a triangulation to the faces it meshes
   and its BREP writer writes what is attached, so a `.w3d` saved after the document has been
   *looked at* is **52x** larger than the same document saved before — 97 KiB against 4.95 MiB on
   AS1, 40 MiB against 230 MiB on the large assembly — and the save is forty times slower.
   `FORMAT.md` specifies a geometry blob and says nothing about a mesh inside one, so a second
   implementation written from that page would be conforming and a fifty-second the size. What the
   larger file buys back is not reliable: re-meshing a reopened AS1 costs 12% of the first
   tessellation and the large assembly 88%, and **why they differ is not known**. Three ways out —
   clean the shape before writing, store the mesh on purpose with the quality it was made at
   beside it, or leave it and document it — and each is a decision about `FORMAT.md` rather than a
   fix.
10. **The project's name.** `3dworld` is a directory. Crates are `w3d-` because `3dworld` is not a
    valid Rust identifier. Costs nothing now, costs a rename later.

### Small, and easy to lose

- **No pointer has ever touched this program.** *New on 2026-09-21, and it is three bodies of work
  deep.* The manipulators are exercised through `crate::gizmo`'s arithmetic and through
  screenshots; the Ribbon's gating is exercised through `Editor::supports`. Neither is the thing a
  user meets: nobody has grabbed a handle with a mouse, and nothing checks that a disabled button
  is grey or that its tooltip appears. `capable()` — the helper that decides a button's enabled
  state and attaches the refusal text — **has no test at all**; it is correct by construction from
  `Editor::supports`, which is tested, and that the construction was applied to the right eleven
  call sites is read rather than checked. It needs an `egui` test harness, or a screenshot
  assertion narrower than the smoke test's colour count, and a display. From
  `2026-09-16_02h35.the-manipulators-that-move-the-part.completed.md` and
  `2026-09-18_06h36.what-a-build-can-actually-do.completed.md`.
- **`Capability` is a flat enum, and nothing in it implies anything.** *New on 2026-09-21.* Nothing
  stops a backend claiming `EdgeIdentity` while denying `Blend`, which is right — `truck` does
  exactly that — or claiming `MultiSectionLoft` while declining a two-section loft, which is not
  right and is not checked. The conformance probes would catch the second only by accident.
- **The keyboard bypasses the capability gating entirely.** *New on 2026-09-21.* `R` still reaches
  `Command::Fillet` and `H` still reaches `Command::Shell` on a build that has neither. Deliberate
  — a key has no disabled state to show, and the refusal in the status bar is the honest answer —
  but it means the query governs the mouse and not the keyboard, and **nothing enforces that the
  two offer the same set**.
- **`Capability::absence` is in English and the editor's refusals are in Spanish.** *New on
  2026-09-21.* The Ribbon's labels are English, the status bar is mostly Spanish, and
  `blend_selected_edge` now puts an English sentence inside a Spanish refusal. The app has no
  localisation; this is one more place that has to be looked at when it gets one.
- **Nothing decides which *form* of blend a button offers.** *New on 2026-09-21.* There are four
  blends — `fillet` and `chamfer` on the whole solid, `fillet_edges` and `chamfer_edges` on named
  edges. The Ribbon drives the whole-solid pair and the gizmo drives the per-edge pair, and one
  `Capability::Blend` covers all four. That split is a decision nobody made.
- **The capability probes' fixtures are one box and one circular profile.** *New on 2026-09-21.* A
  backend that declined a bent sweep of a *polygon* while performing one of a circle would pass.
  Every probe is the smallest call that can only be refused for the reason the capability names,
  which is what makes the two directions meaningful, and it is also the narrowest evidence a `true`
  can rest on. `EdgeIdentity` is probed on a box: `edge_of_line(0)` on a tessellated cube says a
  backend attributes *some* segment to *some* edge, and that the ids are the right edges is checked
  in `kernel-truck/tests/edge_identity.rs` and `app/tests/blend_edges.rs` rather than here.
- **`TruckKernel::bounds` costs 2.4 s on a 6,334-triangle solid**, because it tessellates the body
  again at a sag finer than any viewport asks for. *Measured on 2026-09-16, when the manipulators
  called it every frame and took `make app-test` past its three-minute timeout on `main`.* The
  handles now use `Document::mesh_bounds` — the box around the tessellation the renderer has
  already paid for — which is an **approximation, not an identity**: it is exact to the
  tessellation's own chordal error, a fraction of a pixel at any zoom a gizmo is legible at, and it
  is not the solid's box. `bounds` itself is unchanged and still costs what it costs to every
  caller that needs the kernel's exact answer.
- **Rotation turns about a bounding-box centre, and a group turns wrongly.** *New on 2026-09-21.*
  The rings turn about the selection's bounding-box centre, with no way to put the centre anywhere
  else and no numeric entry for it; and a multi-selection issues `RotateSelection`, which rotates
  **each body about its own centre** rather than about the selection's shared one. The second is
  pre-existing and is still wrong for a group.
- **The sketch tools have no manipulator.** *New on 2026-09-21.* Every other selection got one in
  2026-09-16 — a body gets the translate triad and the rotation rings, a face gets the push/pull
  arrows, an edge gets fillet and chamfer — and a sketch got nothing. Nothing has been decided
  about what a handle on a sketch entity would even be, which is why this is an absence rather
  than a defect. From `2026-09-16_02h35.the-manipulators-that-move-the-part.completed.md`.
- **`Editor::drag_face_extrude` draws no preview.** *New on 2026-09-21.* Dragging a selected face in
  the viewport with no handle accumulates and applies on release like the manipulator does, but
  shows nothing while it is happening; the arrow handle is the only path with a preview.
- **Push/pull is planar-only, and its planarity test is a tolerance.** *New on 2026-09-21.*
  `face_loop` accepts a face whose vertices sit within the weld distance of one plane, scaled by
  the coordinates' own `f32` noise — a very finely tessellated curved face far from the origin
  could in principle pass it, and no such case was constructed. A face with a **hole** is refused
  rather than handled, because the loop chaining insists on exactly one loop: pulling the face of a
  plate with a bore through it will not work. Both are refusals rather than wrong answers.
- **Edge identity stops at the worker boundary.** *New on 2026-09-18.* `Mesh.edge_of_line`
  says which topological edge a wireframe segment came from, and `WIRE.md` has no section for
  it, so a mesh that is encoded and decoded comes back with it **empty** — which
  `Mesh::edge_of_line` reports as "this backend does not say" rather than as a wrong id. It
  costs nothing today, because the browser's backend declines every blend and ids would cross
  the boundary only to be refused; it is the line that has to change the day the browser has a
  kernel that blends, and `wire/src/chunk.rs` says so where the code is. From
  `2026-09-18_03h22.a-blend-that-names-its-edge.completed.md`.
- **`truck`'s `Topology::edges` is not a count of edges.** *New on 2026-09-18.* It sums
  `wire.len()` over every face's boundaries, so it counts each edge *once per face that uses
  it*: a cube reports **24** where it has 12. Nothing depended on it until a per-edge blend
  needed an id space to validate against, and that uses a distinct-edge count of its own
  instead. Correcting the reported number changes what every existing conformance expectation
  about it means, which is why it was written down rather than fixed in passing. From
  `2026-09-18_03h22.a-blend-that-names-its-edge.completed.md`.
- **A chamfer's geometry is unmeasured, and no blend has been weighed on more than one edge.**
  *New on 2026-09-18, and what closed
  [`2026-09-18_03h22.a-blend-that-names-its-edge.completed.md`](./2026-09-18_03h22.a-blend-that-names-its-edge.completed.md)
  left owed.* `chamfer_edges` is verified as a *contract* — declinable with its three siblings,
  refuses an empty selection and an id no edge has — and nothing weighs the material a bevel
  removes the way the fillet's 17.3474 against the closed form's 17.1681 is weighed; the C++
  differs from the fillet's only in the maker type. Every geometric assertion about a blend is a
  single straight edge of a cube: **two edges that meet is untested**, and it is the case where
  blends must interact and the one a real kernel finds hard. So is a curved edge, and any radius
  large enough for two blend surfaces to collide — OCCT's `IsDone()` refusal path is reported and
  never exercised. And `edge_of_line` is unverified against a boolean's output: ids are documented
  to renumber across one and the editor drops its selection accordingly, but no fixture cuts a
  solid and then blends an edge of the result.
- **A blend has no multi-edge selection, and no numeric radius.** *New on 2026-09-18.* The
  seam takes a slice of edge ids and OpenCASCADE is handed all of it at once; the editor passes
  a slice of one, because there is no way for a user to pick two edges. Two edges that *meet*
  are also the untested geometric case — where the blends have to interact, and the one a real
  kernel finds hard. From `2026-09-18_03h22.a-blend-that-names-its-edge.completed.md`.

- **`truck`'s boolean is narrow, and the shape of the narrowness is measured rather than
  understood.** It does box against box in all three operations, and drills a plate with a
  cylinder. It does **not** union two cylinders at any tolerance from 0.05 to 0.001 — `None` or a
  panic — and `cylinder - box` and `cylinder | box` return `None` where `box - cylinder` succeeds,
  so the operation is not symmetric in its operands. A user meets this in the second thing they
  try. From `2026-09-05_13h14.a-boolean-and-a-suite-that-can-tell.completed.md`.
  **The commonest shape of all was measured on 2026-09-13**: two axis-aligned boxes that overlap and
  share coplanar faces — which is very nearly every real cut — fail in *all three* operations at a
  tolerance of 0.004, and so does a pair abutting with one turned a thousandth of a degree. Tangency,
  recorded below as a decline, is not one at the placement tried on 2026-09-13: a cylinder tangent to
  a box face unions correctly, at 9569.08 against 9570.80. From
  `2026-09-13_23h20.where-a-boolean-is-actually-hard.completed.md`.
  Three more shapes of it were measured on 2026-09-05 by
  `2026-09-05_14h52.the-part-disappears.completed.md`, and each is a decline rather than a wrong
  answer, so each conforms and none is a bug:
  **a cavity is impossible** — a 10-cube minus a 2-cube wholly inside it returns `None`, in all
  three operations, so this backend cannot make a solid with a void in it;
  **two cubes sharing exactly a face will not fuse** into the one 2×2×4 box they obviously are;
  and **a cylinder tangent to a box face will not union** with it. Each is a decision about
  `truck-shapeops` — route around it as the separable case now is, pre-flight it, or wait for OCCT
  in wasm, which makes all three moot.
- **A panic inside `truck-shapeops` is fatal in the browser.** It panics rather than failing on
  geometry it cannot handle. `catch_unwind` turns that into an error on the desktop and does
  nothing on `wasm32-unknown-unknown`, which aborts; the backend's `singular` set keeps the one
  case known to abort — a sphere — from reaching it. Neither covers a case nobody has found yet.
  The real answers are a wasm build with unwinding, a pre-flight check cheaper than the operation,
  or OCCT in wasm, which makes it moot.
- **A sphere read from a file is not known to carry a pole.** `singular` records what the backend
  *built*, so a saved sphere, reopened and used as a cutting tool, reaches `truck-shapeops` on the
  web with nothing in front of it.
- **A `truck` boolean does not run at the document's tolerance.** It runs at
  `max(tol.linear, largest_extent * 1e-3)`, because `truck-shapeops` uses that number as the sag
  it divides an intersection curve into a polyline at. So a drilled hole is a polygon with a few
  hundred sides and its volume is 0.006% out. Exercised at 4 mm and 40 mm; nothing has been cut at
  0.4 mm or at 4 m.
- **`TruckKernel::bounds` are the triangulation's, not the surfaces'.** A curved face may bulge
  past them by up to `BOUNDS_SAG` (0.005). It replaced an answer that gridded the untrimmed
  surface and reported points the body does not contain, so this is a bound that can be honoured
  rather than a tighter one.
- **`truck` meshes are about 2.5x denser than they were**, because a trimmed face is a constrained
  Delaunay triangulation rather than four corners of a grid. Nothing has measured what that costs
  the browser beyond the 424 ms the page reports for its own scene on one thread.
- **`vtkio` brings `nom 3.2.1` and `quick-xml 0.22.0` into the host build**, both carrying
  future-incompatibility warnings, for a VTK feature nothing here calls. It cannot be switched off
  from this workspace: `truck-shapeops` depends on `truck-meshalgo` with default features.
- **The truck conformance and tessellation tests take about 18 seconds in debug**, up from under
  one, because they now do real booleans — and `make check` runs the tessellation file twice, once
  per setting of `parallel`.
- **Nothing streams across the worker boundary, and the demo scene cannot show that it could.** A
  chunk *can* be uploaded before its siblings arrive — the indices are chunk-local precisely so that
  it can — and nothing does: `merge` waits for all of them. From
  `2026-09-15_03h30.what-crosses-a-worker-boundary.completed.md`. **2026-09-15 added why it has not
  been demonstrated**: the page's boolean collapses plate and drill into **one body**, so the 624 ms
  of meshing is one body's and cannot be subdivided from outside the kernel. Showing progressive
  upload needs a multi-body document, which is now one line in
  `format/examples/scene_w3d.rs` — and a look at every check written against the current scene.
- **Nothing uses the thread the worker freed.** Since 2026-09-15 the page measures that the thread
  that draws is not blocked while the worker works — 135 ms longest stall against **2063 ms** on the
  control that meshes here — and the only thing it spends that on is painting a spinner. A
  progressive draw, an interactive empty scene and a cancel button are all now possible and none
  exists. From `2026-09-15_10h16.a-document-crosses-the-boundary.md`.
- **The browser demo scene is defined twice**, in `format/examples/scene_w3d.rs` and in `scene()` in
  `web/src/lib.rs`, and what guards them against drift is a triangle count agreeing within 1% — not
  equality, which item 4 above explains is not available. A change to a dimension that does not move
  the triangle count would pass it. Same file.
- **`.gitignore` has `.DS_Store__pycache__/` on one line**, so neither `.DS_Store` nor `__pycache__/`
  is ignored by anything. One character, noticed 2026-09-15 and left alone rather than widening an
  unrelated change.
- **`line_positions` go wholly into chunk 0.** Deterministic and documented, and an imbalance:
  chunk 0 carries the whole wireframe on top of its share of the faces. Same file.
- **16-bit indices are not taken, and the first draft of `WIRE.md` dismissed them with wrong
  arithmetic.** It called the index section "at most a seventh of the vertex section", which is the
  per-*element* ratio read as the per-mesh one. A closed triangle mesh has about twice as many
  triangles as vertices, so its indices are `3 x 2V x 4 = 24V` bytes against the vertices' `28V` —
  six sevenths, and halving them would take something like 12% off a message. The page says so now
  and says the decision waits on a measurement. Recorded because the wrong version read perfectly
  well. Same file.
- **`make measure` has no `encode` or `decode` phase**, and no chunk-count sweep, beside its
  existing `pack` row. Four lines, and a container with OCCT in it. Same file.
- **No second implementation of `WIRE.md` has been written**, so the claim that the page is
  sufficient to implement from is a claim about the page made by whoever wrote it. The header test
  is the closest thing to a check on it. Same file.
- **One body is half of a tessellation.** On AS1 the slowest of eighteen bodies is 481 ms of
  860 ms; on the 15 MB assembly one of 211 is 17.0 s of 37.9 s. Whatever schedules meshing across
  threads has a floor at that body, which is why the browser's pool divides a body's **faces**
  rather than the document's bodies. From `2026-09-14_21h34.what-an-assembly-costs.completed.md`.
- **`Live::resize` is wired and untested.** It reconfigures the surface, the depth texture and the
  capture target, and nothing exercises any of it. The most likely thing in the shell to be wrong.
- **The pick path is asserted at both ends and not in the middle**, where the shell holds a
  `PickPending` across frames.
- **Saving and exporting are synchronous and on the frame.** A large document will stall the
  window, and a STEP export stalls it for longer than a save: it rebuilds the model into another
  representation rather than writing bytes it already has.
- **`Save` with no path writes `untitled.w3d` in the working directory**, because there is no file
  dialogue and adding one is a dependency. The same gap is why there is no *Import STEP* button —
  export can invent a name beside the document and import needs one that exists — and why
  `--import-step` is a command-line option. Everything about files in this program is waiting on
  this one dependency.
- **An import only reframes the camera when the document was empty.** Importing into a populated
  document can leave the new bodies off screen, which looks exactly like an import that did
  nothing.
- **An exported STEP file is not byte-deterministic.** `FILE_NAME` carries a timestamp, so two
  exports of the same body differ. Worth knowing before somebody writes a golden-file test.
- **A `.w3d`'s geometry blobs are not byte-stable across a reopen either**, and for a different
  reason: OpenCASCADE writes a line of shape flags per shape, and a shape just built carries
  `Checked` where the same shape read back from BREP does not. Identical geometry, one character
  different per shape. Two saves of *one* document are identical — that is the claim `FORMAT.md`
  makes and a test holds — but save, reopen and save gives a different file, so a content-addressed
  store would see two. From `2026-09-14_20h25.a-file-that-can-hold-a-tree.completed.md`, which also measured
  the other half: a body's bounds move by up to 1e-13 mm across that round trip, because BREP is
  text.
- **Face ids do not survive a STEP round-trip.** Faces come back renumbered, so a document that
  exports and re-imports loses every per-face selection. That is STEP rather than a defect, and it
  is the second place face identity has come up — the first was the old item 3, edges on `Mesh`,
  which landed. Since 2026-09-05 the conformance suite asserts the property those two share: a face
  id names **one connected region** of the surface, so two faces can no longer wear one name.
- **A `Profile` is one closed outline of lines and whole circles.** No arcs, and no inner loop — so a
  sketch with a hole in it cannot be expressed, and nothing is known about what a backend would do
  with one. `Profile::validate` is also O(n²) in the vertex count, which is nothing at sketch sizes
  and unmeasured at ten thousand points. From
  `2026-09-14_00h21.a-profile-that-reaches-the-kernel.completed.md`.
- **A revolved `truck` solid will not go into a boolean.** A full turn leaves a seam that
  `truck-shapeops` cannot split, so `revolve` marks its result `singular` — it can be drawn and
  measured and not cut. *Revolve, then cut* is an OpenCASCADE-only workflow.
- **Nothing asserts what an extrusion's faces are.** The new arithmetic checks weigh volume and
  extent; the golden census of 2026-09-05 could weigh a prism's boundary plane by plane and does not
  yet.
- **Which XDE levels are an assembly is decided by a heuristic.** Pro/ENGINEER writes each part as
  a product holding two shape representations and XDE marks that product an assembly, so
  `holds_structure` in `w3d_occt.cpp` reads the *names*: a file names the components of a real
  assembly and leaves one product's representations unnamed. Right on the one multi-level sample
  here, and wrong on a file whose assembly components are entirely unnamed — that level collapses
  into one node, keeping every solid and its placement. From
  `2026-09-13_22h17.the-assembly-arrives-as-an-assembly.completed.md`, which also found that taking XDE at
  face value turns a ten-assembly file into a twenty-eight-assembly one.
- **Eighteen placements of five parts are eighteen bodies with eighteen tessellations.** The seam
  hands over a body per placement and says so deliberately — an instance of a `Body` is not a thing
  the contract has — so nothing is shared between two placements of one part. **Measured on
  2026-09-14**: AS1's eighteen meshes fall into five groups by triangle, vertex and line count and
  weigh 2.49 MiB where one blob per group would be 996 KiB; the large assembly's 211 fall into 83
  and weigh 84 MiB against 39 MiB. Equal counts are evidence of repetition and not proof of it, so
  both are upper bounds on what instancing would buy.
- **An imported subassembly with no solids in it arrives as an empty group.** No sample has one, so
  pruning them would be code with no fixture behind it.
- **`Document::import_step` returns the body nodes and not the groups it made**, so a caller that
  wants to select or frame the assembly it just imported has to walk up with `parent_of`. The app's
  status line counts the bodies and never mentions the groups.
- **Nothing converts a unit.** *Was "No units in a document"; taken in part on 2026-09-14.* A
  document now states what one of its numbers means and a version-2 file carries it, but setting a
  unit **relabels** — it does not scale the geometry, which is a rebuild. Nothing in the interface
  sets one either, so the only way a document is in anything but millimetres is a hand-edited file.
  `export_step` refuses such a document rather than writing a STEP file whose stated unit is a lie,
  which is a guard nobody can currently trip from the interface.
- **No selection in a file.** *Was "No thumbnail, no camera, no selection in a file"; corrected
  2026-09-14 after the code was read.* The camera and a PNG thumbnail have been optional manifest
  fields for some time — `FORMAT.md` said they were not, which was drift in the one document that
  makes this format open, and it now documents both. What is still absent is the selection, and
  what it was waiting for was an identity to write it against, which version 2 has.
- **Zip64 is absent rather than handled.** A document over 4 GiB fails to save, and nothing tests
  that path.
- **`fake-csg-1`'s decoder is recursive over untrusted input.** It is the test kernel and
  `FORMAT.md` says not to implement it, but the bytes are still parsed by a real program.
- **Two documents cannot be merged without renumbering one of them.** *New on 2026-09-14, and the
  cost of how the previous item was taken.* Identities are a counter saved with the document rather
  than random numbers, which is what keeps two saves of one document byte-for-byte identical. There
  is no merge, and the one that gets written will have to renumber a side.
- **`Document::by_uid` is a linear scan.** *New on 2026-09-14.* Identity lookup walks the arena.
  Fine at the few thousand nodes a document is, and the alternative is an index that undo, redo,
  remove and compact would each have to keep right — which is the class of thing that goes wrong
  silently. Unmeasured at any size.
- **A version-1 file's identities are invented in the reader**, so opening the same version-1 file
  twice gives its nodes the same identities as each other and nothing outside that session may rely
  on them. Anything stored against a node id — a selection, a comment, a per-face fillet — means
  nothing across a re-save of such a file.
- **Instancing is not in the file either.** Eighteen placements of five parts are eighteen nodes
  with eighteen blobs, so a `.w3d` of an assembly is as large as the assembly. The seam's decision
  — see the register's note on placements — is now also the format's.
- **A node in a file has no transform.** A body's position is in its geometry, so moving a group
  does not move what is inside it, in memory or on disk.
- **Deleting a group promotes what was inside it** rather than deleting the subtree. A decision
  taken on 2026-09-14 because the alternative takes bodies the user did not select; no user has
  been asked.
- **A surface-only STEP file is refused**, and the first foreign file tried was one. Correct — a
  `Body` is a solid and the contract says so — but a modeller that cannot open a surface model at
  all is a limitation somebody will meet, and it needs a document that can hold something that is
  not a solid before it can be anything else.
- **The samples come from one GitHub repository.** Checksums protect against the files changing,
  not against the repository going away, and `make step-check` then does not run.
- **The device is capped at `downlevel_webgl2_defaults` on every target**, so a desktop with
  gigabytes of VRAM is granted a 256 MiB buffer like the weakest thing in the matrix. Deliberate
  and documented — the weakest target is the one every other must satisfy — but the first import
  large enough to care will meet it, and asking for more on native means handling not getting it.
  From `2026-09-03_01h25.what-the-adapter-will-admit.completed.md`, which fixed the guard that was
  reporting the adapter's number instead of this one.
- **`degradation()` and `software_rendering()` are two methods and the page shows both.** They
  answer different questions and the headless test asserts one invariant per method. A third would
  be the moment to make it a list.
- **No grid, no axes, no view cube.** The viewport is a lit solid in empty space with nothing to
  orient against.
- **npm dependencies are unchecked**, and `tools/licences.py`'s non-cargo list is maintained by
  hand.
- **No `cargo-deny`.** It does this and more — advisories, bans, duplicates — and is the right
  answer once the tree is large enough for advisories to matter.
- **The loader's variant probe is a `HEAD` request**, and it logs a 404 per page load on any
  deployment that runs `make web` without `make web-threaded`. Where both are built it is a 200.
- **Nothing pins the nightly `make web-threaded` needs.** `-Z build-std` and `+atomics` are both
  unstable, so a nightly that changes either breaks the build with no warning. Built once on
  `1.100.0-nightly (5db7f4be8 2026-09-01)`; that is a fact about a run, not a pin.
- **The threaded variant's pool is used by tessellation and nothing else.** Booleans, STEP import,
  the mesh upload and the frame loop are all on the thread that asked.
- **`initThreadPool`'s failure path has never run**, and it covers rejections rather than hangs.
  A timeout would cover both and is not written.
- **`w3d-kernel-fake` is a dependency of `w3d-web` that `w3d-web` no longer uses.**

## Known and deliberately not pending

Not gaps. Each is a decision with a reason, gathered so nobody reopens one as a bug.

- **`set_tolerance` does not re-evaluate existing geometry.** Retrofitting a tolerance is a
  rebuild, and a rebuild is a feature that does not exist. Documented at the call site.
- **`Topology` is counts only.** Face ids and edge loops would be a widening of the trait, and the
  callers that looked like they wanted it did not need it: edges arrived on `Mesh` instead (the old
  item 3), and the golden census of 2026-09-05 reads the mesh rather than the trait — deliberately,
  because a face *count* is not kernel-independent and so is not something the suite may assert.
- **A loaded document has no history.** Saving it would mean saving every intermediate body the
  history holds alive, which is most of what garbage collection exists to discard.
- **A `.w3d` from another kernel is refused, not converted.** The whole design turns on it: a
  native file that silently half-converts is the worst outcome a format can have.
- **`OcctKernel` is neither `Send` nor `Sync`.** Correct rather than conservative: `tessellate`
  mutates through `&self` because OCCT attaches triangulations to the faces it meshes. Parallel
  meshing means one kernel per worker, not a lock.
- **`collect_garbage` rebuilds a `HashSet` per call.** Fine at this size, unmeasured at any other.
- **Nothing is back-face culled.** A solid whose normals are inverted is a defect worth *seeing*;
  culling shows a hole and blames the boolean.
- **`render/` does not know what a document is**, and **`w3d-web` is not the modeller**. Both are
  the seam working, not gaps.
- **`Renderer::pick` blocks and is documented as native-only.** `pick_begin`/`collect` is the
  answer for anything with an event loop.
- **The loader's draw check is a heuristic and is meant to be.** A driver that lies cannot be
  detected by asking it, only by looking at what it produced.
- **Safari's Memory64 status is unresolved.** It blocks nothing, because wasm64 was rejected on
  other grounds. Do not quote a Safari version from these files.
