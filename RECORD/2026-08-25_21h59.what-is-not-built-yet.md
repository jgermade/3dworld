# 2026-08-25 21h59 · What is not built yet

**This file is the plan.** It is the only open file in `RECORD/`, and it supersedes the register
in `2026-08-25_19h22.what-is-not-built-yet.completed.md`, which took over from four `Next` blocks
before it.

It records no work. It exists so the plan is something a reader can read rather than reconstruct,
and it has no `Walkthrough · as built` and will never grow one — work that acts on it opens its
own file and says which items it took.

**It is also the one file in `RECORD/` that is maintained rather than appended.** The
never-rewrite rule protects a *record*, where the wrong turns are most of the value; this is a
*plan*, and a plan that only grows stops being one. Items leave it as they are done and `## Taken`
at the end says which file took each, so the reasoning stays one link away. Every other file in
the folder is append-only.

## Where this repo actually was

Eight crates. 65 native tests, 17 more against OpenCASCADE, 17 checks in a real browser, and a
window that opens.

```
kernel/        w3d-kernel       the seam: 16 methods + the conformance suite    ✅
kernel-fake/   w3d-kernel-fake  the contract without geometry                   ✅
core/          w3d-core         document · history · selection · mesh cache     ✅
format/        w3d-format       the .w3d file, specified in FORMAT.md           ✅
kernel-occt/   w3d-kernel-occt  OpenCASCADE through a 16-entry C ABI            ✅ native
                                                                                ⬜ wasm
render/        w3d-render       wgpu · camera · ID-buffer picking               ✅
web/           w3d-web          loader · probe · COOP/COEP · a canvas           ✅ WebGL2
                                                                                ✅ threaded
app/           w3d-app          editor · scene · winit and egui in one pass     ✅ desktop
kernel-truck/  w3d-kernel-truck pure Rust, and its boolean is not one — item 4  ◐
kernel-native/                  ours, or truck                                  ⬜
```

A person can open a window, add primitives, select them, run a boolean on real OpenCASCADE
geometry, orbit, pan, undo, save and reopen — and export what they made as STEP, or import one,
including files written by Pro/ENGINEER and Siemens NX. **No CAD program has yet opened a file this
one writes**: a parser with no OCCT in it has read one and found the solids in it, which is
evidence about the file and not about the geometry.

The browser runs the same viewport on `TruckKernel`, in either a single-threaded or a threaded
build, and the threaded one meshes a solid's faces across a rayon pool. What it cannot do is model:
truck's boolean returns a copy or a bounding box, so the browser draws exact surfaces with nothing
cut out of them, and there is still no OCCT in wasm. See item 4.

**Not verified, and the risk taken with each.**

- **WebGPU has never rendered a pixel, anywhere.** Native runs are Vulkan through lavapipe, which
  is not WebGPU; the browser's WebGPU reports an adapter and draws nothing. The largest single
  unknown, and the only thing established about it is that a browser can claim it falsely.
- **Nothing about how it *feels*.** Thirty frames under a software rasteriser prove the pipeline
  runs. Latency while dragging is the only thing that matters in a modeller and cannot be measured
  here.
- **One browser, one windowing system.** Chromium and X11 under Xvfb. No Firefox, no Safari, no
  Wayland, no macOS, no HiDPI.
- **A skipped test looks like a passed test.** `w3d-render`'s tests print `SKIPPED:` without an
  adapter and `cargo test` still says `ok`; `make web-test` and `make app-test` are not part of
  `make test` at all.
- **No geometry is verified beyond the contract.** The conformance suite asserts what must be true
  of *any* correct kernel. Five document tests and a drilled plate are seeds, not a fixture suite,
  and not one of them is degenerate — which is exactly where B-rep kernels fail.
- **The suite still encodes what two backends agree on**, one of which does no geometry.
- **No CAD program has read a STEP file this one writes.** A parser that shares no code with OCCT
  now reads one and is held to resolving every reference, finding the solids in the model and
  counting the faces by surface type — but it reads the *file*, not the *model*: nothing in it
  builds a solid or would notice one that is not closed. Fusion, FreeCAD, SolidWorks and Onshape —
  the whole reason STEP was chosen — have still never seen one, and nothing that could is
  installable in the environment these sessions run in.
- **Three foreign files is three.** AP203 and AP214 import; no AP242, nothing in inches, nothing
  from CATIA or SolidWorks, nothing pathological. **The unit conversion has still never run**,
  because all three samples are in millimetres.
- **An import is not compared to anything.** Bodies, faces and triangles are printed, not asserted
  against a golden number: a wrong-but-well-formed import passes.
- **No implementation has been written from `FORMAT.md`**, which is the only test of whether that
  document is sufficient. One writer and one reader from the same head agreeing proves less than
  it looks like. There are also no old files, so forward compatibility is asserted by a test that
  edits a version number rather than by history.
- **Every performance number in this repository is somebody else's.** Nothing has been measured on
  this workload, because there is not yet a workload. The threaded browser build reports a
  tessellation time on the page, and it is 0–2 ms on a scene of twelve triangles: a place to put a
  number, not a number. **Nothing here is evidence that threads made anything faster.**
- **The conformance suite passes a backend whose boolean does nothing.** See item 4. Until it
  fails that, "the suite is what keeps the kernel decision reversible" is a claim with a known
  counter-example in the tree.
- **`f32` mesh positions are absolute.** A document kilometres from the origin has lost precision
  before the camera sees it, and the camera's `f64` cannot recover it.
- **No licence *texts* are collected**, and the fonts egui embeds oblige theirs to be preserved.

## The pending register

Ordered by what blocks what, not by size.

### Blocking a modeller somebody can actually use

1. **A CAD program opening a file this one writes.** The half of the old item 1 that no check
   here can close, and it is now the *only* claim about interchange resting on nothing outside
   this repository. `make step-check` has an independent parser reading the file and finding the
   solids in it; what nobody has is a second *geometry* kernel building them. It needs an
   environment with FreeCAD in it — this one's apt sources have none — or a person, once, with
   Fusion or Onshape open and this file in front of them.
   The other half is done: files from Pro/ENGINEER, Siemens NX and ST-Developer import, and a
   surface model from the wild is refused by name. What is still missing there is **a sample in
   inches** — so the unit conversion has never run — **and one in AP242**, and a golden number to
   compare an import against rather than counting that solids came out.
2. **Assembly structure, product names, and instancing from a STEP file.** `import_step` flattens:
   one body per solid, all named after the file, hierarchy and names discarded. There is now a
   number on it — the AS1 assembly from Pro/ENGINEER holds **five** distinct solids and imports as
   **eighteen bodies**, because five parts are placed eighteen times and nothing in the document
   can say so. A user gets eighteen unrelated bodies with the same name and a number.
   `STEPCAFControl_Reader` and XDE read the structure — another toolkit set, and a mapping onto a
   node graph that has no hierarchy to map onto, so it is the natural moment to give the document
   one. Colours and materials arrive by the same road.
3. **Edges in the kernel contract.** A B-rep modeller is largely judged on its edge display, and
   `Mesh` carries no edge data at all. Every screenshot so far is a lit solid with no edges, which
   is not what a modeller looks like. Declare it on the trait first, then implement, then use.
4. **`truck`'s boolean is not a boolean, and the conformance suite passes it.**
   `TruckKernel::boolean` returns a copy of its first operand for `Difference`, and an
   axis-aligned bounding box of the operands for `Union` and `Intersection`. The scene the browser
   has drawn since 2026-08-27 is therefore a plate with no hole in it, and every solid on that page
   came from `create_box` or `create_cylinder` rather than from modelling.
   **The finding about the suite is the bigger half.** A `boolean` that ignores its second operand
   satisfies `conformance` today, which is what item 12 predicted a second backend would expose —
   arriving from the second backend itself. Whatever is added to the suite has to be true of any
   correct kernel and has to fail this: a volume, a face count that could not come from either
   operand alone, a point inside one operand and outside the result.
   Fixing the backend is separate and is not small: `truck-modeling` 0.6 has no boolean, so it is
   `truck-shapeops` at best. Found while building a test fixture — see
   `2026-09-03_00h45.the-threaded-variant-exists.completed.md`.
5. **WebGPU on hardware that works.** See `Verified, and not`. Until then the fast path is an
   argument, and so is every performance claim resting on compute shaders.

### Blocking the wasm target

6. **An OCCT build for Emscripten.** `kernel-occt` is excluded from `make wasm`, so the browser
   has no exact kernel in it. It is no longer a `FakeKernel` bounding box — `TruckKernel` has
   tessellated the browser's scene since 2026-08-27 — but item 4 above is what that is worth: real
   surfaces, and no boolean under them. The toolkit list in `build.rs`
   is the input. Two things must be *decided* rather than discovered: `-fwasm-exceptions` against
   `-fexceptions`, which has real size and speed consequences; and a real upstream pin —
   `native/UPSTREAM` names a version, it does not enforce one. **STEP made this bigger**: five more
   toolkits are in the link now — `TKXSBase`, `TKSTEPBase`, `TKSTEPAttr`, `TKSTEP209`, `TKSTEP` —
   and the last is wanted by nothing here and will not link without the one before it.
7. **The tessellation format across the worker boundary.** Hand-waved as "transferable
   `ArrayBuffer`" in the first session and never designed. It has a fixed point at the GPU end now
   — 28-byte interleaved vertices, de-indexed when face ids demand it — so there is something to
   design against.

### Owed, but not blocking

8. **A GPU in CI.** The browser half is done and so is CI itself — `make test`, OCCT, step-check,
   the window under Xvfb and FreeCAD on every push, the browser nightly — so a green run is now
   evidence of something. It is still not evidence about a **driver**: the window job draws on
   lavapipe and the browser job on headless Chromium's software path, and WebGPU has never
   rendered a pixel anywhere. A GitHub runner has no GPU, so this needs a self-hosted runner with
   one, or a person, a machine and a screenshot.
   Both jobs now *say* so rather than leaving it to be inferred: since
   `2026-09-03_01h25.what-the-adapter-will-admit.completed.md` the report names what is behind the
   adapter, and every run of it anywhere has said `software (CPU rasteriser)`. The `Hardware`
   branch has never been taken.
9. **A NOTICE file for a distribution — a requirement, not good manners.** `make licences` proves
   every crate is *compatible*; it collects no licence text. The fonts egui embeds are OFL-1.1 and
   Ubuntu-font-1.0 and **both oblige their notices to be preserved**; MIT and Apache-2.0 want the
   same, and GPL-3 §6 wants the corresponding source. Serving a `.wasm` or shipping a binary is
   distribution.
10. **`wasm-opt`, brotli, and a real payload number.** `make web` reports 3.34 MiB of wasm and 1.12
   MiB gzipped. Both are upper bounds and lazy ones, and OCCT will dwarf them.
11. **Fixture regression with degenerate input** — coincident faces, tangent surfaces, thin walls.
    Where B-rep kernels actually fail, and where OCCT is known to. Still untouched.
12. **truck as the second backend.** The only thing that can say whether the conformance suite is
    right, because it shares no code with either existing backend. Every failure it produces is a
    question about the suite first.
13. **`BRepBuilderAPI_GTransform` has never been exercised.** The non-uniform-transform fallback
    has no test, because nothing in the suite scales non-uniformly. Most likely thing in the shim
    to be wrong.
14. **Fillets.** `TKFillet` is present. The feature Plasticity is actually good at, so also the
    first honest measurement of the gap.
15. **Transactions are not user-grouped.** One edit is one undo step, so a drag that transforms
    twenty nodes would be twenty steps. `History::begin`/`commit` already take a label, and a STEP
    import is now one transaction for any number of solids — which is a precedent for the shape of
    the fix, not the fix.
16. **Arena compaction.** Slots are never reused, so an arena grows with every node a session ever
    created. Safe only with history cleared, and it renumbers every id. A free list is **not** the
    fix — see the rule in `AGENTS.md` and the bug that produced it.
17. **Measure something.** The 4 GB sharding argument is still an argument. A tessellated body of
    known size through the worker boundary turns it into a number — and there is now a candidate
    workload that costs nothing to obtain: the 15 MB assembly beside the samples
    `make step-samples` already fetches. It is also the first honest number about a synchronous
    import stalling the frame.
18. **The project's name.** `3dworld` is a directory. Crates are `w3d-` because `3dworld` is not a
    valid Rust identifier. Costs nothing now, costs a rename later.

### Small, and easy to lose

- **`Live::resize` is wired and untested.** It reconfigures the surface, the depth texture and the
  capture target, and nothing exercises any of it. The most likely thing in the shell to be wrong.
- **The pick path is asserted at both ends and not in the middle**, where the shell holds a
  `PickPending` across frames.
- **Saving and exporting are synchronous and on the frame.** A large document will stall the
  window, and a STEP export stalls it for longer than a save: it rebuilds the model into another
  representation rather than writing bytes it already has.
- **`Save` with no path writes `untitled.w3d` in the working directory**, because there is no file
  dialogue and adding one is a dependency. The same gap is why there is no *Import STEP* button —
  export can invent a name beside the document and import needs one that exists — and why
  `--import-step` is a command-line option. Everything about files in this program is waiting on
  this one dependency.
- **An import only reframes the camera when the document was empty.** Importing into a populated
  document can leave the new bodies off screen, which looks exactly like an import that did
  nothing.
- **An exported STEP file is not byte-deterministic.** `FILE_NAME` carries a timestamp, so two
  exports of the same body differ. Worth knowing before somebody writes a golden-file test.
- **Face ids do not survive a STEP round-trip.** Faces come back renumbered, so a document that
  exports and re-imports loses every per-face selection. That is STEP rather than a defect, and it
  is the second place face identity has come up — the first is item 3.
- **No units in a document.** `tolerance` implies a scale and nothing states one. A version-2
  conversation for `FORMAT.md`.
- **No thumbnail, no camera, no selection in a file.** The first every file browser wants; the
  other two are what "reopen where I left off" needs.
- **Zip64 is absent rather than handled.** A document over 4 GiB fails to save, and nothing tests
  that path.
- **`fake-csg-1`'s decoder is recursive over untrusted input.** It is the test kernel and
  `FORMAT.md` says not to implement it, but the bytes are still parsed by a real program.
- **Nodes have no stable id across a save.** Names are the only identity in a file, so nothing
  that wants to refer to a body between sessions has anything to hold.
- **A surface-only STEP file is refused**, and the first foreign file tried was one. Correct — a
  `Body` is a solid and the contract says so — but a modeller that cannot open a surface model at
  all is a limitation somebody will meet, and it needs a document that can hold something that is
  not a solid before it can be anything else.
- **The samples come from one GitHub repository.** Checksums protect against the files changing,
  not against the repository going away, and `make step-check` then does not run.
- **The device is capped at `downlevel_webgl2_defaults` on every target**, so a desktop with
  gigabytes of VRAM is granted a 256 MiB buffer like the weakest thing in the matrix. Deliberate
  and documented — the weakest target is the one every other must satisfy — but the first import
  large enough to care will meet it, and asking for more on native means handling not getting it.
  From `2026-09-03_01h25.what-the-adapter-will-admit.completed.md`, which fixed the guard that was
  reporting the adapter's number instead of this one.
- **`degradation()` and `software_rendering()` are two methods and the page shows both.** They
  answer different questions and the headless test asserts one invariant per method. A third would
  be the moment to make it a list.
- **No grid, no axes, no view cube.** The viewport is a lit solid in empty space with nothing to
  orient against.
- **npm dependencies are unchecked**, and `tools/licences.py`'s non-cargo list is maintained by
  hand.
- **No `cargo-deny`.** It does this and more — advisories, bans, duplicates — and is the right
  answer once the tree is large enough for advisories to matter.
- **The loader's variant probe is a `HEAD` request**, and it logs a 404 per page load on any
  deployment that runs `make web` without `make web-threaded`. Where both are built it is a 200.
- **`make web-test` fails two checks, and has since before the threaded variant.** "The canvas is
  not blank" reports 5 distinct colours against a threshold of 8, in the WebGPU and the WebGL2
  runs. Verified against a tree built from `main`: same checks, same count. Plausibly item 4 —
  a box has fewer distinct shades than a drilled plate — but that is a guess and the threshold
  must not be lowered to find out.
- **Nothing pins the nightly `make web-threaded` needs.** `-Z build-std` and `+atomics` are both
  unstable, so a nightly that changes either breaks the build with no warning. Built once on
  `1.100.0-nightly (5db7f4be8 2026-09-01)`; that is a fact about a run, not a pin.
- **The threaded variant's pool is used by tessellation and nothing else.** Booleans, STEP import,
  the mesh upload and the frame loop are all on the thread that asked.
- **`initThreadPool`'s failure path has never run**, and it covers rejections rather than hangs.
  A timeout would cover both and is not written.
- **`w3d-kernel-fake` is a dependency of `w3d-web` that `w3d-web` no longer uses.**

## Known and deliberately not pending

Not gaps. Each is a decision with a reason, gathered so nobody reopens one as a bug.

- **`set_tolerance` does not re-evaluate existing geometry.** Retrofitting a tolerance is a
  rebuild, and a rebuild is a feature that does not exist. Documented at the call site.
- **`Topology` is counts only.** Face ids and edge loops are a widening of the trait; that is item
  3 and happens when there is a caller, not before.
- **A loaded document has no history.** Saving it would mean saving every intermediate body the
  history holds alive, which is most of what garbage collection exists to discard.
- **A `.w3d` from another kernel is refused, not converted.** The whole design turns on it: a
  native file that silently half-converts is the worst outcome a format can have.
- **`OcctKernel` is neither `Send` nor `Sync`.** Correct rather than conservative: `tessellate`
  mutates through `&self` because OCCT attaches triangulations to the faces it meshes. Parallel
  meshing means one kernel per worker, not a lock.
- **`collect_garbage` rebuilds a `HashSet` per call.** Fine at this size, unmeasured at any other.
- **Nothing is back-face culled.** A solid whose normals are inverted is a defect worth *seeing*;
  culling shows a hole and blames the boolean.
- **`render/` does not know what a document is**, and **`w3d-web` is not the modeller**. Both are
  the seam working, not gaps.
- **`Renderer::pick` blocks and is documented as native-only.** `pick_begin`/`collect` is the
  answer for anything with an event loop.
- **The loader's draw check is a heuristic and is meant to be.** A driver that lies cannot be
  detected by asking it, only by looking at what it produced.
- **Safari's Memory64 status is unresolved.** It blocks nothing, because wasm64 was rejected on
  other grounds. Do not quote a Safari version from these files.
