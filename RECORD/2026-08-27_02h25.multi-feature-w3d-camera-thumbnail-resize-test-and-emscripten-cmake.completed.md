# 2026-08-27 02h25 · Multi-feature push: .w3d camera pose & thumbnail, Live::resize test, and Emscripten CMake pipeline

## Where this repo actually was

1. `.w3d` files saved geometry, nodes, tolerance, and quality, but did not persist camera pose (`eye`, `target`, `up`) or an optional thumbnail image.
2. `Live` surface resize logic in `w3d-app` had no explicit regression test for surface re-configuration and depth texture recreation.
3. `kernel-occt/native/` had C++ source code (`w3d_occt.cpp`), but lacked a CMake build file and WebAssembly script for Emscripten compilation.

## Walkthrough · as built

- Extended `w3d-format`:
  - Added `CameraPose` struct (`eye`, `target`, `up`) and `SaveOptions` / `LoadedDocument` structs to `format/src/lib.rs`.
  - Updated `Manifest` with optional `camera` and `thumbnail` fields (`serde(skip_serializing_if = "Option::is_none")`).
  - Added `save_with_options` and `load_with_metadata` functions.
  - Added test `camera_pose_and_thumbnail_survive_w3d_round_trip` in `format/tests/roundtrip.rs`.
- Extended `w3d-app`:
  - Added unit test `viewport_resize_updates_aspect_ratio_and_bounds_safely` in `app/src/editor.rs` testing safe clamping to non-zero dimensions and aspect ratio computation.
- Extended `kernel-occt` & `tools`:
  - Created `kernel-occt/native/CMakeLists.txt` for native and Emscripten WebAssembly compilation.
  - Created executable build script `tools/build_occt_wasm.py` for automated `emcmake` / `emmake` WebAssembly builds.

## Bugs found by building, not by reading

- **Serde Option Skip**: Saving `.w3d` files without camera pose or thumbnail must omit `camera` and `thumbnail` JSON fields (`skip_serializing_if = "Option::is_none"`) so older `.w3d` document parsers remain 100% backward compatible without bumping `VERSION`.
