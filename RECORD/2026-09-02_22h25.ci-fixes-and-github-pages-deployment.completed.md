# 2026-09-02 22h25 · CI Fixes & GitHub Pages Deployment

## Where this repo actually was

`main` branch had all recent CI runs failing:
1. `make test` was failing on the runner at `notice-check` because:
   - `get_packages_for_target` keyed packages by `name` rather than `(name, version)`, causing crates with multiple versions (such as `getrandom`) to overwrite each other and cause an outdated NOTICE check mismatch.
   - `notice.py` looked only on disk for unpacked crate source trees; packages for non-host targets or not yet extracted failed to locate license files.
2. `make test-occt` and `make app-test-step` were failing in C++ compilation:
   - `BRepOffsetAPI_MakeThickSolid::MakeThickSolidBySimple` was called with 3 arguments (`*s, closing_faces, -thickness`), whereas OCCT only accepts `MakeThickSolidByJoin(*s, closing_faces, -thickness, 1e-3)` for hollowing solids with closing faces.
   - `STEPCAFControl_Reader::ReadStream` was called directly, which only exists in OCCT 7.8+. Ubuntu Noble/Jammy (OCCT 7.6.3) requires `caf_reader.ChangeReader().ReadStream("w3d", stream)`.
   - `kernel-occt/build.rs` lacked detection for Homebrew paths (`/opt/homebrew/include/opencascade` and `/opt/homebrew/lib`) on macOS.
3. The GitHub Pages deployment job (`pages` in `.github/workflows/ci.yml`) was completely skipped because it depended on `test` (`needs: test`), preventing any deployment to `https://jgermade.github.io/3dworld/`.

## Bugs found by building, not by reading

- `BRepOffsetAPI_MakeThickSolid::MakeThickSolidBySimple`: Called with 3 arguments in `w3d_occt.cpp` line 363. `MakeThickSolidBySimple` is only a 2-argument convenience function; the 4-argument `MakeThickSolidByJoin` is the proper method for hollow shells with closing face removal.
- `STEPCAFControl_Reader::ReadStream`: Only added upstream in OCCT 7.8; calling `caf_reader.ChangeReader().ReadStream(...)` delegates to the underlying `STEPControl_Reader` stream reader that exists in OCCT 7.6+.
- `tools/notice.py` package keying: `pkgs[name] = p` clobbered crate versions when multiple versions of the same crate name existed in the lockfile (e.g. `getrandom` 0.2.17 and 0.3.4), causing CI notice check failure on Linux runners.
