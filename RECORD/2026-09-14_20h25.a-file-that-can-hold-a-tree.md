# 2026-09-14 20h25 · A file that can hold a tree

Takes **item 10** of the register — *An assembly that survives being saved* — and with it the two
small items it was tied to: *Nodes have no stable id across a save* and *No units in a document*.
They arrived together because they are one conversation and the register said so: a document cannot
carry a tree without an identity for a parent to name, and a version number is expensive enough
that spending one on a tree while leaving the unit for the next is spending it twice.

The `.w3d` is **version 2**.

## Where this repo actually was

Since 2026-09-13 an imported STEP assembly *is* a tree of group nodes in the document: `Document::
import_step` builds it, `reparent` refuses a cycle, the Outliner draws depth. None of it survived
`Ctrl-S`. A version-1 manifest had a flat `nodes[]`, every entry required a `geometry` path, and
nothing in a file could refer to anything else in it — so `format::save` skipped groups outright and
the parts came back flat. `a_group_does_not_survive_a_save` pinned exactly that, so that changing it
would be a deliberate act with a version number attached. This is that act.

Three other things were true and are worth writing down because they shaped the work:

- **`Document::remove` did not take the node out of the tree.** It removed the arena slot and
  recorded the undo, and left the parent's `children` holding a dead id and the node's own children
  holding a `parent` that named a slot which is no longer there.
- **`Document::boolean` did the same, twice**, for both operands, and put the result at the root
  whatever the operands were inside.
- **`camera` and `thumbnail` had been optional manifest fields for some time and `FORMAT.md` said
  they were "deliberately not in a version-1 file".** The specification is the thing that makes the
  format open, so that is a documentation defect rather than a small one.

## Walkthrough · as built

**`Uid`, and where identities come from.** A `u64` counter on the document, handed out by
`Document::place` — which every path that puts a node in the arena now goes through, so "every node
in a document has an identity" is a property rather than a hope. A node that arrives *with* one
keeps it: that is a file being loaded, and the identities in a file are the file's. The counter is
saved in the manifest as `next_uid` and **never rewinds**, not even when an undo takes the node that
spent it — an identity handed out once may already be written down where this program cannot see it.
`Uid::UNASSIGNED` is `0`, which is what `Node::new` produces and what a file may not contain.

**`Unit`, and what it does not do.** `mm`, `cm`, `m`, `in`, `ft`, with a symbol that is written
into files and a `millimetres()` factor that is exact for the imperial pair because the inch *is*
25.4 mm by definition. A new document is millimetres, which is what this program already assumed
everywhere it had to choose. **Nothing converts**: setting a unit relabels the numbers, because
scaling the geometry is a rebuild. What the field buys is that the file says what it means — and
that `Document::export_step` now **refuses** a document stating anything but millimetres, rather
than writing a STEP file whose `SI_UNIT` is a lie. A document that states *nothing* still exports:
that is every version-1 file, and millimetres is the assumption the program has always made.

**`Loaded` / `LoadedNode`, and the one rule.** The counterpart of the kernel seam's `Import`, one
level up: something arrived from outside claiming to be a tree, and `Loaded::validate` is the whole
of what may be assumed about it — every node has an identity, no two share one, **a parent appears
earlier in the list than its children**, and the counter is ahead of every identity present. The
third is the same trick `Import::validate` uses and for the same reason: a cycle becomes
unrepresentable rather than detectable, so `Document::from_loaded` builds the tree in one pass with
no visited set and no recursion. It is checked before the arena is touched, so a refused file leaves
nothing half-built. It lives in `core/` rather than in the reader because the *document* is what
must not be built broken, and there it is testable with no zip and no JSON anywhere near it.

**`Document::depth_first`.** Parents before children, siblings in their own order, depth beside each
node — the order a file must be written in and the order an outliner draws. **Iterative**, because
the depth of this tree is the depth of whatever file was opened and a recursive walk over an
untrusted file is a stack overflow waiting for a deep assembly. `Editor::outline_rows` is now this
walk plus the row-building that a panel owns, instead of a second recursive copy of it.

**The writer.** Walks `depth_first`, writes *every* node including groups, and puts `uid`,
`parent` and an *optional* `geometry` on each entry. Before anything else it asserts that the walk
reached every node: a document whose nodes cannot all be reached from its roots is not a tree, and
writing the ones that can be reached would drop the rest silently.

**The reader.** The version selects the shape. Version 2 requires `uid` and `next_uid`, allows
`parent`, allows an entry with no geometry — that is a group — and allows `unit`, refusing a symbol
it does not know rather than falling back to unitless. Version 1 is read as *what it is*: fresh
identities invented on the way in, every node a root, and a document that states **no unit**,
because claiming millimetres on a version-1 file's behalf is a guess with somebody's dimensions
attached. An entry with no geometry in a version-1 file is damage, not a group: version 1 had no
groups in it to be.

**No downgrade.** A version-2 writer does not write version 1. A file whose tree was silently
dropped to fit an older reader is the half-conversion this format refuses everywhere else.

**`FORMAT.md` is version 2**, including the four identity rules stated as rules a reader must
enforce, and `camera` and `thumbnail` documented where they had been claimed absent.

**The status line counts what it says.** Opening now reports bodies and groups separately — "18
bodies in 10 groups · mm" — because "28 bodies" for eighteen parts in ten assemblies is a number a
user cannot check against anything, and because a document that states no unit is worth seeing
rather than assuming.

## Bugs found by building, not by reading

- **A deleted node left the tree holding its slot.** `Document::remove` removed the arena entry and
  nothing else, so deleting a group left its children with a `parent` naming a slot that is no
  longer there — unreachable from the roots, and therefore invisible to the Outliner while still
  drawn in the viewport. It had been a display fault since groups existed; a file with a tree in it
  turns it into **data loss**, because a node a walk cannot reach is a node a save would drop.
  `detach` now takes a node out of the tree before it leaves the arena, promoting whatever was
  inside it into its place, all inside the same undo step. Promotion rather than deleting the
  subtree: a delete that takes bodies the user did not select with it is the worse of the two
  surprises.
- **A boolean did the same to both operands**, and put its result at the document's root. Two parts
  of an assembly differenced left the group listing two dead ids and the result outside it. The
  result now takes the first operand's place.
- **`Loaded::validate` let a node be its own parent.** The first draft put each identity into the
  seen-set before looking for its parent, so a one-node cycle — `parent` equal to `uid` — passed the
  "earlier in the list" test. Caught by the negative control written for it, which is the argument
  for writing the negative controls.
- **`FORMAT.md` said `camera` and `thumbnail` were not in a version-1 file** while the writer had
  been writing both. The specification is what makes the format open; drift there is worse than
  drift in a comment.
- **The first draft of the AS1 example compared bodies by position and asserted their bounds
  exactly.** Both were wrong for reasons worth keeping: the two documents list their nodes in
  different arena orders — the imported one has its groups first, the reopened one is in file order
  — so a comparison keyed by identity had to be *sorted* by it; and exact bounds fail on a BREP
  round trip by 1e-13 mm. The second of those is in `Verified, and not` as a finding rather than a
  fix.
- **Two format tests were pinning version 1.** `a_group_does_not_survive_a_save` is the limitation
  this work removes, and is replaced by its opposite; `a_future_version_is_refused_with_both
  _numbers` was searching the manifest for the literal `"version": 1` and would have silently
  stopped testing anything the moment the number moved. It reads `w3d_format::VERSION` now.

## Verified, and not

**Verified.**

- `make test` — check, clippy `-D warnings`, `fmt`, licences, the NOTICE check and every test —
  `make wasm`, `make test-occt`, `make step-check`, `make app-test` and `make app-test-step` all
  pass, on rustc 1.98.1 and OCCT 7.6.3 from Ubuntu Noble. Core is 30 tests (was 22), the format's
  round-trip 15 (was 10).
- **The headline claim, on the file the register cares about.** `make step-check` now takes the AS1
  assembly — eighteen bodies in ten assemblies, three levels deep, real OpenCASCADE solids — into a
  document, writes a 97 KiB `.w3d`, opens it **with a second kernel**, and asserts the tree, the
  depths, which nodes are groups, every identity, and each solid's bounds. The new example is
  `kernel-occt/examples/assembly_file.rs`; run against the wrong sample it fails, which is how it
  was checked for saying yes for a living.
- **The tree survives a file** at fixture scale too: an Engine / Cylinder / Piston assembly with a
  loose body beside it comes back with the same names, depths, groups and visibilities, the parent
  link asserted both ways, and **saving what was loaded produces the same bytes**.
- **Identity survives**: the same uids come back, the counter comes back ahead of them, and a node
  created *after* a load gets neither a live node's identity nor one spent by a node deleted before
  the save.
- **A version-1 file still opens**, written out by hand in the test because the writer that produced
  it no longer exists — flat, unitless, with identities invented on the way in. And a version-1
  entry with no geometry is refused as damage.
- **Six negative controls on the way in**, each asserted to fail *as itself* and each against a
  fixture asserted to load unaltered: a parent that is not there, a parent later in the list than
  its child, two nodes sharing an identity, a counter behind an identity in the file, a version-2
  node with no identity, and a unit nobody knows.
- **The document's own rules**, against the fake kernel: undo and redo put a node back under the
  same identity, the counter does not rewind, `depth_first` reaches every node, deleting a group
  promotes what was inside it and undo restores the shape, and a boolean inside a group leaves its
  result there.
- **With real geometry**: `kernel-occt/tests/format.rs` saves a document with a group in it, asserts
  that exactly one blob was written for two nodes, and opens it to find the part under its assembly
  with the bounds it had.
- **At the level a user meets it**: an assembly saved from the editor and opened in another editor
  draws the same Outliner rows, and the status line says "1 body in 1 group · mm".

**Not verified, and the risk taken.**

- **A `.w3d`'s blobs are not byte-stable across a reopen, and that is OpenCASCADE rather than this
  format.** Found by writing the AS1 file twice: every `geometry/*.bin` differs in exactly one
  character — the shape-flags line goes from `0111000` to `0101000` — because a shape this session
  built carries OCCT's `Checked` flag and the same shape read back from BREP does not. The geometry
  is identical; the bytes are not. So "two saves produce identical bytes" holds for **one document**
  — which is what `FORMAT.md` claims and what the test holds it to — and **not** across a save,
  reopen and save. A content-addressed store would see two files for one document. The example
  asserts the manifest is identical across that cycle, which is the half this format owns, and says
  so where it does not.
- **A body's bounds move across a BREP round trip**, by at most 1.1e-13 mm on a part 1524 mm across
  on this file. BREP is text and a double comes back as the nearest double to the digits written.
  The example compares to 1e-9 and prints the number it actually saw, rather than asserting equality
  and being surprised later; the document's own linear tolerance is 1e-7, four orders above it.
- **The unit is stated and nothing acts on it** beyond the STEP refusal. Nothing scales, nothing in
  the UI sets it, and a document in inches is a document whose viewport, tolerance and quality
  numbers mean inches to a program that has never thought about it.
- **The STEP refusal is a guard nobody can currently trip from the interface**, because there is no
  way to set a unit except by hand-editing a file. It is tested against the fake kernel, which
  refuses STEP for its own reasons — so what the test proves is that the refusal happens *before*
  the kernel is asked, not that OCCT would otherwise have written the file.
- **`next_uid` makes two documents unmergeable without renumbering.** There is no merge, and the one
  that gets written will have to renumber a side; a random identity would not have had this problem
  and would have cost the byte-for-byte property instead.
- **Nothing has measured what a large `.w3d` costs.** AS1 is 97 KiB for eighteen solids, written and
  read synchronously on the thread that asked, and nothing timed it. The 15 MB sample beside it is
  still unopened here, and it is register item 9 either way.
- **The promotion rule on delete is a decision, not a finding.** Deleting a group promotes its
  children; no user has been asked whether they expected the subtree to go with it.
- **`make freecad-check` and `make web-test` did not run** — no FreeCAD in this container and the
  browser suite is the nightly. Neither touches this change: one is about another program's STEP
  import, the other about the viewport.

## Loose ends, deliberately left

- **Instancing is still not in the file.** Eighteen placements of five parts are eighteen nodes with
  eighteen blobs, so a `.w3d` of an assembly is as large as the assembly. The tree says how bodies
  are arranged, not that two of them are the same part; two nodes sharing one blob is the only thing
  in the format that says "the same geometry", and it says nothing about intent.
- **A node still has no transform.** A body's position is in its geometry, so an assembly cannot be
  moved by moving the group.
- **The selection is still not in a file.** Identity is what it was waiting for and it now exists,
  so this is a small piece of work rather than a blocked one.
- **Nothing sets a unit but a file.** An editor command, a menu, and the question of what should
  happen to the camera when it changes.
- **`Document::by_uid` is linear.** A document is a few thousand nodes and an index is another thing
  undo would have to keep right.
- **A version-1 file's identities are invented in the reader**, so opening the same version-1 file
  twice gives its nodes the same identities as each other and nothing outside that file's session
  may rely on them.
