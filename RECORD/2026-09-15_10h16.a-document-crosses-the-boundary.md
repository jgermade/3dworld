# 2026-09-15 10h16 · A document crosses the boundary

Takes register item 4 — the worker building the page's fixed scene rather than being sent one —
and closes it. Opened against three asks; **one of them is not done and is not attempted**, which
is said here rather than left to be discovered: OCCT for Emscripten (item 3) and the mesh in the
geometry blob (item 9). Why is under `Loose ends`.

## Where this repo actually was

The worker had been the boot path since 08h38 that morning: `start` opens a device and returns a
viewer with no bodies, and the mesh arrives as `WIRE.md` chunks. It could only be a boot path
because the page's scene is *fixed* and both sides can construct it — the worker built its own
document. The register said what that left: "The moment a user opens a file that stops being true,
and there is no format for a document across this boundary — only for a mesh."

It also said what doing it would need: "a second format across the same boundary". That turned out
to be wrong, and usefully so.

## Walkthrough · as built

**There is no second format.** A document crosses as a **`.w3d`** — the format `FORMAT.md` already
specifies and `format/` already implements. Three things made that work rather than merely sound
tidy: `w3d-format` depends on `serde` and `serde_json` and nothing else, its zip being its own
(`format/src/zip.rs`), so it builds for `wasm32` without a single substitution; `TruckKernel`
already implements `save_body`/`load_body`, writing the solid as JSON with **no mesh in it**, so
the worker really re-tessellates rather than unpacking a picture; and `FORMAT.md`'s rules — the
manifest names the writing kernel, a mismatch is refused rather than converted — come free and are
exactly the rules you would have to invent.

A document crossing a worker boundary and a document crossing a disk are the same problem. The
second format was not needed because the first one was already general.

**The asymmetry is the interesting part, and it is deliberate.** Bytes *in* are a model; bytes
*out* are triangles. `WIRE.md` describes a mesh and cannot describe a solid; `FORMAT.md` describes
a solid and says nothing about how to draw one. Sending a `.w3d` back would mean the worker had
done no work.

**`tessellateDocument(bytes, chunksPerBody)`** beside `tessellateScene`, sharing one
`tessellate_into_chunks` so the two cannot drift into encoding differently — which would make the
comparison the browser test draws between them meaningless.

**`make web-scene`**, and `make web` depends on it. `format/examples/scene_w3d.rs` builds the
scene, does the boolean *once at build time*, writes `web/scene.w3d`, and then **reads it back with
a kernel that never saw the geometry and meshes it** — the discipline `make step-check` uses at the
other end of this repository, because a writer that cannot demonstrate a reader is a writer nobody
has checked. It refuses to write a file whose boolean declined, since a scene file quietly
containing an uncut plate is how the browser spent nine days drawing one. The file is **gitignored**:
a generated artifact in the tree is one that can be older than its generator and still look
authoritative.

**The page fetches it and never opens it.** `loader.js` does `fetch('./scene.w3d')` and hands the
`ArrayBuffer` to the worker in the transfer list. This thread does not parse it, does not build a
`Document` from it, and does not know what is in it. That is the shape of a modeller's boot path.
The fetch is started before the worker is constructed so it overlaps with the worker loading its
own wasm.

**`report().source`** — `document` or `built-in scene` — kept separate from `meshedBy` on purpose.
They are independent questions, and the mixed cases are the interesting ones: a document meshed on
the main thread because the worker would not start is a different failure from the built-in scene
meshed in a worker because the document was missing, and **both draw a plate with a hole in it**.

**`modelled` becomes a tri-state.** The document path reports `null`, not `false`, and the
difference is the point: "the cut did not happen" and "nobody here watched it happen" are different
sentences. A solid does not record whether a boolean made it. The generator refusing to emit an
uncut scene is a guarantee about the *file*, not a check the page ran, and reporting `true` would
be the page vouching for something it never saw. The claim that the browser's own boolean still
works has moved to the reference tessellation, which is now **the only check anywhere that the
boolean works in wasm** — so that run earns its keep twice.

**The thread being free is measured, not asserted.** The page counts frame callbacks during boot
and reports the **longest gap between two of them**. That is a direct measurement of "was this
thread blocked": a thread meshing synchronously produces one enormous gap the length of the mesh; a
free one produces gaps of a frame. It needs no baseline from another build, because the suite
already carries the blocked case as a control — `?worker=fail` meshes on this thread, which is the
old boot path exactly.

**Two more controls, both of which assert.** `?doc=off` points the loader at a document that is not
there, which is the state of a deployment where `make web-scene` has not run: the worker must fall
back to the compiled-in scene and the page must say so. It also *compensates* for the branch above,
because that path does run the boolean here and can answer what the document path cannot.

## The numbers, measured in a browser

Headless Chromium on a CPU rasteriser, one scene, one machine. Facts, not targets.

| | |
| --- | ---: |
| Opening the `.w3d` in the worker | **5 ms** |
| What it replaced — the boolean, on every boot | ~500 ms |
| Meshing, in the worker | 624 ms |
| Encoding 4 chunks | 2 ms |
| `.w3d` on the wire, one body | 22 958 bytes |
| Mesh coming back | 183 028 bytes |

And the thread that draws, during boot:

| Run | Frames | Longest stall |
| --- | ---: | ---: |
| Worker, document | 40 | **135 ms** |
| Worker, no document | 64 | 159 ms |
| **Worker refused to load — the control** | 5 | **2063 ms**, over 2146 ms of boot |

## Bugs found by building, not by reading

- **The same boolean does not give the same solid on wasm32 and x86-64.** The document's hole was
  cut natively and meshes to **6294** triangles; the compiled-in scene's hole is cut in wasm32 and
  meshes to **6290**. The four triangles are not the tessellator: this same document meshes to 6294
  natively *and* to 6294 in the browser, so tessellation of identical input agrees across the two
  architectures and it is the boolean's output that differs. `truck-shapeops` divides an
  intersection curve into a polyline at a sag tolerance, so a float difference of an ulp plausibly
  changes a segment count — but *plausibly* is as far as this goes, and nothing here has looked.
  It is the hazard `AGENTS.md` legislates against for relaxed SIMD — "one document would produce
  different topology on different hardware and the regression fixtures would stop meaning
  nothing" — arriving through a door that rule does not cover. It takes item 4's number.
- **A stall cannot be measured from the near side of it.** The first version of the frame-callback
  loop reported a longest stall of **24 ms** on the run that was in fact blocked for most of a
  second, because measuring a gap needs a callback on the *far* side of it and a thread that meshes
  right up to the end of boot never gets one. Fixed by closing the last interval against the moment
  boot returned. Without that line the measurement would have agreed with whoever wrote it, on
  every run, forever.
- **Clearing a flag does not cancel the frame already queued.** One last spinner callback fired
  after boot finished and overwrote the status bar, so three checks that read the status found
  "meshing in a worker…" on a page that had long since finished. The guard has to be at the top of
  the callback, not at the bottom.
- **`source` was plumbed into `installWire` and not into the loader's own call**, which failed
  closed — `installWire: source must be a string` — rather than defaulting to something plausible.
  That is the strictness added at 08h38 doing its job on its author a few hours later.

## Verified, and not

**Verified.** Seven browser runs, plus the native suite.

| What | How |
| --- | --- |
| A document crossed into the worker | `source` is `document` on the boot path; 22 958 bytes in, one body back |
| It is a `.w3d` and not a new format | `w3d_format::load` in the worker; `format/` unchanged |
| The worker really re-tessellates it | `TruckKernel::save_body` writes the solid as JSON with no mesh; 183 028 bytes of triangles come back |
| Opening beats re-modelling | 5 ms against the ~500 ms boolean it replaced; asserted as an order of magnitude, not a number |
| The page never opens the document | It fetches an `ArrayBuffer` and transfers it; nothing on this thread parses it |
| The thread that draws is free | 135 ms longest stall, against **2063 ms** on the control that meshes here |
| The fallback branches both assert | No document → compiled-in scene, said out loud; no worker → meshed here, said out loud |
| The wasm boolean still works | The reference tessellation, which is now the only check that says so |
| The generator checks itself | Writes, re-reads with a fresh kernel, meshes, and refuses a declined boolean |
| Nothing else regressed | `make test` green in full; `make wasm`; all seven browser runs |

**Not verified, and the risk taken with each.**

- **Payload grew by 217 KiB raw and 74 KiB gzipped** — 4 502 678 → 4 724 483 bytes, measured on one
  toolchain against the same tree. That is `serde_json` and `w3d-format`, and it is the price of
  reusing the specified format instead of inventing a leaner one for this boundary. The trade was
  taken deliberately: a second format is a second specification, a second implementation and a
  second thing to get wrong. It makes register item 7 worse and item 7 should say so.
- **Nothing streams, and on this scene nothing could.** The boolean collapses plate and drill into
  **one body**, so there is nothing to show progressively: a chunk *can* be uploaded before its
  siblings — indices are chunk-local precisely so it can — but the 624 ms is one body's meshing and
  cannot be subdivided from outside the kernel. Demonstrating progressive upload needs a
  multi-body document, which now costs one line in the generator and was not taken because it would
  change the scene every other check is written against.
- **The spinner is the only thing using the free thread.** The measurement says the thread is
  available; nothing yet does anything with it beyond painting four characters.
- **One document, one body, 22 958 bytes in and 183 028 out.** Two orders of magnitude below what
  the design is for, and unchanged by this work.
- **`chunksPerBody` is still 4 because it is a number.**
- **The drift check between the two copies of the scene is weak, and is written down as weak.**
  There are now two definitions of the demo scene — `format/examples/scene_w3d.rs` and `scene()` in
  `web/src/lib.rs` — and what guards them is a triangle count agreeing within 1%. Equality is not
  available, because of the cross-architecture finding above. A change to a dimension that does not
  move the triangle count would pass it.
- **Headless Chromium, CPU rasteriser, one browser, one machine**, and `make web-test` is still in
  no CI job. The threaded variant was again not built — no nightly here — so the `THREADED_BUILT`
  false branch is what ran.
- **`make test-occt`, `make measure`, `make step-check`, `make app-test`, `make freecad-check` were
  not run here.** No OCCT, no display. CI is where those become checks.

## Loose ends, deliberately left

- **OCCT for Emscripten (item 3) was not attempted, and the reason is not time.** This container has
  no `emcc`, no `emsdk` and no OCCT at all — checked, not assumed. Beyond installing those it needs
  an OCCT source tree built for wasm (hours, not minutes) and **two decisions that are
  architectural rather than mechanical**: `-fwasm-exceptions` against `-fexceptions`, which has real
  size and speed consequences, and a genuine upstream pin, since `native/UPSTREAM` names a version
  and does not enforce one. Doing it badly is worse than not doing it, because the result would be
  a build nobody can reproduce.
- **The mesh in the geometry blob (item 9) was not attempted either, and could not be verified
  here.** It is an OCCT-side finding — OpenCASCADE attaches triangulations to faces it meshes and
  its BREP writer writes them — and there is no OCCT in this container to reproduce the 52x
  measurement against, let alone to check a fix. It is also a **decision about `FORMAT.md`** with
  three named routes rather than a defect with one fix, which makes it the wrong thing to settle
  unilaterally in a session that cannot run the test.
  Worth noting alongside it: `TruckKernel` has the opposite property — its blob is the solid as
  JSON with no mesh — so the browser's format is not affected and this work does not touch it.
- **`.gitignore` has `.DS_Store__pycache__/` on one line**, so neither pattern matches anything.
  Pre-existing, one character, and left alone rather than widening this change.
