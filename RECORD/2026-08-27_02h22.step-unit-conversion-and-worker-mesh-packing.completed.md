# 2026-08-27 02h22 · STEP unit conversion and worker mesh packing

## Where this repo actually was

`kernel-occt` imported STEP files, but all fixture samples were in millimetres.
However:
- STEP files defined in Imperial units (inches) had never been verified to convert to millimetres on import (Item 1).
- `w3d-render` did not define a 28-byte zero-copy `PackedMesh` layout for Transferable `ArrayBuffer` serialization across Web Worker boundaries (Item 7).

## Walkthrough · as built

- Added test `step_file_in_inches_is_converted_to_millimetres_on_import` in `kernel-occt/tests/step.rs`:
  - Mutates exported STEP file unit definition to `CONVERSION_BASED_UNIT('INCH', ...)` with factor 25.4.
  - Asserts that importing converts $1\text{in} \times 2\text{in} \times 3\text{in}$ box to $25.4\text{mm} \times 50.8\text{mm} \times 76.2\text{mm}$ in the kernel.
- Defined `PackedVertex` (28 bytes: 12-byte position, 12-byte normal, 4-byte face ID) and `PackedMesh` in `render/src/scene.rs`:
  - Implements `bytemuck::Pod` and `bytemuck::Zeroable` for zero-copy Transferable `ArrayBuffer` serialization across Web Worker boundaries.
  - Implemented `PackedMesh::pack` and `GpuMesh::from_packed`.
  - Added unit test `packed_mesh_serializes_and_preserves_28_byte_alignment` in `render/src/scene.rs`.

## Bugs found by building, not by reading

- **STEP Unit Entity Requirement**: OpenCASCADE's `STEPControl_Reader` requires explicit `CONVERSION_BASED_UNIT('INCH',#3470)` with `LENGTH_MEASURE_WITH_UNIT(LENGTH_MEASURE(25.4),#3461)` in the geometric representation context to trigger automatic unit scaling to millimetres on import.
