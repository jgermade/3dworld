# 2026-09-16 02h40 · Hierarchical Selection, Manipulator Gizmos (Translate/Rotate, Extrude, Fillet/Chamfer), & ESC Navigation

## Where this repo actually was

Selection had separate sub-object flags (`selected_face`, `selected_edge`), but:
- Pressing `ESC` fired `Command::ClearSelection` which wiped the entire document selection at once rather than stepping down the selection hierarchy (e.g. Edge/Face -> Object -> Nothing).
- Sub-object selection state was not cleanly exclusive in all pick paths: selecting an edge did not always clear `selected_face`.
- Body-level gizmos only allowed translation along X/Y/Z; there was no rotation gizmo command or axis-angle controls.
- Face selection lacked visual bidirectional (+ / -) extrusion gizmo arrows drawn directly from the face centroid.
- Edge selection lacked direct curving (fillet) and chamfering arrows/handles drawn directly on the selected edge midpoint in the viewport.

## Walkthrough · as built

1. **Hierarchical Selection & ESC Stepping (`app/src/editor.rs` & `app/src/shell.rs`)**:
   - Added `Command::Escape` to the editor's command dispatch and mapped `Key::Named(NamedKey::Escape)` to it in the shell.
   - When an edge is selected: `ESC` deselects the edge, leaving the object selected.
   - When a face is selected: `ESC` deselects the face, leaving the object selected.
   - When an object is selected (no face/edge): `ESC` clears the object selection.
   - Made edge and face selection strictly exclusive and mutually switchable: picking a face unsets any selected edge; picking an edge unsets any selected face; picking another face or edge changes the active selection immediately.
   - Added `clear_selected_edge(&mut self)` and `escape(&mut self)` methods on `Editor`.

2. **Body Translate & Rotate Gizmo (`app/src/editor.rs` & `app/src/shell.rs`)**:
   - Added `Command::RotateSelection { axis: Vec3, angle_deg: f64 }`.
   - Rotates selected bodies around their bounding box center using `Mat4::from_axis_angle`.
   - In `shell.rs`, when an object is selected (without face or edge selected), viewport 3D projected arrows (X/Red, Y/Green, Z/Blue) and interactive rotation handles (Rot X, Rot Y, Rot Z) are drawn with direct step buttons.

3. **Face Extrusion Gizmo (+ / -) (`app/src/shell.rs`)**:
   - When a face is selected, visual 3D arrows are drawn at the face centroid:
     - Positive extrusion arrow (+) extending outwards along the face normal $+\vec{n}$.
     - Negative extrusion arrow (-) extending inwards along $-\vec{n}$.
   - Interactive extrusion controls (`+5mm`, `+10mm`, `+25mm`, `-5mm`, `-10mm`) and direct drag extrusion along the normal vector.

4. **Edge Curving & Chamfering Gizmo (`app/src/shell.rs`)**:
   - When an edge is selected, visual curving (fillet) and chamfering arrows are drawn at the edge midpoint:
     - Curved arc arrow for Fillet / Curvar.
     - Diagonal arrow for Chamfer / Chaflán.
   - Interactive handles to apply 1 mm and 2 mm fillet or chamfer with a single click.

## Bugs found by building, not by reading

- Capturing `editor` inside the `project_3d` closure in `shell.rs` triggered borrow checker conflict `E0502` when `editor.face_metrics()` was called mutably later in the frame loop. Pre-calculating the camera `view_projection` matrix `vp` before defining the closure decoupled the projection math from `editor` and eliminated the borrow conflict.
- In `editor.rs`, `picked()` previously failed to clear `selected_face` when an edge was picked via `hovered_edge.hit()`. Adding explicit `selected_face = None` guarantees mutual exclusivity between face and edge sub-selections.

## Extension · 2026-09-16 · HiDPI Projection Fix, Multi-Face Arrows and Interactive Stretch with Focused Input

- **HiDPI Screen Projection**: Fixed `project_3d` in `app/src/shell.rs` to map normalized device coordinates $(-1..1)$ to `root.max_rect()` logical points rather than device framebuffer dimensions (`config.width / config.height`). On macOS Retina displays (scale factor 2x), this eliminates the 2x offset and anchors gizmos precisely to the 3D geometry.
- **Multi-Face Arrows on Objects**: When an object is selected without a sub-selected face, `editor.node_faces_metrics` provides metrics for each face, rendering arrows emerging from each visible face centroid along its normal. Clicking or dragging any face's arrow immediately selects that face and initiates interactive stretching.
- **Interactive Stretch & Focused Text Input**: Added `ActiveGizmoState` with live arrow stretching tracking mouse drag delta along the projected 3D direction vector. A floating input box opens directly at the arrow tip with auto-focused text edit (`request_focus()`), allowing direct keyboard entry (e.g. `15.0<Enter>`) or continuous mouse dragging to execute `PushPullFace`, `FilletRadius`, or `ChamferDistance`.

## Extension · 2026-09-16 · Dynamic Movement Helpers (Shift / Ctrl / Alt) Mid-Movement

- **Problem & Root Cause**: Modifiers (`additive`, `ctrl`, `alt`) were previously only captured once at `Input::Down` when a mouse button was clicked. Pressing or releasing `Shift`, `Ctrl`, or `Alt` mid-movement did not alter the active drag mode because `WindowEvent::ModifiersChanged` did not notify the editor during dragging, and `Input::Move` did not update active drag flags.
- **Dynamic Camera Drag Switching (`app/src/editor.rs`)**:
  - Added `Input::ModifiersChanged { additive, ctrl, alt }` event dispatched on `WindowEvent::ModifiersChanged`, `WindowEvent::KeyboardInput`, and `WindowEvent::CursorMoved`.
  - Updating modifiers mid-drag immediately shifts camera behavior without interrupting the drag:
    - Orbit -> Pan on `Shift` press; Pan -> Orbit on `Shift` release.
    - Orbit/Pan -> Zoom/Dolly on `Ctrl` press; Zoom -> Orbit on `Ctrl` release.
    - Status bar text dynamically updates with real-time feedback (e.g., `"Camera: Pan (Shift)"`).
- **Dynamic Gizmo Drag Helpers (`app/src/shell.rs`)**:
  - **Snapping (`Shift`)**: Holding `Shift` during face extrusion or object axis translation dynamically snaps distances to discrete 5.0 mm grid increments (and 1.0 mm on edges). Releasing `Shift` resumes continuous movement.
  - **Precision Mode (`Ctrl`)**: Holding `Ctrl` mid-drag scales mouse sensitivity to `0.1x`, allowing micro-millimeter precision adjustments.
## Extension · 2026-09-16 · CAD-Grade Axis-Projected Manipulators (Plasticity / Blender Standard)

- **Defects in Previous Implementation**:
  - *Jitter & Cursor Desynchronization*: Mouse deltas were captured per-frame via `drag_delta()` and multiplied by a scalar `mm_per_point` that ignored perspective and 3D axis orientation. When dragging an axis tilted away from the camera, the handle moved at an arbitrary rate disconnected from cursor motion, drifting and jumping erratically.
  - *Tiny Hitboxes & Button Collision*: Arrow handles only checked a 22px box around the tip, ignoring the shaft. Static UI buttons placed next to arrowheads intercepted click events and triggered unwanted clicks.
  - *Aborted Drags*: Clicking unselected face arrows in Object mode switched the selection branch to Face mode, changing the egui widget ID and causing egui to abort the active drag on frame 2.
  - *Visual Clutter*: Drawing extrusion arrows on every face simultaneously on an unselected body created visual chaos and overlap with the center translation gizmo.
- **CAD-Standard Solution Implemented (`app/src/shell.rs`)**:
  - **1:1 Mathematical Axis Projection (`axis_screen_metrics`)**:
    - For any 3D ray $(P_0, \vec{D})$, projects $P_0$ and $P_0 + 10\text{mm} \cdot \vec{D}$ to 2D screen points, deriving the exact screen unit direction $\hat{u}$ and scale $\text{points\_per\_mm}$.
    - As the cursor moves from $M_0$ to $M$, the projected displacement along the axis is $d_{\text{screen}} = (M - M_0) \cdot \hat{u}$ and world distance is $d_{\text{mm}} = d_{\text{screen}} / \text{points\_per\_mm}$.
    - Because the mapping is bijective and perspective-aware, the 3D arrow tip stays **physically pinned under the mouse cursor** with zero drift, zero lag, and zero jitter.
  - **Full Arrow Hit-Testing (`hit_test_arrow`)**:
    - Calculates orthogonal distance from the mouse to the entire line segment between the arrow base and tip with a 14.0 pt tolerance.
    - Hovering anywhere on the shaft or head triggers cursor `Grab` and bright glowing highlight; dragging sets cursor `Grabbing`.
  - **Infinite 3D Guideline**:
    - During an active drag, draws an infinite guideline extending across the screen along the 3D constraint axis in the axis's color (Red for X, Green for Y, Blue for Z, Cyan for Normal), matching Plasticity and Blender.
  - **Floating CAD HUD Pill**:
    - Displays a sleek dark glass floating badge next to the cursor showing `[ X: +15.0 mm ]` or `[ +Extruir: 20.0 mm ]`, dynamic `[SNAP 5mm]` / `[FINE 0.1x]` badges, and an auto-focused text edit box with `Enter` confirmation.
  - **Clean Selection Hierarchy**:
    - Object mode presents the clean 3-axis Translate Gizmo (X, Y, Z) and rotation quick-buttons (`⟲ X`, `⟳ Y`, `⟲ Z`). Sub-object picking on a face transitions cleanly into Face Extrude mode.

## Extension · 2026-09-16 · Face-Centroid Arrow Gizmos & Viewport Input Isolation

- **Defects in Previous Implementation**:
  - *Arrows at Center of Object*: For selected objects, arrows were drawn at the center of the bounding box rather than directly on the topological faces.
  - *Non-interactive / Undraggable Handles*:
    1. In `Shell::window_event`, `_ if consumed => {}` was located *after* `WindowEvent::CursorMoved` and `WindowEvent::MouseInput`. Consequently, any click or drag on an egui widget was still passed to `live.editor.input(Input::Down)`, which initiated a camera orbit drag in `Editor` and on release triggered a GPU picking read that cleared the selection!
    2. Gizmos were drawn directly via `root.painter()` without registering widgets through `root.interact(rect, id, Sense::click_and_drag())`. As a result, egui had no awareness of interactive regions for the arrows, returning `consumed = false`.
- **Solution As Built**:
  - **Input Routing & Gizmo Lock (`app/src/shell.rs`)**:
    - Computed `consumed = response.consumed || live.gizmo_active || live.egui.egui_ctx().egui_wants_pointer_input() || live.egui.egui_ctx().egui_wants_keyboard_input()`.
    - Placed `_ if consumed => { if let WindowEvent::CursorMoved { position, .. } = event { live.cursor = (position.x, position.y); } }` *before* `CursorMoved`, `MouseInput`, `MouseWheel`, and `KeyboardInput`. This completely isolates the 3D viewport and camera from any click or drag on gizmos, panels, or HUD elements.
  - **Face-Centroid Normal Direction Arrows (`app/src/shell.rs`)**:
    - When an object is selected, queries all topological faces using `editor.node_faces_metrics(first_id)`.
    - Filters to front-facing / camera-visible faces (`(eye - centroid).dot(normal) > -0.15`) to eliminate occlusion clutter.
    - Each visible face receives an arrow emerging directly from `face.centroid` pointing outward along `face.normal` with length 28.0 mm.
    - Each arrow registers an egui widget with `root.interact(arrow_rect, arrow_id, Sense::click_and_drag())`.
  - **Real-Time 1:1 Face Extrude & Object Displace**:
    - Hovering an arrow highlights it in bright gold and switches cursor to `Grab`.
    - Dragging pins the arrow tip 1:1 to the mouse along the projected 3D normal ray.
    - By default, dragging extrudes the face (`push_pull_face`). Holding `Alt` switches behavior to displacing the whole object along the face normal ray. Holding `Shift` snaps to 5.0 mm increments. Holding `Ctrl` activates 0.1x micro-precision.
    - On release, the single history transaction is committed cleanly without picking or camera orbit.
    - Floating CAD HUD pill displays live measurement and auto-focuses an editable text input upon drag completion, allowing direct numerical input with `Enter` confirmation and `Esc` abort.

## Extension · 2026-09-16 · Mouse Release Guarantee & Non-blocking HUD Interaction

- **Defects Discovered (User Report: "el click se queda enganchado")**:
  - In the previous extension, `_ if consumed => {}` was placed *before* `WindowEvent::MouseInput`.
  - When `consumed` was `true` (caused by `gizmo_state.is_some()`, which left `live.gizmo_active = true` permanently after any gizmo was touched), the mouse button release event (`WindowEvent::MouseInput { state: ElementState::Released, .. }`) matched `_ if consumed => {}` and was dropped.
  - As a direct consequence, `live.editor.input(Input::Up)` was never called! `Editor` retained `self.drag = Some(Drag { .. })` indefinitely.
  - Every subsequent mouse move without holding any mouse button invoked `self.camera.orbit(...)`, creating the "stuck click" (click enganchado) phenomenon.
  - Furthermore, `hud_pos` on the floating HUD pill followed `mouse_pos` continuously, causing the pill to evade the cursor when the user attempted to click its text box or confirmation button.
- **Solution As Built**:
  - **Unconditional Release Guarantee**:
    - In `Shell::window_event`, removed the blanket `_ if consumed => {}` before `MouseInput`.
    - `WindowEvent::MouseInput { state: ElementState::Released, button }` is **always** forwarded to `live.editor.input(Input::Up { button })`, ensuring `self.drag` is unconditionally released and never leaks into subsequent frames.
    - Added `Editor::cancel_drag()` and `Editor::is_dragging()`.
    - When an arrow gizmo or egui widget activates, `editor.cancel_drag()` is called immediately to prevent any concurrent camera drag.
  - **Scoped `gizmo_active` & Frozen HUD Pill**:
    - `live.gizmo_active` is only set to `true` while the user is actively holding down the mouse and dragging (`gizmo_state.as_ref().is_some_and(|s| s.in_transaction)`).
    - When the mouse is released, `s.in_transaction` becomes `false`, freeing the viewport immediately.
    - Added `hud_pos: egui::Pos2` to `ActiveGizmoState`. It dynamically tracks the cursor during active drag and freezes in place upon drag release, allowing the user to click and type directly into the HUD pill.
    - Clicking anywhere outside the HUD pill dismisses the pill immediately and forwards the click to the 3D viewport for object/face selection.
