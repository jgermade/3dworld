## Where this repo actually was

Item 4 was half taken. `WIRE.md` specified what crosses a worker boundary, `w3d-wire` implemented
it, and a tessellation had crossed a heap for the first time that morning. But `w3d_web::start`
still modelled the scene, tessellated every body and uploaded the result before it returned — all
on the thread that then had to draw — and `replaceWithWire` was a method a caller invoked
*afterwards*. That was deliberate: the main thread's own result was the only thing there was to
compare the worker's against. It also meant the **56-second stall `make measure` found was shown to
be removable and not removed**, which is the sentence the register had been carrying.

Two things about this container, because they decide what the claims below are worth.

**It had none of the toolchain the previous session's had.** No `wasm32-unknown-unknown`, no
`wasm-bindgen-cli`, no `node_modules` in `web/test/`. All three were installed —
`wasm-bindgen-cli` pinned to 0.2.127, the lockfile's version, because a mismatch there is a runtime
error about an unknown import rather than a build failure.

**And `make test` did not pass on a clean tree.** `rustc 1.94.1` cannot build `egui 0.36.1`, which
`w3d-app` depends on, so `cargo check` failed at dependency resolution before compiling a line.
That was confirmed by stashing the work and running it on the untouched tree, so that nothing below
can be read as caused by this change. Updated to `rustc 1.98.1`, where the whole of `make test`
passes. Nothing in the repository was changed for it.

## Walkthrough · as built

**`start` stops meshing.** It opens a device, configures the surface, builds the renderer and the
depth texture, and returns a `Viewer` with **no bodies in it**. There is no document on the page
any more. Two things follow that are not obvious from the function, so they are written at it: a
viewer returned from `start` draws nothing, and the camera cannot be fitted there because there are
no bounds to fit it to.

**`replaceWithWire` becomes `installWire(chunks, facts)`.** The merge and the grouping are
unchanged. What is new is that it now **fits the camera**, from the vertices that arrived, because
`start` no longer can. Those are *mesh* bounds, not the B-rep's — they sit inside by the chordal
error, so a tessellated cylinder is fractionally narrower than the cylinder. For framing a view
that is not a difference anyone can see; it is written down because for anything that must be exact
it is the wrong number.

**`facts` rather than three positional arguments**, and one of them is the interesting one.
`tessellateMs` and `modelled` have to be passed because the page has nothing left that could
measure the one or answer the other. `fromWorker` has to be passed because **a `WIRE.md` message
has no field for where it was made** — deliberately: the format describes a mesh, not a
provenance — so bytes tessellated on this thread and bytes posted from a worker are byte-for-byte
indistinguishable on arrival. Only the caller knows. Missing or mistyped facts are an error rather
than a default, because a `tessellateMs` that quietly became 0 would read as a boot too fast to
believe.

**`report().meshedBy`**, which is the whole of how any of this is checkable. A page that fell back
to meshing on the thread that draws produces the identical picture, in the identical colours, with
the identical triangle count; the only difference is a stall, and nothing in a screenshot, a colour
count or a triangle count can see one. So the page says which happened, and every run of
`make web-test` asserts it.

**`tessellateHere()`** is what `start` used to do, kept reachable on purpose. A module worker can
fail for reasons that have nothing to do with the engine — a CSP without `worker-src`, a
`worker.js` that did not deploy, a `file:` URL — and a modeller that shows *nothing* because a
worker would not start is a worse answer than one that is slow.

**The loader's order, and all three parts of it are load-bearing.**

- **The worker starts before the module is imported.** It loads its own copy of the wasm and shares
  nothing, so there is nothing to wait for, and every millisecond spent negotiating an adapter on
  this thread is a millisecond the worker is already modelling.
- **The mesh is installed before the graphics check.** `drewSomething` decides whether WebGPU
  actually rasterised anything by counting colours on the canvas, and an empty viewport is a flat
  canvas. Run it first and every browser on earth "fails" it and falls back to WebGL2. The
  dependency is invisible in both functions, which is why it is a comment in the one place that
  orders them.
- **The graphics fallback re-installs rather than re-tessellates.** This is the one that was
  costing something already: the old code called `start` again, and `start` tessellated. So a
  machine that fell back from WebGPU to WebGL2 — which is to say the *weakest* machine that reaches
  this page — paid for the whole tessellation twice. It now re-uploads bytes it already holds.

**`modelled` crosses beside the bytes**, since the worker's document is now the only one there is.
This matters more than it looks: the page asked for a plate with a hole from the first day it drew
anything and for nine days got a plate, because the backend's boolean returned a copy of its first
operand. That check is the only one anywhere that says the browser is modelling rather than
displaying, and moving the tessellation out would have quietly taken it away.

**The comparison, rebuilt in the opposite direction.** It used to be free: the main thread meshed,
the worker replaced it, and "the same triangles by a different route" was a before-and-after on one
viewer. Now the worker goes first and there is no `before`, so `boot` returns the `module` and the
page tessellates the same scene on the main thread *afterwards* and installs it through the same
wire path. Two independent tessellations, in two linear memories, of one document, are required to
agree. `installWire` is told `fromWorker: false` for that second one, and the run asserts the
report changes from `worker` to `main thread` — because if it did not, `meshedBy` would be a
decoration that always agrees with whoever wrote the caller, and the check above it would be worth
nothing.

**A sixth browser run: the worker failing.** `?worker=fail` points the loader at a worker URL that
404s, so the fallback is reached through a *real* rejection rather than a flag that skips the
attempt. An untested fallback is a fallback that does not work, and this one exists precisely for
machines nobody here is testing on.

## Bugs found by building, not by reading

- **Every pick in this page has been read from the wrong place, on every run, since the viewport
  existed.** The canvas backing store was 960x624 inside a box 960x468 tall. `fit()` runs once at
  boot, when the status bar still says "starting…"; the moment the page has anything to report the
  bar grows to six lines and the grid takes that height out of the viewport — with *no window
  resize*, so the `resize` listener never fires and `fit` never runs again. A mismatch like that is
  invisible on screen, because the image is simply scaled into the box and looks correct. It is
  wrong only for something that maps a screen coordinate back into the buffer, and the only thing
  that does is a click. Every click was landing about a third of the height from where it was read,
  and the scene is a large centred plate that absorbed the error.
  What exposed it was a *seventh* status line — the worker-failure run's note, which grew again
  when the error message was improved — taking enough height out of the viewport to push a centre
  click off the part. Fixed with a `ResizeObserver` on the container, which is what sees a layout
  change that no window resize accompanies. The measurement is in the record because the
  diagnosis was measured rather than reasoned: 960x624 backing against 960x468 displayed, before
  and after.
  **It now has an assertion of its own** rather than being left to the pick to notice, because a
  passing pick demonstrably was not evidence.
- **Hard-coding the provenance would have made the new check worthless on its first use.** The
  first version of `installWire` set `meshedBy = worker` unconditionally, which is true of every
  caller that exists in `loader.js` and false of the first line of the test written against it —
  which installs main-thread bytes through the same method. It would have passed.
- **A chunk out of `tessellateScene` is not what the worker says it is.** `web/worker.js` carried a
  comment stating its `Uint8Array`s are views into the module's linear memory, and that posting
  their `.buffer` would hand the engine the whole wasm heap. Measured: a 75 964-byte chunk arrives
  in a 75 964-byte `ArrayBuffer`, so `js_sys` is copying onto the JS heap and each chunk already
  owns its buffer. The copy in the worker stays — as insurance, because the day anyone reaches for
  `Uint8Array::view` to avoid it, the old comment becomes true and the failure is catastrophic —
  but it stays with an accurate reason, and the ratio is now asserted so a change to it is a
  failing check rather than a silent hazard.
  **What this does not explain is why the first version of that file failed in Chromium**, which is
  what the original comment was written from. The measurement says what the buffers are; it does
  not say what went wrong that day, and this paragraph should not be read as settling it.
- **`make test` was already failing on a clean tree**, for a toolchain reason with nothing to do
  with any of this. Worth recording because the obvious reading of a red `make test` in the middle
  of a change is that the change did it.

## Verified, and not

**Verified.** All six runs of `node web/test/browser.mjs` against Chromium, plus the native suite.

| The worker really ran | 4 chunks, 182 788 bytes, every byte arrived, and the sender's buffers are detached afterwards — the check only the sending side can make |

| `meshedBy` is evidence, not decoration | Installing main-thread bytes through the same method flips the report to `main thread`; asserted as a transition |

Worker phases on this machine, one scene, headless Chromium on a CPU rasteriser: instantiate 44 ·
model 500 · mesh 549 · encode 2 ms. Facts, not targets.

**Not verified, and the risk taken with each.**

- **The stall is off the thread that draws; it is not gone, and the user still waits.** `boot`
  awaits the worker before it installs anything, and nothing is drawn before the mesh arrives —
  no spinner, no progressive upload, no interaction with an empty scene. What changed is that the
  main thread is no longer *blocked* for the duration, which is the thing that would let any of
  those exist. None of them does. **Time-to-first-frame was not measured before and after**, and
  on this scene it is unlikely to have improved: the worker costs 44 ms to instantiate that the
  old path did not pay.
- **No document has crossed.** The worker still *builds* the page's scene rather than being sent
  one, which works only because that scene is fixed and both sides can construct it. This is the
  whole of what keeps it a demonstration boot path rather than a modeller's, and it is what takes
  item 4's number in the register.
- **One body, four chunks, 178 KiB** — two orders of magnitude below the 84 MiB the design is for.
  Nothing here says what happens at that size, and the one thing that would is OCCT in wasm.
- **`chunksPerBody` is still 4 because it is a number.** Unchanged, still unmeasured.
- **The threaded variant was not built**, because this container has no nightly toolchain and
  `make web-threaded` rebuilds `std`. So `make web-test` proper — which depends on `web-both` — was
  **not run**; `node web/test/browser.mjs` was, with `THREADED_BUILT` false. Both branches of those
  assertions exist and the false branch really ran, so this is not a check that evaporated; but
  what a worker does *inside* a threaded build is untouched and unknown.
- **Headless Chromium on a CPU rasteriser, one browser, one machine.** No Firefox, no Safari, and
  the timings say nothing about hardware. `make web-test` is still in no CI job, so this whole file
  is checked on one machine and nowhere else.
- **`make test-occt`, `make measure`, `make step-check`, `make app-test` and `make freecad-check`
  were not run here** — no OCCT, no samples, no display. Nothing in this change touches the
  kernel, the format or the shell, but that is an argument, not a check. CI is where it becomes one.
- **The camera now frames from mesh bounds rather than the document's.** Both paths use the same
  function so they cannot disagree with each other, but neither agrees exactly with what `start`
  used to do.
- **Nothing is measured about memory.** Two heaps exist; neither has been filled.

## Loose ends, deliberately left

- **Nothing exploits the thread being free.** The entire benefit of this change is latent until
  something draws, reports progress, or accepts input while the worker works. A spinner is the
  cheap one; a progressive upload — chunk 0 on screen before chunk 3 arrives — is the one the
  format was already built for, since chunk indices are chunk-local precisely so a chunk can be
  uploaded alone. `merge` still waits for all of them.
- **`dpr` is sampled once** at boot. A window dragged to a monitor with a different device pixel
  ratio gets the same stale backing store the `ResizeObserver` just fixed, by a different route.
- **The worker is started unconditionally**, even where `tessellateHere` would be faster. On a
  scene this size, instantiating a second wasm module costs 44 ms to save 549; on a scene small
  enough, it would be a loss. Nothing measures where the crossover is.
- **The failure path is tested through a 404 and only a 404.** A CSP refusal, an out-of-memory
  worker and a worker that starts and then throws all reach the same `catch` and none is exercised.
