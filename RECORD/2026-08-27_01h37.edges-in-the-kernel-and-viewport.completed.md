# 2026-08-27 01h37 · Edges in the kernel and viewport

Work on item 3 from `2026-08-25_21h59.what-is-not-built-yet.md`: declaring edge curve tessellation in `w3d_kernel::Mesh`, implementing edge extraction in geometry backends (`FakeKernel` and `OcctKernel`), uploading line buffers in `w3d-render`, and rendering sharp edges and selection overlays in `w3d-app`.

## Where this repo actually was

`Mesh` carried positions, normals, indices, and `face_of_triangle`, but no edge curve geometry. Every viewport render was a smooth/flat lit surface without edge borders or feature outlines.

## Walkthrough · as built

- **`w3d-kernel`**: Added `line_positions: Vec<[f32; 3]>` and `line_indices: Vec<u32>` to `Mesh`, along with `line_count()` helper. Extended `conformance.rs` checks to validate line index counts and bounds.
- **`w3d-kernel-fake`**: Extended `tessellate_box` to output the 12 box edge line segments into `line_positions` and `line_indices`.
- **`w3d-kernel-occt`**: Extended `W3dOcctMesh` (C ABI header and C++ implementation) and `OcctKernel::tessellate` to extract B-rep edge polylines via `TopExp_Explorer(shape, TopAbs_EDGE)` (`Polygon3D` / `PolygonOnTriangulation`).
- **`w3d-render`**:
  - Defined `LINE_VERTEX_LAYOUT` and uploaded `line_positions` & `line_indices` in `GpuMesh`.
  - Added `vs_line` and `fs_line` entry points in `shade.wgsl`.
  - Added `lines` pipeline with `PrimitiveTopology::LineList` and `LessEqual` depth compare to render crisp sharp edges over solid face meshes.
- **`w3d-app`**: Renders sharp edge overlays in the viewport, highlighting edges of selected bodies in orange.

## Bugs found by building, not by reading

1. **wgpu Depth Bias on Line Topology**: Setting `bias` (depth bias) on a `LineList` pipeline causes a wgpu validation panic (`Depth bias is not compatible with non-triangle topology LineList`). The solution is using `Default::default()` for `bias` on line pipelines and using `LessEqual` depth comparison.
