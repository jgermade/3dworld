# 2026-08-26 08h05 · STEP against something that is not us

Took item 1 from [the register](./2026-08-25_21h59.what-is-not-built-yet.md), which the previous
file had put there hours earlier and which was the largest caveat in the repository.

## Where this repo actually was

STEP went in and out, through 17 tests against real OpenCASCADE and a two-process round trip in a
real window. Every one of those claims had the same shape: **OpenCASCADE agreeing with
OpenCASCADE.** The writer and the reader are one library, and a round trip through one library
proves that it is self-consistent, which is not what a file format is for.

The `Verified, and not` of the previous file said so in as many words, and the register turned it
into item 1 with two halves: a file this program writes, opened by something else; and a file
something else wrote, opened by this program.

## Walkthrough · as built

### A parser with no OpenCASCADE in it

`tools/step_check.py` reads a file this program wrote using `steputils` — a pure-Python ISO
10303-21 parser that shares no line of code with OCCT — and then asks it questions:

| Check | Why it is not a formality |
| --- | --- |
| every `#n` resolves | The one thing OCCT reading its own output can never fail: a truncated file, a lost instance, a writer that renumbered halfway. |
| `FILE_SCHEMA` is AP214, `FILE_NAME` names this program | The two strings a receiving program and a confused user respectively read first. |
| every `MANIFOLD_SOLID_BREP` is reachable from a shape representation | A solid nothing points at is *in the file and not in the model*, and a receiving program is entitled to ignore it. This is the failure that looks fine in a byte count and in a round trip. |
| faces counted by surface type | `PLANE=6,CYLINDRICAL_SURFACE=1` for a drilled plate is the assertion that **the hole is in the file**. |
| exactly one length unit, `.MILLI. .METRE.` | The document has no units; the file is where that decision is written down, so it is where it gets checked. |

**The split matters.** `steputils` supplies the *file* — instances, types, parameters — and nothing
about geometry. Every geometric question above is this script's own reading of part 21, on
purpose: a parser that also interpreted the geometry would be one opinion arriving twice.

The controls run first, as everything in `tools/` here does. Prose, a truncated file, a file whose
reference dangles, and a well-formed file that must pass — plus one control on the *real* input:
half of the file being checked must not pass, because a checker that accepts half a file has not
read the half it was given either.

### Files three other programs wrote

`make step-samples` fetches, and `tools/step-samples.txt` pins:

| File | Written by | Schema | Must |
| --- | --- | --- | --- |
| `as1_pe_203.stp` | PRO/ENGINEER, 2008 | AP203 | import |
| `face_recognition_sample_part.stp` | SIEMENS PLM Software NX 9.0, via ST-DEVELOPER v15 | AP214 | import |
| `splinecage.stp` | ST-DEVELOPER v15 | `AUTOMOTIVE_DESIGN_CC2` | **be refused** |

Three producers, none of them OpenCASCADE, two schemas this program does not write, and one schema
name — `AUTOMOTIVE_DESIGN_CC2` — that nothing here had ever seen.

**Pinned by SHA-256, not by a branch.** The register has held it against `native/UPSTREAM` since it
was written that naming a version is not enforcing one; a hash enforces it. A file whose digest
does not match is deleted rather than kept, because a check against the wrong input is worse than
no check. Nothing is committed, nothing is distributed, and `tools/licences.py` names both the
files and `steputils`.

### Two examples, and why they are not tests

`kernel-occt/examples/export_step.rs` writes the drilled plate and a sphere;
`import_step.rs` reads whatever it is given, and takes `--must-refuse` for the file that has to be
turned away.

Examples rather than tests, for two reasons. The samples are fetched and are not in the tree, and
**a `cargo test` that passes when its input is missing is a test that says yes for a living** —
the same objection this repository already records about `w3d-render` skipping without an adapter.
And they need no display, unlike `make app-test-step`, so the whole check runs on a machine with
no X server.

`import_step` does not stop at "it parsed". Every body it gets back is asked for its topology and
then **tessellated**, because a shape that cannot be meshed cannot be drawn, and a modeller that
imports something invisible has not imported it.

## Bugs found by building, not by reading

- **The first foreign file tried has no solids in it.** `splinecage.stp` is a legitimate STEP file
  containing four surfaces and no closed volume, and this modeller refuses it. That is the
  contract working — `import_step` is documented as one body per *solid*, and a `Body` is a solid —
  but the decision was made in the abstract and met reality on the first attempt. It is now a
  *negative control found in the wild rather than invented*: the check requires that it be refused
  **by name**, with what was in the file instead, and rejects a refusal whose message is too short
  to help anybody.
- **An assembly loses its instancing, and the numbers say so out loud.** The AS1 assembly holds
  **five** `MANIFOLD_SOLID_BREP` and imports as **eighteen bodies**: five distinct parts, placed
  eighteen times. Nothing in the document can say "the same part, eighteen times", so a user gets
  eighteen unrelated bodies. Neither wrong nor discoverable by reading — it took a parser counting
  one number and a reader reporting another. It is what item 2 of the register is now about, with
  evidence.
- **`FILE_NAME` cannot be read with string surgery**, and the first version of the fetcher tried.
  It got two of these three headers wrong: real files wrap the fields across lines and put C
  comments between them. Moved into `step_check.py --describe`, where there is an actual grammar.
  A small demonstration of exactly why the check is a parser and not a `grep`.
- **The GitHub API answers 403 through this environment's proxy**, while `raw.githubusercontent.com`
  is fine — so pinning to a commit SHA was not available. Pinning to a content hash is better
  anyway, and would have been the right answer with the API working.

## Verified, and not

**Verified.**

| | |
| --- | --- |
| `make step-check` | A file this program wrote, read by a parser with no OCCT in it: 460 instances, every reference resolving, both solids reachable from a shape representation, 6 planes + 1 cylinder + 1 sphere, millimetres. Then three files from three other programs, described by that same parser and put through the real reader — two imported and meshed, one refused with a reason. |
| the checker's controls | Prose, a truncated file, a dangling reference, and half of the real file are each rejected; a well-formed file passes. Pointed by hand at three mutations of a real export — one instance deleted, `.MILLI.` changed to metres, the schema renamed — it rejected all three, naming the reference, the unit and the schema respectively. |
| `make step-samples` | Fetches and verifies SHA-256; a mismatch deletes the file rather than keeping it. |
| `make test`, `make test-occt`, `make app-test-step` | Unchanged and green. |

**Not verified, and the risk taken with each.**

- **No foreign program has evaluated our geometry.** This is the half of item 1 that remains, and
  the distinction is exact: `steputils` reads the *file* and this script reads the *graph*. Neither
  builds a solid. That the topology is well-formed and the surfaces are the right count is real
  evidence and it is not the same as a CAD system saying "this is a valid closed solid of the
  expected volume". Nothing that could say that is installable in this environment — there is no
  FreeCAD in the image's apt sources — so it stays owed, and it is a manual step somebody has to do
  once, on a machine with a CAD program on it.
- **Three files is three.** No AP242, no file in inches, nothing from CATIA or SolidWorks, and
  nothing pathological. The unit conversion path still has never run: all three samples are in
  millimetres, so the code that scales a file in inches remains unexercised, exactly as it was
  before this work.
- **The imports are not asserted against expected geometry.** "18 bodies, 160 faces, 51 920
  triangles" is printed, not compared to a golden number, and nothing checks that the NX part is
  the *shape* it should be. What is asserted is that solids come out, can be measured and can be
  meshed. A wrong-but-well-formed import would pass.
- **The samples come from one repository.** Checksums protect against the files changing, not
  against the repository disappearing; `make step-check` then cannot run at all.
- **Still nothing measured.** The same upstream holds a 15 MB assembly, which would be the first
  honest number about import time and about the frame stalling. It is not wired up.
- **`make step-check` is not part of `make test`**, because it needs OCCT and a pip install. Like
  `make web-test` and `make app-test`, it is a check somebody has to remember.

## Loose ends, deliberately left

- **A CAD program in the loop.** The one thing that would close item 1, and it needs an environment
  with FreeCAD in it — or a person, once, with Fusion open.
- **A sample in inches, and one in AP242.** Both exist in the wild; neither was found in a place
  that could be pinned in the ten minutes it was worth spending.
- **Golden geometry for the imports.** Volume, or a hash of the topology counts, would turn "it
  imported" into "it imported the right thing". It needs a number somebody trusts first.
- **The 15 MB assembly**, which is the measurement item in the register waiting for a workload.

## Walkthrough · as completed

STEP is no longer only OpenCASCADE agreeing with itself. A parser that shares no code with it
reads what this program writes and is held to resolving every reference, finding the solids in the
model and counting the hole in the plate; and files from Pro/ENGINEER, Siemens NX and ST-Developer
go through the real reader, with a surface model from the wild serving as the negative control.
Everything fetched is pinned by content hash, committed nowhere, and named in the licence report.

Two findings came out of it that reading could not have produced: a legitimate STEP file with no
solids in it, refused — correctly, and now required to be refused *by name* — and an assembly whose
five distinct parts arrive as eighteen unrelated bodies.

What remains owed has moved to [the register](./2026-08-25_21h59.what-is-not-built-yet.md), which
keeps item 1 in a narrower form — a foreign *geometry* kernel opening one of our files, which
cannot be done in this environment — and takes the rest: samples in inches and AP242, golden
geometry for imports, the 15 MB assembly as the first measurement, and the instancing that item 2
now has evidence for.
