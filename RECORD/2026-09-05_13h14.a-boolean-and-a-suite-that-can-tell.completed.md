# 2026-09-05 13h14 · A boolean, and a suite that can tell

Takes **item 4** from `2026-08-25_21h59.what-is-not-built-yet.md`: *"`truck`'s boolean is not a
boolean, and the conformance suite passes it."* Both halves. The boolean is real now, within limits
this file is specific about, and the suite has a half that a bounding box cannot pass.

It also takes the register's small item **"`make web-test` fails two checks"**, which turned out to
be the same defect wearing a different hat — the guess recorded beside it was right.

## Where this repo actually was

`TruckKernel::boolean` did this:

```rust
BooleanOp::Union => /* a box the size of both operands' bounds */,
BooleanOp::Difference => self.copy(a),
BooleanOp::Intersection => /* a box the size of the overlap of the bounds */,
```

and passed all 28 conformance checks. That is not an oversight in the suite so much as a hole in
what bounds can prove: **every assertion the suite made about a boolean was an assertion about its
bounds, and the bounds of a bounding box are correct.** The union of a box and a sphere really does
contain both operands when it is the box that contains both operands.

Downstream of it, `web/src/lib.rs` asked for a plate with a 6 mm hole, wrote `let _ =` on the
result, and drew a plate. Two browser checks had been failing since before the threaded variant —
"the canvas is not blank", 5 distinct colours against a threshold of 8 — and the register's note
beside them said *"plausibly item 4 — a box has fewer distinct shades than a drilled plate — but
that is a guess and the threshold must not be lowered to find out."*

## Walkthrough · as built

### The order is not the order it reads in

The boolean was the item. It could not be *seen* to work, and could not be checked by anything,
until two things underneath it were fixed — and neither was on the register, because reading the
code does not show either one.

### 1 — Tessellation meshed surfaces, not faces

`mesh_surface` took each face's **surface**, took its parameter range, and laid a
`StructuredMesh` grid over it. A face is a surface *plus the loops that trim it*, and the loops
were never read. For the geometry that existed at the time, that mostly worked: a box's planes
come out of `tsweep` with a parameter range that is exactly the rectangle. For everything else it
did not:

- A cylinder's cap is a plane trimmed to a circle, and `Plane`'s parameter range is unbounded, so
  the range fell back to `(0,1)²` — a **square cap on a round cylinder**.
- A face bounded by an intersection curve — which is *every* face a boolean makes — has no
  parameter range that describes it, so nothing a boolean produced could be meshed at all.

It is `truck-meshalgo`'s triangulation now, run over a shell holding one face, so the loops are
what bound the triangles. Two things come free with it: the **edges**, which this backend never
had (`line_positions` and `line_indices` were empty for every truck body ever drawn), taken from
the same polylines the triangulation divided the boundary curves into — so the wireframe and the
surface meet on shared points rather than on two approximations of one curve — and correct meshes
for `revolve`, `sweep`, `loft` and `extrude`, which had the same square-cap problem and nobody had
looked.

`bounds` had it too, and worse: it gridded the untrimmed surface and expanded an `Aabb` over
points **the solid does not contain**. It is measured over the triangulation now, at a sag of
0.005. That trades an answer that was wrong for an answer that is the mesh's — a curved face may
bulge past it by up to the sag — and the docstring says so.

The mesh is denser: the cylinder in `tessellation.rs` went from 1290 vertices to 3273, because a
cap is now a constrained Delaunay triangulation of a disc rather than four corners of a square.

### 2 — Two of the three primitives were inside out

The sphere and the cylinder enclosed a **negative** volume. Every normal on them pointed at the
body's centre. They have been drawn that way in the browser since 2026-08-27 and in the desktop
shell for as long as `TruckKernel` has been selectable.

Nothing caught it because nothing had ever asked. `Mesh` did not state a winding convention — the
renderer assumed one from the first frame and no document said it — so a backend could satisfy
every line of the contract while handing back a solid turned inside out. `Mesh`'s docstring states
it now, and the suite asserts it.

The cylinder's fix is not `not()`. It is built differently, and that is the third thing:

### 3 — A cylinder that a boolean can cut

`create_cylinder` revolved a rectangle about the axis by exactly 2π. `truck`'s `rsweep` closes a
sweep only when the angle is **past** a full turn; at exactly 2π it wraps the profile onto itself
and leaves a *seam*, a closed edge that begins and ends at the same vertex.
`truck-shapeops` cannot split one, and the measured consequence is not subtle:

| The pin | Subtracting it from a 40×40×10 plate |
| --- | --- |
| revolved rectangle, seam | **25 seconds**, and the result was the *plug* — volume 1130, the pin's own — rather than the plate |
| disc swept along the axis | **4 seconds** (debug), 360 ms (release), volume 14869.87 against 14869.03 by arithmetic |

So it is a disc — a circle from an `rsweep` past a full turn, attached as a plane, `tsweep`t along
the axis. It comes out oriented outwards as well, so the cylinder needed no flip; only the sphere
did.

The sphere is fixed with `not()` and is still a sphere `truck-shapeops` cannot touch: it panics,
inside `Solid::new`, on every combination tried — union, intersection, difference, and with the
tool in either orientation. `truck-shapeops`' own healing (`SplitClosedEdgesAndFaces`) is not
implemented for `truck-modeling`'s `Curve`, so that road is closed at this version.

### 4 — The boolean

`truck_shapeops::or` and `and`, with `Difference` as `and(a, b.not())`.

**The tolerance is not the document's**, and this is the compromise that could not be avoided.
`shapeops` uses its `tol` both as "are these the same point" and as the sag it divides an
intersection curve into a polyline at. The document's linear tolerance is `1.0e-7`; asking for
intersection curves that fine on a 40 mm plate is hundreds of thousands of segments. So the floor
is **relative to the operands**: `tol.linear.max(largest_extent * 1.0e-3)`. It is in one method,
`boolean_tolerance`, with the reasoning attached, and it is why a truck boolean is not exact in
the way OCCT's is — the hole is a polygon with a few hundred sides, and its volume comes out
0.006% over.

**Two failure modes, and they are told apart.** `truck-shapeops` returns `None` for a result it
could not build — that becomes `KernelError::Failed`. For geometry it cannot handle it *panics*,
which on the desktop is caught (`catch_unwind` → `Failed`) and in the browser is the end of the
module: `wasm32-unknown-unknown` aborts. So the case that is *known* to abort is refused before it
is attempted: `TruckKernel` remembers which bodies it built with a pole — today, spheres —
propagates that through `transform` and `copy`, and returns `KernelError::Unsupported` rather than
running. A declared no, instead of a crash.

### 5 — The suite, in two halves

The half that existed is unchanged in what it asserts and is now called the **contract** half: 28
checks, run against every backend including the fake.

The **geometry** half is 6 more, run only where the new `GeometryKernel::does_geometry` says the
backend does any. It asks the one question bounds cannot: *how much material is there?* The volume
a mesh encloses, by the divergence theorem, which is cheap, is true of any correct kernel to
within its sag, and is not something bookkeeping can fake — a bounding box has a volume and it is
the wrong one.

Three of the six are **mandatory**: the union, difference and intersection of a 4-cube and a 2-cube
sharing a 1×1×1 corner, whose answers are 71, 63 and 1 by arithmetic. No `Unsupported` is accepted
from them, because a kernel that cannot subtract one box from another is not a kernel — and
without a floor, "decline everything" would pass.

Which is the other half of the decision: **a backend may decline an operation and still conform;
it may not answer wrongly.** The four existing boolean checks, whose fixtures involve a sphere,
now accept `KernelError::Unsupported` and nothing else. That is a deliberate loosening in one
direction to buy a large tightening in another, and the alternative was a suite that either
excuses a bounding box or fails the only kernel the browser has.

`FakeKernel` is excused from the geometry half **by saying what it is**, not by being
special-cased in the suite. And the excuse is not free: `conformance::geometry` is public so that
`kernel-fake/tests/conformance.rs` can point the half it is excused from *at* it and require it to
fail, on the union and on the difference by name. A tier nothing fails is a tier that excuses
everybody.

### 6 — The browser says whether it modelled

`scene()` returns the document **and whether the boolean succeeded**, `report()` carries it as
`modelled`, and `browser.mjs` asserts it. Nothing in a screenshot, a triangle count or a frame
counter distinguishes "a plate with a hole" from "a plate and a pin in the same place", which is
exactly how this survived nine days.

## Bugs found by building, not by reading

- **`NaN` normals, twelve of them on a cylinder.** `truck-meshalgo`'s triangulation reports them
  where a surface degenerates. It was found by the conformance suite's *determinism* check — the
  same body tessellated twice gave two different meshes — which is not a coincidence: a `NaN`
  normal is a vertex that compares unequal to itself. `mesh_face` takes a corner's normal only if
  it is one, and falls back to the triangle's own plane.
- **The inside-out primitives** (above). Found by writing the volume check, not by reading
  `create_sphere`.
- **`bounds` reported points the body does not contain** (above). Found by following the square
  cap.
- **`let _ =` on the browser's boolean.** The call whose result was discarded is the only reason
  the page could not tell it was drawing an uncut plate.

**Not verified, and the risk taken with each.**

- **The boolean is narrow, and the shape of the narrowness is measured rather than understood.**
  What works: box against box, all three operations; a plate drilled by a cylinder. What does not:
  **cylinder ∪ cylinder fails at every tolerance tried** (0.05 → 0.001, `None` or a panic);
  **cylinder − box and cylinder ∪ box return `None`** where box − cylinder succeeds, so the
  operation is not symmetric in its operands; anything with a sphere is refused. A user will meet
  this in the second thing they try.
- **A panic in `truck-shapeops` is fatal in the browser.** `catch_unwind` covers the desktop. The
  `singular` set covers the one case known to abort. Neither covers a case nobody has found yet,
  and `wasm32-unknown-unknown` has no unwinding to fall back on.
- **A sphere that arrives through `load_body` is not known to be singular**, because the flag
  records what this backend *built*. A document saved with a sphere in it, reopened, and used as a
  cutting tool would reach `truck-shapeops` on the web.
- **The relative tolerance has been exercised at two sizes**, 4 mm and 40 mm. Nothing has been cut
  at 0.4 mm or at 4 m.
- **The volume check is over a tessellation, so it is an approximation of an approximation.** It
  is asserted to 0.1% on planar fixtures, where the mesh is exact, and one-sidedly on curved ones
  (never more than 1% over, never less than 70% of the true figure) — deliberately loose, because
  its job there is the *sign*.
- **Nothing has drawn a sphere in the browser since the flip was fixed** except the headless
  checks; the scene is a plate and a drill.
- **The payload grew.** 3.34 → **4.25 MiB** of wasm, 1.12 → **1.28 MiB** gzipped. Three of the 20
  new crates reach wasm — `truck-shapeops`, `truck-meshalgo`, `spade`, plus `robust`, `nom` and
  `memchr` under them; `vtkio`, `xz2` and `zlib-rs` are host-only and do not.
- **Two new host-only crates carry future-incompatibility warnings** — `nom 3.2.1` and
  `quick-xml 0.22.0`, both reached through `vtkio`, which is `truck-meshalgo`'s VTK feature and
  which nothing here calls. It cannot be turned off from this manifest: `truck-shapeops` depends
  on `truck-meshalgo` with default features.

## Loose ends, deliberately left

- **`make check` and `make test-occt` are slower.** The truck conformance run went from 0.6 s to
  ~11 s in debug, and `tessellation.rs` from ~0.1 s to ~7 s, because both now do real booleans.
  Twice over, since `make check` runs the tessellation file with and without `parallel`. Worth
  revisiting if it becomes the reason somebody stops running `make test`.
- **`BOUNDS_SAG` is a constant and bounds are a tessellation.** An exact bound would come from the
  surfaces themselves. Nothing needs it yet, and the number it replaced was wrong rather than
  coarse.
- **The `parallel` feature is now parallelism over faces on top of `truck-meshalgo`'s own**, which
  is `rayon` on native and single-threaded on `wasm32` by the library's own `cfg`. Nested pools are
  correct and are not obviously the right shape.
- **`does_geometry` has one reader**, the suite. It is the sort of thing a UI might want to say out
  loud, and nothing says it.
- **The face count changed for cylinders**, which means stored face ids from before this change
  refer to different faces. Nothing persists a truck face id today — `.w3d` stores the solid, not
  the mesh — but a saved selection would have moved, and item "no selection in a file" is where
  that becomes a real problem.

## Walkthrough · as completed

The browser models. It asked for a plate with a hole from the first day it drew anything; today it
gets one, and a check asserts that it did rather than that something was drawn.

What landed: `truck-shapeops` behind `TruckKernel::boolean`, with a size-relative tolerance, a
declared refusal for the geometry that aborts, and a `catch_unwind` where unwinding exists;
`truck-meshalgo`'s triangulation in place of a grid over the untrimmed surface, which fixed the
square caps, gave this backend its first edges, and made a boolean's output meshable at all; a
cylinder built so that it can be cut; a sphere that is no longer inside out; a stated winding
convention on `Mesh`; a conformance suite in two halves with `does_geometry` deciding which apply,
three mandatory box fixtures under the geometry half, and a negative control that requires the fake
to fail it; and `modelled` on the browser's report, asserted in `browser.mjs`.

Two register entries close with it: item 4, and the two browser checks that had been failing since
before the threaded variant — 5 distinct colours became 92, which is what a drilled plate looks
like next to a plate.

What did not land, and is the register's: the boolean is narrow and the narrowness is measured
(cylinder against cylinder does not work at any tolerance, and the operation is not symmetric in
its operands); a panic inside `truck-shapeops` is still fatal in the browser; a sphere read from a
file is not known to carry a pole; and the payload grew by 0.9 MiB. Nothing is pending in this
file.
