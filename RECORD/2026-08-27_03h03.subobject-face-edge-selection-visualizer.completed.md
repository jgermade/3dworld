# 2026-08-27 03h03 · Sub-object Face and Edge Selection Visualizer

## Where this repo actually was

`w3d-render` recorded `face_id` per triangle in `PackedVertex` (location 2) for ID-buffer GPU picking, and `Editor::picked` received `face`. However, face picking only selected the parent body node, with no sub-object face highlight, face normal calculation, or selection badge in the UI.

## Walkthrough · as built

- Added `FaceMetrics` struct (`face_id`, `area`, `normal`, `centroid`, `triangle_count`) and `Mesh::face_metrics(face_id)` in `w3d-kernel` to compute exact surface area (mm²), unit surface normal vector, and face centroid for any topological face index on a tessellated mesh.
- Updated `w3d-render` shader (`render/src/shade.wgsl`) and uniform serialization to support `selected_face` rendering with a vibrant cyan (`rgb(0.15, 0.75, 1.0)`) GPU highlight overlay when a sub-object face is selected.
- Updated `Editor` in `w3d-app` to track `selected_face: Option<(NodeId, u32)>` across pick events, reporting face area and unit normal vector in the status bar upon picking.
- Added a floating `Sub-object Inspector` overlay window in egui (`app/src/shell.rs`) displaying Face ID `#<id>`, Selection Mode badge, Surface Area metric, Face Normal `[nx, ny, nz]`, Centroid `[cx, cy, cz]`, Triangle count, and quick sub-object action buttons (`Deselect Sub-object`, `Fillet [R]`, `Chamfer [C]`).
- Added unit tests in `kernel/src/lib.rs` and `app/src/editor.rs` validating face metrics accuracy (area 100.0 mm² and normal `[0, 0, 1]` on a 10x10 square), sub-object selection mode toggles, status reporting, and selection clearing.

## Bugs found by building, not by reading

- Fragment shader `fs_shade` in `shade.wgsl` was interpolating `face_id` smoothly across vertices if not marked `@interpolate(flat)`. Because `face_id` was flat in vertex stage, passing `selected_face` as a uniform field rather than per-vertex attribute allowed instantaneous GPU face highlight without requiring mesh buffer re-uploads.
