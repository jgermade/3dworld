## Walkthrough · as built

### Four jobs, and what each is for

`.github/workflows/ci.yml`, on every push:

| Job | Runs | Why it is a separate machine |
| --- | --- | --- |
| `test` | `make test`, then `make wasm` | The no-setup gate. Anybody can run it, so it is the one that must never be the only thing that ran. |
| `occt` | `make test-occt`, then `pip install steputils`, `make step-samples`, `make step-check` | OpenCASCADE, and STEP against something that is not us. |
| `window` | `make app-test`, `make app-test-step` | Xvfb, lavapipe, and OCCT — the modeller in a real window. |
| `freecad` | `make freecad-check` on the artifact `occt` uploaded | Another program's opinion of a file this one wrote. |

`test-occt` and `step-check` share a job on purpose. Each job is a fresh machine, and a second one
would rebuild two hundred crates to run one command; the steps are named, so a failure still says
which check failed. That is the only place the plan was traded against the clock.

**The browser is nightly**, in its own workflow. It is the slowest by a distance — a wasm build,
`wasm-bindgen-cli` compiled from source at a version that has to match the dependency exactly, and
a browser Playwright downloads — and it checks a thing that changes rarely.

**Only `actions/*`.** A third-party action is a dependency with a licence and a supply chain, and
this repository has a rule about those. The caching action everybody uses would be a fine choice
and it is still a choice nobody has argued for in a record file.

### The FreeCAD check, and what it is worth

`tools/freecad_volume.py` opens a STEP file this program wrote and asks FreeCAD for the volume of
each solid. What those volumes are compared against is **arithmetic**:

- a plate of 40×40×10 with a ⌀12 hole through it is 16000 − π·6²·10 = 14869.026645 mm³
- a sphere of r=8 is (4/3)π·8³ = 2144.660585 mm³

because that is what a cylinder and a sphere are. No CAD kernel has a vote on those numbers, so
agreeing with them is not two kernels agreeing with each other. It also settles the unit for free:
a file that said metres would be out by a factor of a billion, not by a rounding error.

The tolerance is 1e-6 relative and it is tight on purpose — these volumes come from exact
integration over analytic surfaces, not from a mesh — and each solid is additionally asked whether
it `isValid()` and `isClosed()`, because a shape that encloses nothing has a volume too.

**What it is not is a second geometry kernel.** FreeCAD's is OpenCASCADE, the same one that wrote
the file. What it covers is *another application's import path* — its XDE layer, its unit handling,
its document model — which is a real category of bug and not the one still outstanding. The script
says so at the top, and so does the register.

The file reaches that job as an **artifact**: the `occt` job uploads `ours.step`, the `freecad` job
downloads it. So the FreeCAD machine needs neither Rust nor OpenCASCADE, and the file makes a real
trip out of one process and into another program on another machine.

### Two details worth their comments

- **`make occt-headers` runs only if the header is missing.** The Ubuntu Noble packaging bug is
  real and is also fixed in some images; fetching a header nobody needs is a network call nobody
  asked for. Both GitHub images have it, so the step prints "the distribution shipped it".
- **The `wasm-bindgen-cli` version is read out of `Cargo.lock`**, not written into the workflow. A
  mismatch there is a runtime error in the browser about an unknown import, not a build failure,
  and a version written down twice is a version that will be wrong once.

## Bugs found by building, not by reading

- **The cache key knew about `Cargo.lock` and not about the compiler**, while the Rust step runs
  `rustup update stable`. A `target/` built by an older rustc, restored under a key that cannot see
  the difference, is a rebuild that looks like a cache hit and a failure that looks like nothing.
  Found by writing the second job and noticing the first one's key would collide with it across a
  toolchain update. `rustc --version` is in every key now.
- **Every `actions/*` step printed a Node 20 deprecation warning.** They still ran — the runner
  forces Node 24 — and that is precisely how a warning becomes a thing nobody reads. The majors
  that declare `node24` are `checkout@v7`, `cache@v6`, `upload-artifact@v7` and
  `download-artifact@v7`, and `download-artifact@v6` is *not* one of them, which is the kind of
  thing you only find by looking at each `action.yml` rather than assuming the numbers move
  together.
- **FreeCAD 0.19 leaves the third field of `Version()` empty**, so the first run printed
  "FreeCAD 0.19." with a trailing dot. Cosmetic, and it is the version string that will identify
  which program answered when somebody reads this log in a year, so it is worth being a string
  rather than a format.
- **FreeCAD is not in Ubuntu 24.04 at all** — it is in jammy at 0.19.2 and returns in questing at
  1.0. Found before writing anything, by looking, and it is why that one job pins `ubuntu-22.04`
  while everything else is `ubuntu-latest`.
- **`workflow_dispatch` cannot be triggered on a branch whose workflow is not on the default
  branch.** So the nightly workflow could not be run at all from here; see `Verified, and not`.

## Verified, and not

**Verified.**

| | |
| --- | --- |
| CI, first run, all four jobs green | `make test` + `make wasm`, `make test-occt` + `make step-check`, `make app-test` + `make app-test-step`, and FreeCAD — in under three minutes wall clock, from cold caches. |
| **FreeCAD 0.19 read a file this program wrote** | `sphere r=8: 2144.660585 mm3, arithmetic says 2144.660585 (2.12e-16)` and `drilled plate 40x40x10, hole d=12: 14869.026645 mm3, arithmetic says 14869.026645 (2.81e-15)`. Fifteen significant figures against hand arithmetic, in another program, on another machine, from a file that travelled as an artifact. |
| the toolchain | The runner's `rustup update stable` gives a compiler this workspace builds with, and `make licences`, clippy and fmt pass there as they do here. |
| CI, second run, all four jobs green | With `checkout@v7`, `cache@v6`, `upload-artifact@v7`, `download-artifact@v7` and the compiler in every cache key. Under three minutes again. |
| the nightly job's **commands**, run by hand here | `cargo install wasm-bindgen-cli --version 0.2.127`, `npm install` in `web/test/`, `make web-test`: nineteen `ok` lines and `all checks passed` in Chromium — WebGPU offered, WebGL2 forced, and a run with no COOP/COEP that degrades with a sentence a user can read. What has not run is the *workflow*; see below. |

That FreeCAD line is the strongest sentence in this repository about STEP, and it is worth being
precise about why: the volumes are not compared to what OpenCASCADE thinks the volumes are. They
are compared to π.

**Not verified, and the risk taken with each.**

- **Still no GPU.** The `window` job draws on lavapipe and the browser job on headless Chromium's
  software path. A GitHub runner has no GPU, so this needs a self-hosted runner with one, or a
  person, a machine and a screenshot. **WebGPU has still never rendered a pixel anywhere**, which
  is the same sentence as three record files ago.
- **The nightly workflow has never run.** `workflow_dispatch` only fires for a workflow that is on
  the *default* branch — the API answers 404 for this one — and a schedule fires there too. The
  YAML is therefore unexecuted: what was checked instead is its *content*, by running the same
  commands here, and the one line in it that is not a command is the version read out of
  `Cargo.lock`. **The first real test of that file is the first night after it merges**, which is a
  thing to watch for rather than assume.
- **FreeCAD is not a second kernel**, and no program built on Parasolid or ACIS has opened one of
  these files. That is what remains of item 1 and no CI can close it.
- **The FreeCAD job pins nothing.** `apt install freecad` gets whatever 22.04 has today, and jammy
  will not be a runner label forever. A container or a version pin is the fix and neither is
  written.
- **`ubuntu-latest` moves**, and the OCCT packages move with it. The Noble header workaround is
  conditional precisely because that has already happened once.
- **Nothing measures CI itself.** Four jobs on every push is a cost. Two runs is not a sample, and
  no cache has been *observed* to hit: both runs took about three minutes, which is either a cold
  build being fast or a warm one being slow and nothing here tells the difference.

## Loose ends, deliberately left

- **A merge queue, required checks, a badge.** All of them are settings on a repository rather than
  files in it, and none is mine to decide.
- **The browser job is nightly and therefore invisible on a branch.** Anybody working on `web/`
  will want it on a push; that is a one-line change and a cost, and it should be made by whoever
  is paying it.
- **A container for the FreeCAD job**, which would pin the version and drop the `ubuntu-22.04`
  label. It also drops apt caching and adds an image to trust.
- **The samples are fetched on every `occt` run.** Three files, 200 KiB, from one repository; they
  could be cached by their own hashes, which is what the hashes are for.

## Walkthrough · as completed

This repository has CI, and it runs the checks that were the whole point of having any: OCCT, the
window, STEP against a parser that is not OpenCASCADE, and files from three other programs. The
browser runs nightly. Every action is `actions/*` at a Node 24 major, and every cache key names the
compiler that filled it.

And a program that is not this one has opened a file this one wrote and measured it: FreeCAD 0.19,
against arithmetic, to fifteen significant figures. What that does not do is prove a second
*geometry kernel* agrees, because FreeCAD's is OpenCASCADE — the difference is written into the
script, the workflow, `AGENTS.md` and the register, so that nobody has to rediscover it.
